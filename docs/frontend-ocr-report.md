## 2. 1단계 — 셋업

### 2-1. 패키지 매니저 · 경로 · 폴더 구조

- npm → **pnpm** 전환 (`node_modules`·`package-lock.json` 삭제 후 재설치)
- `tsconfig.json` + `vite.config.ts`에 `@/*` → `src/*` alias 추가. 모든 import를 alias로 통일
- **FSD 구조**로 재편:

| 이전 | 이후 |
|---|---|
| `src/components/ui/` | `src/shared/ui/` |
| `src/lib/cn.ts` | `src/shared/lib/cn.ts` |
| `src/index.css` | `src/app/styles/index.css` |
| `src/main.tsx` | `src/app/main.tsx` |
| `src/App.tsx` | `src/app/DevGallery.tsx` (컴포넌트명도 `DevGallery`로) |

`pages` / `widgets` / `features` / `entities` 레이어를 만들었습니다. 임포트 방향은 위→아래만 허용(`app → pages → widgets → features → entities → shared`), 같은 코드가 3번째 반복될 때만 `shared`로 승격하는 규칙을 유지했습니다.

현재 `widgets` / `features`는 비어 있습니다. 6개 화면 모두 페이지 단위로 끝나서 아직 승격 대상이 없습니다.

### 2-2. 라우터

react-router v7 **declarative 모드**(`<BrowserRouter>/<Routes>/<Route>`). data 모드(`createBrowserRouter`)는 쓰지 않았습니다.

```
/                          진입 분기 자리(플레이스홀더, 미구현)
/dev/gallery               컴포넌트 갤러리
/dev/document-upload       05
/dev/document-confirm      D07
/dev/ocr-review            07 (+ O07·O08 모달)
/dev/medication-schedule   09 (+ 09-A 시트)
```

`/`는 `user.status_code` 기준 진입 분기(pending → 문서 등록 / active → 홈)가 들어갈 자리입니다. 요구사항정의서에 분기 조건이 있지만 홈 화면이 없어 추측 구현을 피하고 안내 문구만 뒀습니다.

### 2-3. shadcn/ui 도입 — CLI를 쓰지 못했습니다

`pnpm dlx shadcn@latest init`이 이 환경에서 실행되지 않습니다. CLI가 `ui.shadcn.com` 레지스트리에 접근하는데 사내(샌드박스) 네트워크가 해당 도메인을 403으로 막습니다. 버전을 4.16.0·2.10.0까지 내려봤지만 모두 같은 지점에서 실패했습니다.

**대응:** 공식 shadcn/Radix 소스를 직접 옮겨 작성했습니다. Radix 프리미티브는 `pnpm add`로 정상 설치됩니다(`registry.npmjs.org`는 접근 가능).

- `components.json`은 FSD 경로에 맞춰 손으로 작성해뒀습니다. 네트워크가 열린 환경에서 `pnpm dlx shadcn@latest add <component>`를 돌리면 그대로 이어집니다
- **직접 작성한 것:** `dialog` `select` `tabs` `checkbox` `switch` `sonner`
- **교체하지 않은 것:** `Button` `Card` `Input` `StatusBadge` `Header` `BottomTabbar` — Figma 치수 기준이라 유지
- 기존 수제 `Checkbox`·`Toggle`은 shadcn `checkbox`·`switch`로 교체(파일명 소문자로 변경). 시각적 크기는 이전과 동일하게 맞췄습니다(`size-6`, 트랙 `h-8 w-14`)

### 2-4. 디자인 토큰 · 접근성

토큰 2단 구조(Primitives → 의미 토큰)와 **토큰 이름을 그대로 유지**했습니다. shadcn 컴포넌트가 요구하는 이름(`destructive` `muted` `accent` `popover` 등)은 새 색을 만들지 않고 기존 값을 가리키는 **별칭**으로만 추가했습니다.

`cn` 유틸을 shadcn 표준(clsx + tailwind-merge)으로 교체했습니다. 호출 형태(`cn(...args)`)는 그대로입니다.

> **알려진 한계:** tailwind-merge는 우리 커스텀 `@theme` 클래스(`rounded-card` `bg-warning-bg` `h-touch` 등)를 모릅니다. 이 클래스들끼리 충돌할 때 자동 병합이 안 되므로, 같은 속성을 덮어쓸 때는 className 순서에 의존하지 말고 조건 분기로 처리해야 합니다.

NFR-ACC-001(최소 터치 영역 44px)에 맞춰 shadcn 기본 높이를 올렸습니다 — Select 트리거 36px → 44px, Tabs 32px → 44px.

### 2-5. 추가 컴포넌트

- **`CheckboxField`** — shadcn Checkbox를 감싼 라벨+설명 조합. 행 전체가 클릭 영역(`<label>`, `min-h-touch`), `required`에 따라 "(필수)"/"(선택)" 표기, 체크박스와 텍스트를 **상단 정렬**(설명이 2줄이어도 체크박스가 중앙으로 밀리지 않게). 03 개인정보 동의·O08에서 쓸 용도로 미리 만들었습니다
- **`Button`에 `danger` variant 추가** — O07 삭제 확인 버튼용. Figma에 없는 변형이며 새 색 없이 기존 `danger`/`danger-strong` 토큰만 재사용

## 3. 명세·디자인 이상 목록 (중요)

각 화면을 시작하기 전에 요구사항정의서 · Figma 프레임(상태 변형 포함) · 노션 API 명세를 교차 확인했습니다. 어긋난 6건입니다.

### 3-1. 수술명 필드가 어디에도 없었음 → Figma·타입 양쪽에 추가

Figma `07`과 3개 변형(`07-R` `07-R1` `O06`) 전부 **진단명만** 있고 수술명이 없었습니다. 노션 API 명세 3-2의 OCR 응답에도 `surgery`가 없습니다(다른 화면인 9-2 `GET /records/{recordId}`에만 존재).

**결정:** `OcrResult.fields.surgery` 타입 추가 + **Figma 4개 프레임에 수술명 필드 직접 추가**.

Figma 편집 내역: `07`(66:115) `07-R`(119:212) `07-R1`(147:52) `O06`(142:133)의 Content 프레임에 진단명 Field를 복제해 진단명 바로 뒤에 삽입했습니다. Content가 auto-layout이라 아래 형제들이 자동으로 밀렸고 하단 CTA는 절대 위치라 겹침 없음을 스크린샷으로 확인했습니다.

→ 백엔드 전달사항 5-1 참고

### 3-2. 복용일수를 약마다 다르게 둘 수 없음 → 스펙대로 top-level 1개 유지

목업 요청은 약마다 복용일수가 달랐지만(7일/14일/7일), 스펙 3-2의 `medicationDays`는 **레코드 전체 1개** 필드이고 `OcrMedication`에는 일수 필드가 없습니다.

**결정:** 스펙 유지. 약별 일수는 `note`에 자연어로만 표기하고 구조화 필드를 추가하지 않았습니다.

> **주의:** `note`에 "1일 2회 · 7일분"처럼 빈도를 넣으면 O07 약 카드가 `1일 N회 · {note}` 형태로 조립하기 때문에 "1일 2회 · 1일 2회 · 7일분"으로 중복 표시됩니다. 실제로 한 번 발생해서 목업의 `note`를 복용 시점만 담도록 정리했습니다.

### 3-3. 복용일수 입력 UI가 07·O07 어디에도 없었음 → 07에 필드 추가

`medicationDays`는 "활성 기간 계산의 핵심 값"인데 수정할 방법이 없었습니다. OCR이 14일을 1일로 잘못 읽으면 홈 노출 기간이 통째로 틀어집니다.

**결정:** 퇴원일 바로 아래에 "복용일수" 숫자 입력 + "일" 단위 표기 + 신뢰도 배지 추가.

### 3-4. `lowConfidenceCount`가 로컬 편집 후 낡음 → 화면 표시용은 재계산

스펙 3-2는 "서버가 세어주고 프론트에서 다시 세지 않는다"로 정하고 있습니다. 그런데 O07에서 약을 지우면 그 값이 즉시 낡습니다 — 유일하게 낮은 신뢰도였던 약을 지웠는데도 "4개 미확인"이 남으면 사용자가 해소할 방법이 없습니다.

**결정:** 화면에 보이는 개수·항목명은 **현재 상태에서 재계산**합니다. 서버 값은 최초 로드 기준값으로만 두고 화면에 직접 쓰지 않습니다. 07의 "확인 필요 항목" 카드와 O08 모달이 같은 값을 씁니다.

→ 스펙과 다른 선택입니다. 백엔드 협의 시 짚어야 합니다

### 3-5. O07 입력 폼이 미설계 → 기획 결정대로 구현 (Figma가 코드를 따라옴)

Figma `O07`(204:25)은 목록 상태만 있고 "수정"·"+ 약 추가"를 눌렀을 때의 입력 폼이 없었습니다. 기획 확정 사항대로 구현했습니다.

- Dialog 하나 안에서 `list` ↔ `edit` 뷰 전환. **Dialog 중첩을 쓰지 않습니다** (375px에 2겹은 답답하고 포커스 트랩 중첩 시 스크린리더 동작이 불안정)
- 삭제 확인도 모달 없이 해당 카드 안에서 인라인 처리
- 닫기 시 미저장 변경이 있으면 하단에 인라인 확인 바("저장하지 않고 닫을까요?")
- 낮은 신뢰도 약 카드에 `StatusBadge type="review"` 추가 — **Figma에 빠져 있던 것**. O08이 "N개 항목을 확인해주세요"라고 안내하는데 모달을 열면 어떤 약이 문제인지 알 수 없는 상태였습니다
- "수정"·"삭제"를 Figma의 작은 텍스트 대신 `h-touch`(44px) 버튼으로 — NFR-ACC-001 위반이었습니다

**구현 시 보강한 것:** ESC·오버레이 클릭·우상단 X도 "닫기" 버튼과 같은 경로를 타게 만들었습니다. 그러지 않으면 ESC로 미저장 변경을 조용히 날려버립니다.

### 3-6. 09-A에 프리셋이 없고, 복용 시작 시점 필드가 빠져 있었음

REQ-CARE-003은 시간 지정 방법으로 "**프리셋**(아침/점심/저녁/자기 전) **또는** 시·분 선택 박스"를 명시하는데 Figma `09-A` 시트에는 시·분 휠만 있었습니다. 슬롯 버튼은 "아침 08:00"처럼 프리셋 라벨을 달고 있어 모델상으로는 프리셋이 존재하는데 고르는 UI가 없는 상태였습니다.

**결정:** 시트에 프리셋 칩 4개 추가 + 시·분 Select 병행. 칩을 누르면 시·분이 함께 채워집니다.

또 `09-A`에만 "복용 시작 시점" 필드가 없었습니다(`09`·`09-B`에는 있음). 나중에 추가된 필드(207:25)가 `09-A`에 반영되지 않은 것으로 보고 `09` 기준으로 맞췄습니다.

**휠 vs Select:** REQ가 "시·분 선택 **박스**"라고 쓰고 있어 Figma의 스크롤 휠 대신 shadcn Select로 구현했습니다.

### 3-7. (참고) O05가 퍼센트를 노출 — 이번 범위 밖이지만 수정 필요

Figma `O05 OCR 저신뢰 검토`(70:95)에 "전체 추출 정확도 · 71%", "진단명 96% · 퇴원일 91% · 복약 58%"처럼 **퍼센트가 그대로 노출**돼 있습니다.

- REQ-DOC-003: "퍼센트를 노출하지 않고 구간에 따라 '확인 필요/확인됨' 배지와 색상으로만 표시"

양쪽에 정면으로 어긋납니다. 이번 6개 화면 범위 밖이라 건드리지 않았지만, **O05를 구현할 때 이 프레임을 그대로 옮기면 안 됩니다.**

## 4. 2단계 — 화면별 구현

### 4-1. 05 문서 업로드 (REQ-DOC-001 / 66:97)

카메라·갤러리 진입점 2개. 실제 카메라·파일 접근이 없는 개발 환경이라 `docs/sample-docs` 환자1 문서 3종을 순서대로 담는 것으로 흉내냅니다(카메라는 한 장씩, 갤러리는 남은 문서를 한 번에).

D07과의 촬영 루프는 react-router의 `navigate(path, { state })`로 담은 문서 목록을 주고받습니다. 상태관리 라이브러리를 추가하지 않았습니다.

> **구현 판단:** Figma는 "선택된 문서" 카드를 항상 예시 파일과 함께 보여주지만, 한 장도 담기 전에는 숨기도록 했습니다. Figma 내용을 와이어프레임 예시로 해석했습니다.

### 4-2. D07 등록할 문서 확인 (201:25)

96×88 썸네일 박스(“1쪽”·“2쪽”), 파일명 줄, "문서 추가"(→ 05로 복귀) / "등록 완료"(→ 07). `/dev/document-confirm`을 단독으로 열었을 때도 의미 있게 보이도록 기본 목업 2장을 뒀습니다.

### 4-3. 07 OCR 결과 확인·수정 (REQ-DOC-003 / 66:115)

- 진단명 · **수술명** · 퇴원일 · **복용일수** 편집 필드 + 신뢰도 배지
- 복약 정보 요약 카드(탭 → O07 모달)
- 의료진 권고사항 **편집 전용** 리스트 — 추가·삭제 UI 없음
- "확인 필요 항목" 경고 카드
- 저장하기 / 다시 촬영·재업로드

**신뢰도 배지:** 스펙·요구사항 모두 "확인 필요 / 확인됨" 2종 문구만 요구합니다. `StatusBadge`에 새 variant를 만들지 않고 기존 톤을 재사용했습니다.

| confidence | 배지 | 톤 |
|---|---|---|
| high | 확인됨 | `active` (초록) |
| medium | 확인 필요 | `dose` (주황) |
| low | 확인 필요 | `review` (빨강) |

문구는 2종이지만 색 강도를 나눠 "낮은 신뢰도가 먼저 눈에 띄도록"이라는 요구사항을 반영했습니다.

**퇴원일은 달력 입력(`type="date"`)입니다.** 새 라이브러리 없이 처리했습니다 — shadcn Calendar는 `react-day-picker`+`date-fns`가 필요하고, 375px 화면에서는 네이티브 쪽이 실제로 낫습니다(모바일에서 OS 기본 선택기, 접근성은 브라우저가 처리). 달력 아이콘을 24px로 키우고, 입력칸 아무 곳이나 눌러도 열리도록 `showPicker()`를 붙였습니다. 표시 형식은 로케일을 따르지만 **저장 값은 항상 `YYYY-MM-DD`**입니다.

**권고사항에 추가 UI를 두지 않는 이유(요구사항정의서 근거):** 이 값이 홈·생활관리·기록상세·챗봇 근거로 퍼지므로, 환자가 기억으로 입력하면 출처 없는 문장이 "의료진 권고사항" 권위를 얻고 AI 답변까지 증폭됩니다. OCR 오인식 수정은 원문 근거가 있어 허용합니다.

### 4-4. O07 복약 정보 편집 모달 (204:25)

3-5 참고. 편집은 로컬 상태에만 반영되고 "변경 저장"을 눌러야 07에 반영됩니다. 신규 추가 약의 `tempId`는 프론트에서 `new_1` 형태로 만들고, OCR 추출이 아니므로 신뢰도 배지를 붙이지 않습니다(`OcrMedication.confidence`를 optional로 변경).

edit 뷰 입력 필드:

| 라벨 | 타입 | API 키 |
|---|---|---|
| 약품명 | text (필수, 비면 확인 비활성) | `name` |
| 용량 | text | `dose` |
| 1일 복용 횟수 | Select (1~4회 / 필요 시 → `null`) | `timesPerDay` |
| 복용 시점 | text + 프리셋 칩(식전/식후/취침 전/필요 시) | `note` |

`medications`는 `advices`와 달리 신규 추가가 허용됩니다(스펙 3-3).

### 4-5. O08 낮은 신뢰도 항목 확인 (205:25)

저장하기 → 확인 모달 1회 → "확인 후 저장" 시에만 진행. "항목 다시 확인"은 저장하지 않고 닫습니다. 낮은 신뢰도 항목이 0개면 모달 없이 바로 저장합니다.

**Figma는 "진단명과 복약 정보를 다시 확인해주세요."로 항목명이 하드코딩**돼 있어 동적으로 조립하게 만들었습니다. 한국어 조사도 받침에 맞춰 처리합니다.

```
["진단명","복약 정보"]                  → 진단명과 복약 정보를 다시 확인해주세요.   ← Figma 원본과 동일
["복약 정보","진단명"]                  → 복약 정보와 진단명을 다시 확인해주세요.
["진단명","수술명","복용일수","복약 정보"]  → 진단명, 수술명, 복용일수, 복약 정보를 다시 확인해주세요.
```

1개는 `~을/를`, 2개는 `~과/와`로 잇고, 3개 이상은 쉼표로 나열합니다.

### 4-6. 09 복약 시간 설정 — **통합 슬롯 구조로 재설계** (REQ-CARE-003)

> 2026-08-14 기획 결정으로 약별 시각 지정을 폐기하고 통합 슬롯 구조로 다시 만들었습니다.
> **Figma `09`(125:50)는 아직 옛 구조입니다.** 이 화면은 작업지시 문서가 기준이고 Figma 수정이 뒤따릅니다. `09-A 시간 선택` 시트는 구조가 안 바뀌어 그대로 씁니다.

**무엇이 바뀌었나.** 사용자는 아침·점심·저녁·취침 전 **시각 4개만** 정하고, 약은 "어느 시간대에 먹는지"만 가집니다.

```
[전]  셀레콕시브  [08:00] [20:00]
      리바록사반  [20:00]
      파모티딘    [08:00] [20:00]      ← 08:00 두 번, 20:00 세 번 입력
[후]  아침 08:00 · 점심 13:00 · 저녁 19:00 · 취침 전 22:00   ← 시각은 여기 4개뿐
      셀레콕시브  [아침 ✓] [점심 ] [저녁 ✓] [취침 ]
```

데이터 모델도 `times: string[]`(약별) → `mealTimes`(사용자별 4개) + 약별 `slots: MealSlot[]`로 교체했습니다. `mealTimes`는 **사용자 단위**입니다 — 진료기록이 2건이어도 환자의 아침 식사 시각은 하나이므로 `recordId`별로 저장하지 않습니다.

`bedtime`을 쓰고 `night`를 쓰지 않은 이유: '취침 전'은 시계 시각이 아니라 취침 행동에 붙는 개념이고, `night`는 22시라는 시각으로 읽혀 늦게 자는 사용자에게 의미가 어긋납니다.

**자동 배정** (`slotAssignment.ts`). 사용자가 약마다 체크를 다시 하지 않도록 OCR `timing` 문구에서 시간대를 먼저 읽습니다. 문구에서 찾은 개수가 복용 횟수와 **정확히 맞을 때만** 그것을 쓰고, 아니면 횟수 기준 기본값으로 떨어집니다. 영문·약어가 섞여 올 수 있어 한글 키워드만 봅니다(추측해서 틀리는 것보다 못 찾고 폴백하는 게 안전).

| 1일 횟수 | 폴백 기본값 |
|---|---|
| 1회 | 아침 |
| 2회 | 아침·저녁 |
| 3회 | 아침·점심·저녁 |
| 4회 | 아침·점심·저녁·취침 전 |

`1회 → 아침`으로 바꿨습니다(이전은 저녁 20:00). 이전 값은 Figma의 리바록사반 예시에 맞춘 것이었고, 일반적인 1일 1회 처방은 아침입니다. 리바록사반은 `timing`이 "저녁 식후"라 1단계에서 저녁으로 잡히므로 결과는 그대로입니다.

**취침을 저녁과 분리한 게 중요합니다.** 위장약·수면 관련 약처럼 취침 전 복용이 지정된 처방이 실제로 있고, 저녁 식후와 취침 전은 3~4시간 차이라 합치면 복용 간격이 어긋납니다.

**검증 규칙.** `toast`로만 알리면 어느 약이 문제인지 못 찾으므로 전부 인라인으로 보여줍니다.

| 조건 | 처리 |
|---|---|
| 시간대 0개인 약(필요 시 제외) | 저장 비활성 + 그 약 아래 메시지 |
| 아침→점심→저녁→취침 전 순서 위반 | 저장 비활성 + 시간대 카드 아래 메시지 |
| `startPeriod` 미선택 | 저장 비활성 |
| `timesPerDay > 4` | **저장 허용** + 안전 문구. 사용자가 여기서 할 수 있는 조치가 없어 막으면 앱을 못 씁니다 |

취침 전 자정 넘김은 미지원입니다. 분이 00·30뿐이고 시가 23까지라 최대 23:30으로 자연히 제한됩니다. 자정 넘김을 지원하려면 "몇 시부터 다음 날인가"를 서버·알림 스케줄러까지 같이 정해야 해서 범위가 커집니다.

**UI 세부.** 어떤 약도 쓰지 않는 시간대는 **숨기지 않고 흐리게 + "이 시간대에 먹는 약 없음"**으로 둡니다(아래에서 체크를 켜면 바로 쓰이게 되므로). 약별 토글은 체크박스가 아니라 토글 버튼 4개이고 `grid grid-cols-4`를 씁니다 — `flex-1`은 라벨 길이 차이로 폭이 들쭉날쭉해집니다. 복용 시작 시점은 시간대 카드와 착각하지 않도록 구분선 + 칩 형태로 다르게 그렸습니다.

**`09-B 기존 저장 시각 프리필`**은 여전히 별도 컴포넌트 없이 같은 화면이 처리합니다. `mealTimes`가 `null`이면 기본값, 약의 `slots`가 비어 있으면 자동 배정, 값이 있으면 저장값 우선입니다.

저장 후에는 `/dev/flow-complete`(`app/DevFlowComplete.tsx`)로 이동합니다. 실제 목적지인 홈 대시보드(REQ-HOME-001)와 OS 알림 권한 요청이 아직 없어 확인용 자리입니다.

## 5. 백엔드 전달사항

> **아래 항목들은 아직 노션에 반영되지 않았습니다.** 이 문서가 원본이니 노션 API 명세·ERD에 옮겨주세요.

### 5-1. `fields.surgery` 추가 요청

`GET /documents/{batchId}/ocr` 응답과 `PATCH /documents/{batchId}/ocr` 요청 양쪽에 `diagnosis`와 동일한 형태로 추가가 필요합니다 — 조회 시 `{ value, confidence }`, 저장 시 `string`.

> 프론트 타입은 `surgery`로 확정했습니다. 백엔드에서 다른 이름(`surgeryName` 등)으로 정하면 맞추겠습니다.

### 5-2. `lowConfidenceCount` 재계산 (협의 필요)

3-4 참고. 스펙의 "프론트에서 다시 세지 않는다"와 다르게 화면 표시용 개수를 재계산하고 있습니다. 로컬 편집으로 값이 낡는 문제를 서버에서 어떻게 볼지 정해야 합니다.

### 5-3. 통합 슬롯 재설계에 따른 계약 변경 (코드 밖 작업, 신동훈)

계약 변경분은 `전달_통합슬롯_계약변경.md`에 정리돼 있습니다. 프론트 구현과 별개로 처리해야 합니다.

1. **API 명세 5-3 교체** — `times: string[]` → `mealTimes`(4개) + 약별 `slots`
2. **API 명세 4장 `todayMedications`** — 평평한 목록 → 시간대별 묶음(취침 전 포함)
3. **ERD** — `medication_times` 삭제, `user_meal_times` · `medication_slots` 신설, `Enum meal_slot`에 `BEDTIME` 포함
4. **알림 설계 2건 철회** — 하루 알림이 15건에서 최대 4건으로 줄어듭니다. 알람이 (사용자 × 시간대) 단위가 되므로 `alarms.medication_id`가 불필요해지고(대신 `alarms.meal_slot` 필요), 슬롯당 알람이 1건이라 `alarm_events.batch_key`도 묶을 게 없어집니다. `background_jobs.idempotency_key`는 유지

**해소된 미결:** 1일 4회 처방. 슬롯이 3개였을 때는 담을 데가 없어 "경고 후 저장 허용"으로 뒀는데, 취침 전이 들어오면서 4회까지 정확히 표현됩니다. 남은 경고 대상은 1일 5회 이상뿐입니다.

### 5-4. 기존 명세 11장에 이미 있던 항목 중 이번 작업과 직접 엮인 것

- 4번 OCR 신뢰도 구간 판정 — 3-7의 O05 퍼센트 노출 문제와 직결됩니다
- 8번 `medicationDays` 추출 안정성 — 3-3에서 입력 UI를 추가했으니 추출 실패 시 사용자 입력으로 처리 가능해졌습니다

## 7. 개발 환경 이슈

증상별 대처는 [`docs/README.md`](README.md)의 "설치·빌드가 막힐 때"에 정리돼 있습니다. 여기서는 **왜 그 설정이 있는지**만 남깁니다.

**`pnpm-workspace.yaml`의 `nodeLinker: hoisted`는 지워도 되는 설정이 아닙니다.** WSL(`/mnt/c/...`)에서 `pnpm install`을 돌리고 Windows 네이티브 IDE로 편집하면, pnpm이 만드는 symlink를 Windows 쪽 TypeScript 서비스가 따라가지 못합니다. 그래서 `react`·`clsx`·`@radix-ui/*` 등 **symlink로 걸린 패키지만 골라서** `Cannot find module`이 뜹니다. `DialogContentProps` 류의 에러도 `@radix-ui/react-dialog` 타입을 못 읽어 생기는 2차 증상이라 따로 고칠 게 없습니다.

> **함정 — pnpm 11은 `.npmrc`의 pnpm 설정을 읽지 않습니다.** 처음에 `.npmrc`에 `node-linker=hoisted`를 넣었는데 조용히 무시됐습니다(`pnpm config get node-linker` → `undefined`). pnpm 10에서는 동작하기 때문에 버전에 따라 갈립니다. `.npmrc`가 남아 있는 것은 pnpm 10 이하 팀원을 위한 것이고, 실제로 먹는 쪽은 `pnpm-workspace.yaml`입니다.

hoisted의 대가는 **의존성 격리 약화**입니다. `package.json`에 선언하지 않은 패키지를 import해도 통과할 수 있으니 새 패키지는 반드시 `pnpm add`로 먼저 선언해야 합니다.
