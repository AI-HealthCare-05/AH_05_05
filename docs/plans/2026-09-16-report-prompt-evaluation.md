# 보고서 RAG 프롬프트 보완 검증

## 범위

Planner·작성·검증의 외부 Markdown 프롬프트만 동작 지침을 보완했다. 모델, 호출 한도, 출력 스키마, 검색 코드, 기존 보고서와 띄어쓰기 프롬프트는 이번 작업에서 변경하지 않았다. 운영 RAG 기본값은 비활성이다.

- 한국어 검색 질문과 등록 대상 유지, 중복 질문 억제.
- 조건명·부정·수치·행동의 원문 범위 보존, 사용자 질환 추측 금지.
- 경고별 주장을 분리하고 인용문과 청크 ID를 순서대로 대응.
- 생활 안내와 추가 주의사항의 구분, 근거 없는 안내로 빈 섹션 채우기 금지.
- 검증기가 유효한 문장을 불필요하게 재작성하거나 삭제하지 않도록 지시.

## 실제 호출 결과

GPT-4o를 사용했으며 실제 환자 데이터는 사용하지 않았다.

| 시험 | 결과 |
| --- | --- |
| 기존 프롬프트의 가상 조건·대상·인용·유효 주장 보존 검사 | 6항목 중 3항목 통과 |
| 최종 프롬프트의 같은 가상 사례 검사 | 6항목 모두 통과, 2.95초 |
| 최종 프롬프트 + 실제 Qdrant 검색, 가상 등록 목록 | 14.8초, 6개 검색 질문, 검증된 안내 3개·인용 3개 |

중간 버전은 여러 경고를 한 주장에 넣고 청크 ID와 인용 개수를 다르게 출력하여 안내가 전부 제외됐다. 경고별 분리와 배열 대응 지침 보완 후 최종 검색 시험에서는 세 경고가 각각 추가 주의사항으로 출력됐다. 생활 안내 중복은 없었다.

가상 등록 목록은 비타민 C와 아세트아미노펜이었다. 최종 검색 시험의 세 안내는 모두 비타민 C 근거이며, 약품 근거까지 확보된 것은 아니다. 음식·생활 섹션은 미확인, 추가 주의사항은 부분 확인 상태였다.

소규모 사례 시험이므로 전체 의학적 품질, 환각 방지, 속도 향상을 입증하지 않는다. 모델 출력은 변동하며 프롬프트만으로 준수를 보장할 수 없다. 프롬프트 길이에 따른 입력 토큰 증가도 있다. 운영 활성화는 별도 판단이 필요하다.

## 재현

저장소 루트에서 실행한다. `--run-live`는 비용이 발생하는 외부 호출에 명시적으로 동의하는 옵션이다.

```powershell
.venv/Scripts/python.exe -m scripts.evaluate_report_prompts --run-live
.venv/Scripts/python.exe -m scripts.smoke_report_rag --run-live --scenario mixed
.venv/Scripts/python.exe -m pytest ai_worker/tests/llm/prompts ai_worker/tests/reports -q --tb=short
```

가상 평가 스크립트는 인용 개수와 청크 개수의 일치도 검사한다. 프롬프트는 프로세스 캐시를 사용하므로 반영하려면 해당 서버·워커를 재시작해야 한다. 이번 작업에서 커밋·푸시·배포는 하지 않았다.

## 후속 코드 보완

프롬프트 수준 시험 이후 사용자가 승인한 코드 보완을 적용했다.

- 내부 모델 출력은 `evidence: [{chunk_id, exact_quote}]` 구조로 변경했다. 기존 병렬 배열은 수용하지 않으며, 저장된 공개 보고서·웹·메일 카드 형식은 바꾸지 않았다.
- 원격 구조화 출력의 엄격한 JSON 스키마는 유지하면서 로컬 검증은 주장 단위로 수행한다. 형식이 잘못된 후보와 공백뿐인 제목은 그 후보만 제외한다. 잘못된 최상위 구조·18개 초과 배치는 전체 거부한다.
- 검증기가 삭제하거나 정렬만 바꾼 경우 추가 호출하지 않는다. 편집된 주장만 섹션당 최대 1회 재검증하고, 실패하더라도 이미 검증된 다른 주장은 유지한다. 재검증되지 않은 초안을 복원하지 않는다.
- 제외 사유는 `claim_rejected_*` 정수 집계로 결과 메트릭에 담는다. 원문·제품명·환자 입력을 로그로 추가하지 않는다.
- 새 스키마에 맞춰 작성·검증 프롬프트, 기존 테스트 자료와 가상 평가 도구도 함께 갱신했다.

검증 과정에서 실제 OpenAI 요청이 `grounded` 필수 필드 누락으로 거부되는 사례를 발견해 스키마를 수정했다. 실제 LCEL 파서와 모의 HTTP 응답을 연결하는 테스트로 요청 스키마와 개별 후보 보존을 확인한다.

최종 가상 모델 시험은 6/6 통과(3.77초). 실제 Qdrant 연결 시험은 검색 질문 6개, 검증된 안내 3개·인용 3개(20.23초)였다. 모두 비타민 C 근거이며 약품 근거 확보나 속도 개선의 증거는 아니다. 운영 비활성 기본값과 미배포 상태는 유지한다.

초기 관련 프롬프트·보고서 테스트 396개 통과(10.04초), 수정 Python 파일 Ruff 검사 통과. 신규 회귀 테스트는 근거 쌍, 형식 오류 격리, 재검증 실패·재수정, 불필요한 재호출 방지, 출처·대상·인용 거부, 구형 배열 거부, 공백 제목, 섹션별 호출 상한과 실제 LCEL 파서를 포함한다.

독립 검토에서 전체 마감이 지연된 재검증을 취소할 때 검증된 형제 주장도 유실되는 경계 사례를 발견했다. 실패를 재현한 뒤 재검증의 내부 제한시간을 전체 마감보다 50ms 앞서 끝내도록 수정했다. 제한시간 초과는 이미 검증된 형제 주장을 보존하는 경로로 처리하고 외부 요청 취소는 계속 전파한다. 이 회귀 사례를 포함한 격리·기존 검토 테스트 25개가 통과했다.

최종 결과: 관련 테스트 **397개 통과(10.26초)**, Ruff 검사·포맷 검사 통과. 독립 재검토에서 남은 차단·주요 지적 없음. 코드·프롬프트·테스트는 미커밋 상태로 남겼고 커밋·푸시·배포하지 않았다.
