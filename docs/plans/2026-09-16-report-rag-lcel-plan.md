# AI 보고서 LCEL RAG 연동 계획

## 목표와 품질 기준

현재 보고서 품질을 유지하면서 추가 안내를 실제 검색 원문에 연결한다.
등록 제품, 약 효능·주의·금기, 승인된 상호작용, 성분 합계·단위·그래프는 서버가 소유한다.
RAG는 음식·음료, 생활·복용 안내, 추가 주의사항에만 적용한다.
고정 생활안내 JSON은 신규 경로에서 사용하지 않으며 검색 실패 시 대체 문구로도 쓰지 않는다.

## 확정한 설계

1. Planner: 등록 대상 ID와 허용 섹션, 검색 질문을 구조화 JSON으로 생성한다. 잘못된 계획이나 호출 실패는 서버 검색 계획으로 대체한다.
2. 섹션별 검색·작성: 원 질문을 포함한 최대 3개 쿼리, 대상·문서 유형·버전 필터, 중복 제거와 관련성 정렬, 섹션당 최대 6개 청크·문서당 최대 2개를 사용한다. 섹션은 최대 3개를 병렬 실행한다.
3. 검증·편집: 주장마다 실제 청크 ID와 원문 구절을 연결한다. 코드로 대상·수치·단위·출처·인용을 검사하고 별도 LLM으로 원문의 뒷받침 여부와 충돌을 검사한다. 편집된 문장을 재검증하며 수정 재시도는 섹션당 최대 1회다.

검증 실패 문장은 제외한다. 검증 완료된 섹션은 다른 섹션의 실패나 시간 초과로 폐기하지 않는다.
등록된 다른 제품에 관한 근거를 잘못 붙이거나, 근거 부족을 안전함으로 바꾸지 않는다.
LLM이 개인 복용량 변경·중단·증량을 지시하지 않도록 제한한다.

기존 공백 교정과 검증은 유지하고 RAG와 병렬 실행한다. 전체 API 120초, 요청 시작부터 내부 110초 마감을 공유한다.
기본 데이터 조회나 기존 카드 생성 실패는 기존 오류 정책을 유지한다. RAG 실패는 부분 보고서로 표시한다.
신규 모델 호출의 SDK 자동 재시도는 끄고 요청 안에서 같은 검색을 재사용한다.

## 인터페이스와 배포

- 기존 생성 API와 카드 구조를 유지하고 선택적 `sectionStatuses`를 추가한다.
- 출처에 선택적 `quote`, `chunkId`, `datasetVersion`을 추가한다. URL과 출처 제목은 서버 메타데이터에서 가져온다.
- 검증 상태는 `verified`, `partial`, `unverified`이며 미확인 사유를 표시한다.
- 웹, Markdown, 이메일 첨부는 같은 최종 카드를 소비한다. 이메일 발송 때 재생성하지 않는다.
- `INTAKE_REPORT_RAG_ENABLED=false`를 기본으로 둔다. 실제 품질 비교가 끝나기 전 운영 활성화하지 않는다.
- 기존 Qdrant·모델 설정을 재사용한다. 웹 검색·새 컨테이너·큐·LangGraph·DB 마이그레이션은 제외한다.
- 모델에 사용자 이름·이메일·생년월일을 보내지 않고 로그에는 원문 대신 단계별 수치만 기록한다.

## 구현 순서와 검증

U1. 현재 출력 기준과 공개 원문 출처를 확인한다. 문서 registry에 없는 자료나 생성 문구는 근거에서 제외한다.

U2. LCEL 체인과 별도 검증 경로를 추가한다. 기존 엄격한 공백 검증기를 완화하지 않는다.

U3. 출처·확인 상태 UI 및 이메일을 연결한다. 모바일/데스크톱 카드·수치·펼치기 동작 회귀를 검사한다.

U4. 가상 입력으로 실제 검색·모델 호출을 검사하고 기존/신규 출력 품질을 비교한다. 기준 미달이면 비활성 상태를 유지한다.

필수 검증: 제품·계산 결과 불변, 필수 경고 누락 없음, 가짜 출처·잘못된 대상·단위 변조 차단, 문서 내 지시 무시,
Planner 실패 대체, Qdrant/모델 실패와 시간 초과, 완료 섹션 유지, 호출·동시성 제한, 웹/이메일의 근거 일치.
문장 가독성과 대표 사례의 중요한 안내가 기존보다 나빠지면 전환하지 않는다.

## 작업 경계

핵심 구현은 Terra high, 독립 테스트는 Luna max, 최종 검토는 Astra low로 분담한다.
서비스의 보고서 생성 모델은 기존 설정을 유지한다. 로컬 파일만 수정하며 별도 요청 없이 커밋·푸시·배포하지 않는다.
검증 기록과 미완료 사항은 실행 결과 문서에 기록하고 이 계획서의 요구사항을 임의로 축소하지 않는다.
