# 위험정보 기반 답변 정책 실험 기록

## 상태

`SUCCESS` — 위험정보가 없거나 확인되지 않은 개인화 복약·섭취 질문을 일반 정보 범위로 제한하고, 안전성 검사 전후에 경고를 유지하는 결정론적 경로를 확인했다.

## 가설

임신·수유·연령·신장/간질환·수술 예정·항응고제 복용 여부를 `YES` / `NO` / `UNKNOWN`으로 모델링하면, 누락된 정보를 `NO`로 오인하지 않고 개인화된 복약·영양제 안내를 보수적으로 제한할 수 있다.

## 기준선

기존 `MedicationChatRequest`에는 취약군 여부가 없었다. 따라서 개인화된 용량·섭취·병용 질문이라도 위험정보 누락을 구분하지 못했고, LLM 정제 과정에서 경고 문구가 빠질 가능성도 있었다.

## 변경

- `MedicationChatRiskProfile`에 8개 위험 플래그를 추가하고 기본값을 모두 `UNKNOWN`으로 설정했다.
- `MedicationChatRiskPolicy`가 질문 도메인별 기본 범위를 결정한다.
  - 의약품: 근거가 확인된 내용만 안내
  - 영양제: 근거 기반 내용과 비개인화 일반 가이드 허용
  - 생활습관: 일반 가이드만 허용
- 개인화된 복용·섭취·용량 질문에서 위험 플래그가 `YES` 또는 `UNKNOWN`이면 `WARNING_REQUIRED`로 전환한다.
- 경고는 초안과 LLM 정제 답변 모두에 적용해 `GroundedClaimValidator`가 제한된 최종 문장을 검사하도록 했다.
- `risk.policy` 추적 span에는 도메인·범위·사유 코드만 기록하며, 원문 질문이나 위험정보 값은 기록하지 않는다.

## 검증

| 검증 항목 | 결과 |
| --- | --- |
| 임신 정보 `UNKNOWN`인 개인화 영양제 질문 | `WARNING_REQUIRED`, `PREGNANCY_STATUS_UNKNOWN` |
| 명시적으로 모두 `NO`인 영양제 질문 | 일반 가이드 범위 유지 |
| 의약품 질문 | 항상 `EVIDENCE_ONLY` |
| 수술 예정 `YES` | `SCHEDULED_SURGERY_YES` 경고 |
| 경고 문구가 안전성 검사 입력에도 전달되는지 | 통합 테스트로 확인 |
| 추적 span이 민감 원문을 기록하지 않는지 | 요약 필드만 기록하도록 단위 테스트로 확인 |

관련 회귀 테스트는 `60 passed`였다. 전체 AI Worker 검증과 Ruff 검사는 이 단계의 커밋 직전에 별도로 실행한다.

## 제한과 다음 단계

- 현재 사용자 DB에는 이 위험 플래그를 채우는 확정 컬럼·입력 화면이 없으므로, 요청 모델의 기본값은 안전하게 `UNKNOWN`이다.
- 이 정책은 진단이나 개인별 복용 결정을 하지 않는다. 위험 플래그가 불명확한 경우에는 일반 정보로 한정하고 의료진·약사 확인을 안내한다.
- 실제 체크박스/건강정보 저장이 추가되면, 검증된 값만 `MedicationChatRiskProfile`에 주입하는 API·DB 변경을 별도 작업으로 진행한다.
