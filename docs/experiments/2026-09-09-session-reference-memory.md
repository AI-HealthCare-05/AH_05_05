# 동일 세션 구조화 참조 기억 실험 기록

## 상태

`SUCCESS` — “그 약”, “그 성분”, “그중”을 현재 세션의 최근 근거 섹션에서만 해석하며, 다른 세션의 완료 메시지는 참조 후보에 포함되지 않는다.

## 가설

이미 저장된 `chat_messages`의 동일 세션 완료 이력에서 정해진 근거 섹션만 파싱해 구조화 참조를 만들면, 전체 대화 원문을 LLM에 맡기지 않고도 짧은 후속 질문을 안전하게 보완할 수 있다.

## 기준선

기존 서버는 같은 세션의 최근 10개 메시지를 `history`로 전달했지만, “그 약”을 제품명으로 치환하는 명시적 구조가 없었다. 따라서 제품명이 없는 후속 질문은 일반적인 미해결 질문으로 끝날 수 있었다.

## 변경

- `MedicationChatRequest.session_reference`에 최대 4개의 구조화 엔터티를 전달한다.
- 애플리케이션 서비스는 `AcceptedChatRequest.history`만 사용한다. 저장소가 이미 `chat_session_id`로 필터링해 가져온 최근 완료 메시지이므로 다른 세션 메시지를 읽지 않는다.
- `ChatSessionReferenceMemory`는 다음의 근거 섹션만 파싱한다.
  - `일반 제품 안내`의 제품 행: 약 제품명·약물 타입 보존
  - `세부 성분 안내`의 성분군 행: 영양성분군 타입 보존
  - `확인된 상호작용`의 `A ↔ B` 행: 이름만 보존하고 기존 카탈로그가 다시 타입을 검증
- Core는 단일 제품의 “그 약” 또는 단일 성분의 “그 성분/그 영양제”만 치환한다. “그중”은 현재 세션의 최근 상호작용 대상들을 문장에 명시한 뒤 기존 카탈로그를 다시 조회한다.

## 검증

| 사례 | 결과 |
| --- | --- |
| `타이레놀정500밀리그람` 답변 뒤 `그 약의 복용법도 알려줘` | 제품명으로 치환, `MEDICATION_GUIDE` 경로로 재해석 — PASS |
| `와파린 ↔ 비타민 K` 답변 뒤 `그중 ...` | 두 이름을 명시하되 타입은 카탈로그 재검증 — PASS |
| 현재 세션 이력이 없음 | 참조어를 임의 대상명으로 바꾸지 않음 — PASS |
| 세션 A 후속 질문 | 세션 B의 완료 메시지가 `history`에 포함되지 않음 — PASS |

도메인·Core·앱 서비스·저장소 관련 테스트 `74 passed`로 확인했다. 전체 회귀 검증은 커밋 직전에 별도로 실행한다.

## 제한

- 이 단계는 기존 `chat_messages`를 사용하므로 DB 마이그레이션이 없다.
- 형식이 확인된 근거 섹션만 파싱한다. 임의의 LLM 서술문에서 제품명·성분명을 추론하지 않는다.
- 세션이 바뀌면 기억은 자동으로 비어 있다. 사용자의 장기 건강정보는 이 기능이 아니라 활성 복약/영양제 컨텍스트에서만 가져온다.
