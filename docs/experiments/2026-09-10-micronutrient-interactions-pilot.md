# 미량영양소 상호작용 논문 파일럿 전처리

## 목적

`feature/383`에서 새 학술 PDF 두 건을 기존 지식 코퍼스에 바로 합치지 않고, 전처리 품질과 직접 상호작용 근거를 먼저 검증했다. 이 기록은 이후 컬렉션 생성 전에 어떤 청크가 사용 가능한지 판단하는 근거다.

## 범위와 안전 경계

- 두 문서 모두 저작권·배포 권한을 별도로 확인하기 전까지 `DEMO_RESTRICTED`로 유지한다.
- 이 파일럿에서는 OpenAI 임베딩 API 전송, Qdrant 컬렉션 생성, 활성 컬렉션 교체를 실행하지 않았다.
- `마그네슘–아연`은 이 두 원문에서 직접 근거를 확인하지 못했으므로 상호작용 쌍 메타데이터를 만들지 않았다.
- 원본 PDF는 저장소의 `/data/knowledge/raw/**` 제외 규칙에 따라 로컬에만 두며, Git 커밋·팀 배포에는 포함하지 않는다.

## 입력 문서

| 문서 | 문서 ID | 역할 | 결과 |
| --- | --- | --- | --- |
| BOND Zinc Review (2016) | `research_micronutrient_interactions-bc3fd489c828415e` | 아연 기능·흡수·생체이용률의 보조 근거 | 차단 유지 |
| Micronutrient interactions: effects on absorption and bioavailability (2001) | `research_micronutrient_interactions-e3b164ce9cc98cc6` | 칼슘–철분, 철분–아연, 아연–구리, 비타민 C–철분의 직접 관계 | 승인 |

## 전처리 전략

1. 프로젝트 전용 `KnowledgePdfLoader`를 사용한다. LangChain 기본 `PyPDFLoader`가 아니다.
2. 2001년 논문에는 문서 전용 좌표 파서를 적용한다.
   - 첫 페이지: 제목, 초록, 좌단 본문, 우단 본문 순서
   - 두 번째 페이지: 표 1을 제외하고 본문 좌단→우단 순서
   - 세 번째 페이지: 본문만 보존하고 참고문헌 영역 제외
   - 세로 `Downloaded` 워터마크, 저자 연락처, 이메일 제거
3. `o200k_base`로 청크 토큰을 계산한다.
4. 상호작용 쌍은 성분이 함께 등장한다는 이유만으로 태그하지 않는다. 검수한 `evidence_phrases`가 실제 청크에 있어야만 메타데이터를 부여한다.

## 6차 dry-run 결과

| 문서 | 자동 품질 | 수동 상태 | 청크 | release 후보 | 판단 |
| --- | --- | --- | ---: | ---: | --- |
| BOND Zinc Review | `BLOCKED` | `PENDING` | 64 | 0 | 다단 읽기 순서·복잡 표·과대 청크 문제로 격리 유지 |
| Sandström 2001 | `PASS` | `APPROVED` | 7 | 7 | 원문 3쪽 시각 대조 후 release 후보로 승인 |

Sandström 논문은 레이아웃·회전 텍스트 경고가 0건이었고, 초록 마지막 줄과 본문 페이지 경계를 포함해 원문과 대조했다.

## 직접 관계 메타데이터

| 조합 | 근거가 붙는 조건 |
| --- | --- |
| 칼슘–철분 | `calcium on iron absorption` 문맥 |
| 철분–아연 | 고용량 수용액/보충제 조건에서 철분이 아연 흡수에 영향을 준다는 문맥 |
| 아연–구리 | `zinc-copper-iron interactions` 문맥 |
| 비타민 C–철분 | 비타민 C의 철 흡수 촉진 문맥 |

문서 제목이나 단순 소제목(`Iron–zinc interactions`)만으로는 쌍을 자동 추론하지 않도록 했다. 따라서 일반적인 성분 동시 언급 청크가 상호작용 검색 결과로 과도하게 올라오는 일을 줄인다.

## 다음 게이트

1. `DEMO_RESTRICTED` 원문을 외부 임베딩 API로 전송해도 되는지 별도 승인한다.
2. 승인되면 기존 release와 합친 새 불변 컬렉션을 생성한다.
3. 칼슘–철분, 철분–아연, 아연–구리, 비타민 C–철분 평가 질문으로 기존 컬렉션과 검색 정확도를 비교한다.
4. BOND 논문은 표 좌표 복원과 다단 전용 파서가 준비될 때까지 release·임베딩에서 제외한다.
