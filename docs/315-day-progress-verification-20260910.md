# 315 일수 진행률 및 시간 변경 검수

## 표시 기준

- 홈·진행 중/지난 챌린지 카드·상세의 총 진행률은 `달성 일수 / 목표 일수`로 표시한다.
- 실제 목표가 하나 이상 있는 날짜만 목표 일수에 포함한다. 해당 날짜의 모든 대상·복용 슬롯을 완료해야 1일 달성이다.
- 날짜별 개별 복용 기록은 계속 `완료 횟수 / 해당 날짜 목표 횟수`로 표시한다.
- 진행 중 되돌리기는 항목 체크, 하루 달성, 달력 색, 일수 진행률을 함께 되돌린다.
- 종료·취소 후 확정된 결과는 occurrence 스냅샷으로 계산하며, 이후 원본 기록 변경은 확정 결과·배지를 바꾸지 않는다.

## API 호환성

서버는 `targetDayCount`, `completedDayCount`, `dayProgressRate`를 추가 제공한다. 기존 횟수 필드와 배지 판정은 유지한다. 이전 API를 만난 프런트엔드는 응답에 포함된 전체 occurrence의 날짜별 완료 여부로 일수를 계산한다. DB 스키마 변경은 없다.

## 검수 항목

1. 3회 목표를 모두 먹은 첫날과 1회 목표가 미완료인 둘째 날은 `1 / 2일`, 50%다.
2. 같은 날 일부만 완료하면 개별 체크만 표시되고 그날은 미달성이다.
3. 당일 모두 완료하면 가운데 원·체크 모션이 표시되고 해당 날짜 네모가 채워진다.
4. 홈에서 먹은 기록을 되돌린 후 상세로 돌아오면 체크·일수·네모가 함께 해제된다. 복약과 영양제 모두 확인한다.
5. 마이페이지에서 예정 시각을 이미 지난 시간으로 앞당겨도 기존 날짜/슬롯 목표가 삭제되지 않는다. 새로 참여할 때의 참여 전 목표를 만들어내지는 않는다.
6. 종료 후 원본 기록을 되돌려도 종료 결과와 지급 배지는 유지된다.

## 검증 범위

최종 통합 브랜치에서 UI 81개(일수·undo·완료 모션·날짜 스크롤·API·홈·자동 갱신), 백엔드 115개(메모리 SQLite: API·일수·시간 변경·배지·종료 워커)가 통과했다. 타입 검사와 빌드 통과(기존 큰 청크 경고 있음).

시간 변경 경계의 과거 목표는 기록으로 보존한다. 예를 들어 17시에 19→16으로 앞당겨 보존된 오늘 목표는 이후 18시로 다시 바꿔도 같은 ID/기록 연결을 유지한다. 앞으로의 목표 시각은 최신 설정을 따른다. 슬롯 자체 삭제 정책은 이번 시간 변경 수정 범위가 아니다.
