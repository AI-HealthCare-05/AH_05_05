# 추가 PDF 전처리 품질 보완 계획

## 목표

추가한 PDF 12개를 일괄 처리하기 전에 유형별 대표 문서 4개에서 텍스트 복원과 자동 품질 차단 기준을 검증한다. 자동 검사가 통과했다는 이유만으로 표가 무너지거나 검색 메타데이터가 비어 있는 청크가 배포 후보가 되지 않도록 한다.

## 현재 문제

- 페이지 번호가 달라지는 반복 머리글은 문자열이 완전히 같지 않아 제거되지 않는다.
- PDF 줄 끝 하이픈과 soft hyphen이 남아 검색어와 문서 용어가 달라진다.
- FDA 목차가 본문과 중복되어 같은 제목과 내용이 반복될 수 있다.
- 논문의 출판 정보·저자 기여·참고문헌 주변 문장이 검색 청크에 남는다.
- 표의 열 순서가 무너져도 현재 자동 검사는 `PASS`를 반환한다.
- 회전된 표 머리글·축 라벨이 있어도 추출 위험이 기록되지 않는다.
- 약명·영양성분명과 근거 수준이 비어 있어도 자동 검사에서 드러나지 않는다.

## 구현 원칙

1. 반복 머리글은 숫자만 마스킹한 서명으로 비교하되, 페이지 가장자리에서 반복되는 줄만 제거한다.
2. soft hyphen은 제거하고, 줄 끝 하이픈은 문서 안에 온전한 단어가 확인될 때만 붙인다. 그 외에는 의미 있는 하이픈을 보존한다.
3. FDA `CONTENTS` 페이지는 중복 본문으로 사용하지 않는다.
4. 복잡한 표는 임의로 열을 재구성하지 않고 자동 상태를 `REVIEW`로 내려 원문 대조를 요구한다.
5. 다단·회전 텍스트는 본문을 레이아웃 모드 결과로 교체하지 않고 위험 신호만 기록한다. 일반 추출 본문을 유지하면서 원문 대조 대상으로 분리한다.
6. 검색 엔터티·근거 수준·짧은 청크·보일러플레이트·미복원 줄바꿈을 문서 품질 지표로 기록한다.
7. 번호형 `DNI`·`Drug-Nutrient Interaction` 장 제목을 약명과 무관한 일반 규칙으로 인식하고, 제목만 남은 극소 청크는 다음 의미 단위에 병합한다.
8. 기존처럼 치명적인 크기·계층·단위 오류만 `BLOCKED`, 사람이 판단할 수 있는 표·메타데이터 문제는 `REVIEW`로 분리한다.

## 검증 범위

- FDA levothyroxine 허가문서
- levothyroxine 음식·약물 상호작용 문헌고찰
- aspirin·warfarin 영양소 상호작용 논문
- botanical supplement 이상반응 논문

전체 12개 처리, OpenAI 임베딩 전송, Qdrant 컬렉션 생성은 이번 범위에서 제외한다.

## 1차 텍스트 기반 구현 후 결과

대표 문서 4개를 `knowledge-additional-research-pilot-v2`로 다시 처리했다. 최종 산출물은 115개 청크이며, 네 문서 모두 자동 `REVIEW`, 수동 `PENDING`으로 격리되어 일괄 인덱싱 대상은 0개다. 감소분은 중복 FDA 목차·출판 후면부와 제목만 남은 극소 청크이며, 잘못 분류되던 상호작용 장을 독립 의미 단위로 다시 묶었다.

## 보완 효과

- 페이지마다 숫자가 달라지는 반복 머리글도 정규화된 서명으로 제거한다.
- soft hyphen과 줄 끝 하이픈을 보수적으로 복원해 검색어와 원문 용어의 불일치를 줄인다.
- FDA 중복 목차, 논문 앞면 인용 정보, 저자 기여·펀딩·제조사 후면부를 검색 본문에서 제외한다.
- 장식선이 붙은 제목과 번호형 상호작용 절을 실제 의미 섹션으로 보존한다.
- 표 구조·검색 엔터티·근거 수준·보일러플레이트·짧은 조각을 자동 품질 사유 코드로 기록한다.
- 문서명·출처 URL·DOI·저자·발행연도·약명/성분명·근거 수준·연구 대상을 manifest에서 청크까지 보존한다.
- 표 포함 청크 수와 다단·회전 텍스트 경고 페이지 수를 보고서에 기록하고, 모든 표 청크를 수동 검수 문서에 반드시 포함한다.
- `4. ASA and DNIs`처럼 약명마다 달라지는 장 제목을 일반 패턴으로 `INTERACTION`에 분류한다.
- 복잡한 표는 추측으로 복원하지 않고 `REVIEW`로 격리해 잘못 연결된 수치가 챗봇 근거가 되는 것을 방지한다.

## 다음 수동 검수 순서

1. FDA 문서의 최소 18토큰 청크와 표 5개의 열 순서가 독립 근거로 안전한지 확인한다.
2. Levothyroxine 문헌고찰의 회전 텍스트 5개 페이지에서 표 머리글과 본문 순서를 원문과 대조한다.
3. Aspirin·Warfarin 논문의 표 3개를 원본과 대조해 약물·영양소·효과 열이 섞이지 않았는지 확인한다.
4. Botanical supplement 논문의 표 3개와 18토큰 조각을 확인하고 식물별 엔터티 세분화 범위를 결정한다.
5. 네 문서가 모두 수동 승인되기 전에는 나머지 8개 PDF 전체 처리나 Qdrant 릴리스 생성을 진행하지 않는다.

## 수동 대조 방법

각 검수 Markdown의 `원본 PDF`를 먼저 열고 `우선 대조 위치`에 표시된 원본 페이지와 `결정론적 표본 청크`를 나란히 비교한다. 페이지 번호는 PDF 파일의 실제 페이지 순번이며, 본문에 인쇄된 학술지 페이지 번호와 다를 수 있다.

1. 표의 행을 왼쪽에서 오른쪽으로 읽었을 때 청크의 문장 순서와 같은지 확인한다.
2. 약·성분, 용량, 대상자 수, 결과, 권고가 서로 다른 행과 섞이지 않았는지 확인한다.
3. 회전된 표에서는 열 제목이 빠지거나 본문 끝에 잘못 붙지 않았는지 확인한다.
4. 단위와 부호(`mg`, `mcg`, `%`, 증가·감소 화살표)가 원문과 같은지 확인한다.
5. 문제가 없으면 `APPROVED`, 추가 확인이 필요하면 `KEEP_PENDING`, 규칙 수정이 필요하면 `REPROCESS_REQUIRED`에 체크하고 검수자·날짜·메모를 작성한다.

우선 확인할 위치는 다음과 같다.

| 문서 | 최우선 원본 페이지 | 대응 청크 |
| --- | --- | --- |
| FDA LEVO-T | p.5, p.8-10, p.14-16 | 14, 23, 24, 32, 34 |
| Levothyroxine 문헌고찰 | p.4, p.6, p.8 | 6, 8, 10 (p.4-8 전체는 회전 텍스트 경고 범위) |
| Aspirin·Warfarin 논문 | p.8-10, p.17 | 13, 14, 25 |
| Botanical 이상사례 논문 | p.3-5 | 9, 12, 13 |

## 2차 좌표 기반 재처리 결과

표 영역과 본문을 좌표로 분리하고, 셀 행 직렬화·열 개수·원본 토큰·숫자 합계·다단 단어 배정 검사를 추가한 뒤 대표 문서 4개를 `knowledge-additional-research-pilot-v3`로 다시 처리했다. 선 없는 표는 페이지에 `Table1`·`Table II` 표제가 있을 때만 text-table 전략을 2차 적용해 일반 본문 전체가 표로 오인되는 범위를 제한했다. 셀 문자열은 `x_tolerance=1`로 추출해 `StudyDesign`을 `Study Design`처럼 복원했다.

| 대표 문서 | v2 청크 | v3 청크 | 좌표 기반 표 청크 | 최종 자동 상태 | 결과 |
| --- | ---: | ---: | ---: | --- | --- |
| FDA LEVO-T 허가문서 | 39 | 51 | 17 | `REVIEW` | 투여량 표를 별도 청크로 분리했고 치명적 구조 손상은 발견되지 않았으나 수동 승인은 유지하지 않음 |
| Levothyroxine 문헌고찰 | 26 | 35 | 15 | `BLOCKED` | 회전 표의 셀 소속 또는 원본 토큰 보존을 검증하지 못한 페이지가 있어 `TABLE_STRUCTURE_UNSAFE`로 차단 |
| Aspirin·Warfarin 논문 | 36 | 45 | 21 | `BLOCKED` | p.8·9·17의 선 없는 표를 좌표 표로 감지했지만 p.17 머리글 분할과 일부 토큰 손실이 남아 차단 |
| Botanical 이상사례 논문 | 14 | 37 | 24 | `BLOCKED` | p.3의 선 없는 표와 p.4-7 표를 분리했으나 복합 머리글과 긴 무공백 문자열을 안전하게 복원하지 못해 차단 |

v3 보고서에 기록된 전체 청크 후보는 168개지만, 안전성 검사 후 로컬 산출물로 유지된 문서는 FDA 1개·51청크뿐이다. 나머지 3개 문서는 삭제한 것이 아니라 검수 보고서만 남긴 `AUTOMATIC_QUALITY_BLOCKED` 상태이며 OpenAI 임베딩과 Qdrant 적재 대상이 아니다.

### 해결된 문제

- 표 경계 안의 단어를 본문에서 제외해 표와 본문의 중복 근거 생성을 막았다.
- 표 행을 `열 이름=셀 값`으로 직렬화하고 행을 쪼개지 않는 표 전용 청킹을 적용했다.
- `Same as ...` 참조 행에 직전 행의 열 정보를 함께 남겨 단독 청크의 문맥 손실을 줄였다.
- `Table1`처럼 공백이 사라진 표제도 선 없는 표 탐지 조건으로 인식한다.
- PDF CropBox 바깥의 음수 좌표를 허용하되 좌표 축 순서는 검증한다.
- 한 페이지의 좌표 추출 실패가 문서 전체 fallback으로 번지지 않도록 페이지 단위로 격리한다.
- 오른쪽 단이 몇 픽셀 위에서 시작해도 상단 전폭 → 왼쪽 단 → 오른쪽 단 → 하단 전폭 순서를 유지한다.
- 열 개수, 원본 토큰, 숫자·단위, 계산 가능한 합계를 검증하고 실패 문서는 자동 `BLOCKED`로 분류한다.

### 아직 수동 승인을 보류하는 이유

- 다층 표 머리글이 여러 행과 열로 분할된 문서는 열 이름을 하나의 의미 있는 머리글로 합치는 추가 규칙이 필요하다.
- 회전 표 일부는 좌표가 복원돼도 셀 내부 텍스트 소속을 원문과 동일하다고 자동 입증할 수 없다.
- Botanical 문서의 긴 무공백 문자열은 단순 공백 삽입으로 고치면 학명·수치가 달라질 수 있어 임의 복원하지 않았다.
- 따라서 이번 단계의 성과는 모든 표를 억지로 통과시킨 것이 아니라, 안전하게 복원된 문서와 불확실한 문서를 자동으로 분리한 것이다.

## 3차 청크 격리·표 행 복원 결과
