# #225 복약 페이지 개편 설계

## 목표

복약 목록을 처방 상세 페이지 없이 한 화면에서 비교·관리할 수 있게 개편한다. 서버가 처방 종료 여부와 조회 기간을 결정하고, 프론트는 그 계약을 그대로 사용해 여러 처방을 펼쳐 보거나 선택 삭제한다.

## 전제와 범위

- 기준 브랜치는 #226이 병합된 `main`이다.
- 기존 API 경로 `GET /api/v1/medications`를 유지한다.
- 모델과 마이그레이션은 변경하지 않는다.
- `completed_at`을 채우거나 완료 상태 배치를 만들지 않는다.
- `CareEpisodeStatus.COMPLETED`를 새로 사용하지 않는다.
- 물리 삭제와 벌크 삭제 API를 만들지 않는다.
- 홈 화면의 날짜 출력 결과는 바꾸지 않는다.
- 새 프론트 의존성을 추가하지 않는다.
- Windows에서는 `pnpm install`, `npm i`, `npm install`, `yarn`, `pnpm add`, `pnpm update`를 실행하지 않는다. `node_modules`나 락파일을 복구하거나 재생성하지 않는다.

## 서버 설계

### 조회 기간 계약

`GET /api/v1/medications`는 선택 쿼리 `from`, `to`를 받는다. 날짜는 ISO `YYYY-MM-DD` 형식이다.

| 입력 | 확정 범위 |
|---|---|
| 둘 다 없음 | 서버의 오늘에서 3개월 전부터 오늘까지 |
| `from`만 있음 | `from`부터 `from + 3개월`까지 |
| `to`만 있음 | 서버의 오늘부터 `to`까지 |
| 둘 다 있음 | 전달된 범위 그대로 |

월 계산은 달력 월을 기준으로 한다. 예를 들어 5월 31일에서 3개월 전은 달력 연산이 정한 2월 말일이다. 서버 시간대는 `config.TIMEZONE`을 사용한다.

다음 입력은 422를 반환한다.

- 확정된 `from`이 `to`보다 뒤인 경우
- 확정된 기간이 5년을 초과하는 경우
- FastAPI가 날짜로 파싱할 수 없는 경우

5년 초과 범위는 조용히 자르지 않는다. 사용자가 선택한 조건과 실제 조회 조건이 달라지는 것을 막기 위해 명시적으로 거절한다.

### 목록 필터와 정렬

조회 대상은 다음 조건을 모두 만족해야 한다.

- 요청 사용자 소유
- `status=ACTIVE`
- OCR 원본 작업이 연결됨
- `medication_start_date`가 존재함
- 시작일이 확정된 `from`과 `to` 사이임

끝난 처방도 현재 DB 상태는 `ACTIVE`이므로 이 조건에 포함된다. `CANCELLED`는 사용자가 삭제한 기록이므로 제외된다. 지시서의 `status__in=[ACTIVE, COMPLETED]` 예시는 “COMPLETED를 사용하지 않는다”는 최종 규칙과 충돌하므로 적용하지 않는다.

목록은 `medication_start_date DESC`, `id DESC`로 정렬한다. 종료일은 계산값이므로 SQL 기간 조건에 사용하지 않는다.

### 종료일과 완료 판정

목록 응답 `MedicationOverview`에 `is_finished: bool`을 추가한다. `CamelModel` 직렬화 결과는 `isFinished`다.

종료일 계산과 완료 판정은 순수 함수로 한곳에 둔다.

1. 정기 복용 약의 일수 중 최댓값을 사용한다.
2. 정기 복용 약이 없으면 전체 약의 계산된 일수 최댓값을 사용한다.
3. 약 일수가 없으면 처방의 `medication_days`, 그것도 없으면 1일을 사용한다.
4. `end_date = medication_start_date + longest_days - 1`이다.
5. `is_finished = end_date < 서버 기준 오늘`이다.

프론트는 `endDate`와 사용자 기기 시계로 완료 여부를 다시 계산하지 않는다.

### 종료 처방 수정 차단

`PUT /api/v1/med/medication/schedule/{record_id}`는 트랜잭션 안에서 처방과 약 목록을 잠근 뒤 같은 종료일 함수로 완료 여부를 검사한다. 종료일이 서버 기준 오늘보다 앞이면 저장 전에 409를 반환한다.

- 코드: `MEDICATION_SCHEDULE_FINISHED`
- 메시지: `이미 끝난 처방은 수정할 수 없습니다`

종료일이 오늘인 처방은 아직 끝난 처방이 아니므로 수정할 수 있다. GET 일정 조회와 DELETE 취소는 종료 여부와 관계없이 기존 계약을 유지한다.

## 프론트엔드 설계

### 파일 책임

- `MedicationsPage.tsx`: 조회, URL 필터, 펼침 ID 집합, 선택 ID 집합, 삭제 결과를 조정한다.
- `MedicationEpisodeCard.tsx`: 접힌 요약과 펼친 약 목록을 렌더링한다. 선택 모드와 완료 상태에 따라 가능한 동작만 노출한다.
- `MedicationPeriodFilterSheet.tsx`: 최근 1·3·6개월과 직접 지정 입력을 제공한다.
- `MedicationBulkDeleteDialog.tsx`: 선택 개수 확인, 진행 상태, 전체 실패 재시도를 표시한다.
- `MedicationSlotSheet.tsx`: 기존 활성 처방의 정기 약 시간대 수정에만 재사용한다.
- `shared/lib/dateLabel.ts`: 날짜와 기간 포맷을 담당하며 연도 표시를 옵션으로 받는다.

`MedicationEpisodePage.tsx`, 해당 export, `/medications/:recordId` 라우트는 제거한다. 기존 상세 페이지 E2E는 삭제하지 않고 아코디언 동작 검증으로 바꾼다.

### 목록과 아코디언

헤더 제목은 `복약`이다. 기본 상태의 우측에는 기존 약봉투 등록 `+`와 `삭제`를 함께 둔다.

접힌 카드에는 다음 정보를 표시한다.

- 연도를 포함한 처방 기간
- 약 개수
- `복용 중` 또는 `복용 완료`
- 복용 중이면 서버 `daysRemaining`으로 만든 D-day

`daysRemaining`은 오늘을 포함한 값이므로 1이면 `D-Day`, 2 이상이면 `D-{daysRemaining - 1}`로 표시한다. 완료 여부는 오직 `isFinished`를 사용한다.

카드는 각각 독립적으로 펼쳐지며 여러 개를 동시에 열 수 있다. 펼침 상태는 컴포넌트 메모리에만 두고 URL이나 localStorage에 저장하지 않는다.

펼친 카드에는 약 이름·용량·복용 시간대와 약봉투 사진 링크를 표시한다. 활성 처방의 정기 약만 `MedicationSlotSheet`를 열 수 있다. 필요 시 복용 약과 완료 처방에는 수정 버튼이나 비활성 버튼을 렌더하지 않는다. 완료 처방도 사진 보기와 삭제는 가능하다.

체크박스, 펼침 버튼, 약 수정 버튼은 중첩 버튼이 되지 않도록 독립된 인터랙션 영역으로 구성한다.

### 기간 필터와 URL

필터 선택지는 최근 1개월, 최근 3개월, 최근 6개월, 직접 지정이다.

- 최근 3개월은 기본값이며 URL에서 `from`, `to`를 제거한다. 서버 기본 범위를 사용한다.
- 최근 1개월과 6개월은 오늘 기준 날짜를 계산해 `?from=YYYY-MM-DD&to=YYYY-MM-DD`를 쓴다.
- 직접 지정은 두 날짜가 모두 있고 `from <= to`일 때만 적용한다.
- URL이 바뀌면 목록을 다시 조회한다.
- 브라우저 뒤로가기는 이전 URL 필터와 목록을 복원한다.
- 알 수 없거나 한쪽만 있는 URL 쿼리는 그대로 서버에 전달해 서버 계약에 따라 처리한다.

결과가 없으면 `이 기간에 등록한 처방이 없어요`와 `기간 넓히기`를 보여준다. `기간 넓히기`는 필터 시트를 열며 약봉투 등록 CTA를 빈 결과 안에 추가하지 않는다. 헤더의 `+`는 유지한다.

### 날짜 표시

공유 함수는 단일 날짜와 기간을 지원하고 `includeYear` 옵션을 받는다.

- 같은 해: `2026년 8월 14일 ~ 20일` 또는 `2026년 8월 14일 ~ 9월 2일`
- 해가 바뀜: `2026년 12월 28일 ~ 2027년 1월 3일`
- 연도 옵션 없음: 홈의 기존 `8월 14일 ~ 20일` 형식 유지

복약 목록은 연도 옵션을 켠다. 홈의 `MedicationRecordGrid`와 `MedicationTimeline`은 공유 함수를 사용하더라도 출력 문자열과 레이아웃이 달라지지 않아야 한다.

### 선택 삭제

기본 헤더의 `삭제`를 누르면 선택 모드로 전환한다.

- 카드 왼쪽에 개별 체크박스를 표시한다.
- 카드 본문 클릭도 해당 카드 선택만 바꾸고 펼침 상태는 바꾸지 않는다.
- 헤더 제목은 `N개 선택`으로 바뀐다.
- 우측에는 `취소`를 항상, `삭제하기`는 1개 이상 선택됐을 때만 표시한다.
- 전체 선택 체크박스는 제공하지 않는다.

확인창의 문구는 `N개를 삭제할까요?`다. 기존 `DELETE /api/v1/medications/{record_id}`를 `for...of`로 한 건씩 순차 호출하고 ID별 성공 여부를 기록한다. `Promise.all`이나 벌크 API는 사용하지 않는다.

- 전부 성공: 성공한 카드를 제거하고 `N개를 삭제했어요` 토스트를 표시한 뒤 선택 모드를 종료한다.
- 일부 실패: 성공 카드만 제거한다. 실패 카드는 목록과 선택 상태를 유지하고 `N개를 삭제했어요. N개는 실패했어요` 토스트를 표시한다.
- 전부 실패: 목록과 선택 상태를 유지하고 에러 다이얼로그에서 같은 항목을 재시도할 수 있게 한다.

## 오류와 접근성

- 목록 조회 실패는 사용자가 다시 시도할 수 있는 오류 상태로 표시한다.
- 필터 입력 오류는 시트 안에서 설명하고 잘못된 URL 서버 응답은 목록 오류 상태로 표시한다.
- 삭제 중에는 중복 실행을 막고 진행 문구를 보여준다.
- 아코디언 버튼은 `aria-expanded`와 연결된 패널 ID를 가진다.
- 선택 체크박스는 처방 기간이 포함된 접근 가능한 이름을 가진다.
- 모든 조작 대상은 최소 터치 영역과 키보드 포커스 링을 유지한다.
- 375px 폭에서 가로 스크롤이 생기지 않도록 헤더 액션과 카드 정보를 줄바꿈 가능하게 구성한다.

## 테스트 전략

### 백엔드

- 파라미터가 없을 때 최근 3개월 범위
- `from`·`to` 동시 지정과 시작일 기준 필터
- `from`만, `to`만 전달한 기본값 조합
- `from > to`와 5년 초과의 422
- `CANCELLED` 제외와 최근 시작일·ID 순 정렬
- 종료일이 어제·오늘·내일인 경계의 `isFinished`
- 완료 처방 일정 PUT의 409와 데이터 미변경
- 오늘 종료 처방 일정 PUT 성공

### 프론트엔드

- 응답의 `isFinished`를 사용하고 기기 날짜로 완료 여부를 재계산하지 않음
- 카드 여러 개 동시 펼침과 페이지 이동 없음
- 완료 처방에서 시간 변경 진입 요소가 없고 삭제·사진 보기는 유지
- 기본 3개월 URL 무쿼리, 다른 프리셋과 직접 지정 URL, 뒤로가기 복원
- 빈 기간의 `기간 넓히기`
- 같은 해·연도 경계 날짜 표시와 홈 날짜 출력 회귀
- 선택 모드에서 펼침 차단, 0개일 때 삭제하기 숨김, 전체 선택 없음
- 순차 삭제의 전부 성공·일부 실패·전부 실패 및 재시도
- 제거된 상세 라우트를 참조하던 기존 E2E의 새 아코디언 계약 전환
- 목업과 실 API 모드의 계약 확인

`origin/main`에서 이미 재현되는 #218 `signup-real-api-contract.spec.ts` 이름 검증 실패는 #225 회귀와 분리해 보고한다.

## 검증 제약

프론트 워크트리에 `node_modules`가 없을 때 `pnpm build`, `pnpm typecheck`, `playwright test`도 pnpm의 자동 설치를 유발할 수 있다. 개발자가 WSL에서 해당 워크트리의 의존성을 준비하기 전에는 이 명령들을 실행하지 않는다. 준비 여부를 확인한 뒤 허용된 검증 명령만 사용한다.
