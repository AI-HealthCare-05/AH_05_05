# 좌표 기반 PDF 표·다단 전처리 설계

## 목표

연구 논문과 의약품 허가문서에서 일반 텍스트 추출만으로 무너지는 표의 셀 소속과 다단 본문의 읽기 순서를 좌표 기반으로 복원한다. 값과 단위의 소속을 검증할 수 없는 문서는 Qdrant 인덱싱 전에 자동 차단하며, 대표 문서 4개를 다시 전처리해 수동 검수 가능한 근거를 만든다.

## 해결할 문제

- 회전 표의 머리글과 셀이 본문 문자열에 평탄화되어 어떤 값이 어느 열에 속하는지 알 수 없다.
- 다단 논문에서 오른쪽 단락이 왼쪽 단락 중간에 섞이거나 페이지 상단 표가 본문 뒤로 이동한다.
- `6 | 0 | 8 | 14`와 같은 셀 값이 `60 8 1 4`로 합쳐져 수치 의미가 바뀔 수 있다.
- `Same as calcium supplement`처럼 이전 행을 참조하는 셀은 단독 청크가 되면 대상을 잃는다.
- 현재 자동 품질 검사는 복잡한 표를 검수 대상으로 표시할 뿐, 구조 손상이 확인돼도 인덱싱을 차단하지 않는다.

## 설계 선택

### 1. 추출 엔진

`pdfplumber`를 좌표·표 추출 엔진으로 추가하고 `pypdf`는 기존 문서 유형과 실패 시의 보수적 대체 경로로 유지한다. 좌표 처리는 `RESEARCH_ARTICLE`과 `REGULATORY_DRUG_LABEL`에만 우선 적용한다. 스캔 PDF OCR은 이번 범위에 포함하지 않는다.

### 2. 페이지 블록 계약

기존 `KnowledgePage.content`는 호환성을 위해 유지하고, 페이지에 순서가 보존된 `blocks`를 추가한다.

- `TEXT`: 좌표로 정렬된 본문 블록
- `TABLE`: 표 머리글과 행이 구조화된 블록
- 각 블록은 `bbox`, `order`, `content`를 가진다. PDF의 CropBox 바깥 객체는 음수 좌표를 가질 수 있으므로 좌표 부호를 제한하지 않고 축의 시작·끝 순서만 검증한다.
- 표 블록은 `headers`, `rows`, `column_count`, `validation_errors`를 가진다.
- 좌표는 PDF 좌표계의 `(x0, top, x1, bottom)`을 사용한다.

`content`는 블록을 `order` 순서대로 직렬화한 결과다. 기존 normalizer와 splitter가 `content`를 계속 사용할 수 있으므로 이전 문서와 테스트를 깨지 않는다.

### 3. 표 영역 분리와 행 복원

1. 페이지에서 `find_tables()`로 표 경계와 셀을 찾는다.
2. 표 경계 안의 단어는 본문 후보에서 제외해 중복 추출을 막는다.
3. 셀 좌표를 행·열 위치로 정렬하고, 첫 번째 의미 있는 행을 머리글로 사용한다.
4. 병합 셀이나 빈 셀은 왼쪽 값을 임의 전파하지 않는다. 참조 표현만 이전 행의 동일 열 값과 함께 명시적으로 보강한다.
5. 각 행은 `열 이름=셀 값 | 열 이름=셀 값` 형식으로 직렬화한다. 열 이름이 없으면 `열 1`, `열 2`처럼 위치를 보존한다.
6. 표 전체는 별도 `TABLE` 청크 후보가 되며 일반 본문과 overlap하지 않는다.

### 4. 다단 본문 읽기 순서

표 밖의 단어를 줄 단위로 묶은 뒤 페이지 중앙을 가로지르는 공백과 좌표 분포로 단 수를 판정한다.

- 페이지 폭의 절반 이상을 차지하는 상단 블록을 먼저 읽는다.
- 그 다음 왼쪽 열을 위에서 아래로 읽고, 오른쪽 열을 위에서 아래로 읽는다.
- 페이지 폭의 절반 이상을 차지하는 하단 블록을 마지막에 읽는다.
- 단일 단 문서는 위에서 아래로 읽는다.
- 원본 단어가 누락되거나 두 블록에 중복 배정되면 안전하지 않은 읽기 순서로 판정한다.

### 5. 자동 품질 검사

다음 검사를 모두 통과해야 표를 인덱싱 후보로 유지한다.

- 모든 행의 셀 개수가 `column_count`와 일치한다.
- 표 경계 안에서 추출된 비어 있지 않은 원본 셀 문자열이 직렬화 결과에 보존된다.
- 숫자, 부호, 백분율, 용량 단위가 셀별로 보존된다.
- 합계 행에 숫자가 있고 구성 행의 합계를 계산할 수 있으면 열별 합계가 일치한다.
- 본문 단어는 누락과 중복 없이 정확히 한 블록에 배정된다.

표 검사가 실패하면 `TABLE_STRUCTURE_UNSAFE`, 다단 순서 검사가 실패하면 `READING_ORDER_UNSAFE`를 기록하고 자동 상태를 `BLOCKED`로 설정한다. 단순히 복잡한 표가 있다는 사실은 기존처럼 `REVIEW` 사유로 유지한다.

### 6. 청킹 계약

- `TEXT` 블록은 기존 의미 섹션 분리와 문서 유형별 토큰 정책을 그대로 적용한다.
- `TABLE` 블록은 표 제목·머리글·행 경계를 우선하며, 행을 둘로 자르지 않는다.
- 표 한 행이 hard max를 초과하면 해당 문서는 `TABLE_STRUCTURE_UNSAFE`로 차단한다.
- 표 청크에는 `content_kind=TABLE`을, 일반 청크에는 `content_kind=TEXT`를 기록한다.
- 표 청크는 overlap을 0으로 고정한다.

### 7. 실패 처리

- `pdfplumber`가 페이지를 열지 못하면 기존 `pypdf` 텍스트를 사용하되 레이아웃 안전성을 확인할 수 없음을 경고한다.
- 표가 감지됐지만 셀 구조를 만들지 못하면 평탄화된 내용을 근거로 사용하지 않고 `TABLE_STRUCTURE_UNSAFE`로 차단한다.
- 다단 여부를 확정할 수 없으면 임의 재배열하지 않고 `READING_ORDER_UNSAFE`로 차단한다.
- 자동 차단은 문서 삭제가 아니라 청크 단위 검수·재처리 대상으로 격리하는 의미다.
- 모든 후보 페이지와 청크는 `quarantine/text`, `quarantine/chunks`에 상태·사유와 함께 보존한다.
- 청크 상태는 `APPROVED`, `PENDING`, `REPAIR_REQUIRED`, `EXCLUDED_NON_CONTENT`로 구분한다.
- 참고문헌처럼 검색 근거가 아닌 청크는 `EXCLUDED_NON_CONTENT`, 좌표·표 검증에 실패한 청크는 `REPAIR_REQUIRED`로 기록한다.
- 필요한 청크가 하나라도 `PENDING` 또는 `REPAIR_REQUIRED`이면 `release/chunks`를 만들지 않는다. 일부 청크만 먼저 Qdrant에 넣지 않고, 필요한 청크가 모두 승인된 문서 버전만 하나의 불변 릴리스로 인덱싱한다.

## 대표 문서 검증 범위

1. FDA LEVO-T 허가문서: 단일 단 오탐 감소와 투여량 표 셀 보존
2. Levothyroxine 상호작용 문헌고찰: 회전 표와 이전 행 참조 복원
3. Aspirin·Warfarin 영양소 상호작용 논문: 표 머리글 순서와 중복 Figure 제거
4. Botanical supplement 이상반응 논문: 페이지 상단 표 순서와 숫자 열·합계 보존

대표 4개 문서만 다시 처리한다. 나머지 PDF 일괄 처리, OpenAI 임베딩 전송, Qdrant 컬렉션 생성·활성화는 수행하지 않는다.

## 테스트 기준

- 좌표가 있는 표가 본문과 중복되지 않고 행·열 구조로 복원된다.
- 열 개수 불일치, 숫자·단위 손실, 합계 불일치가 각각 차단 사유가 된다.
- 상단 전폭 제목, 좌측 단, 우측 단, 하단 전폭 꼬리말 순서가 보존된다.
- 중복 또는 누락된 단어가 있으면 읽기 순서 검사가 실패한다.
- 기존 pypdf 기반 문서와 `KnowledgePage(content=...)` 생성 코드는 그대로 동작한다.
- 대표 문서 보고서에 차단 사유와 표·다단 검수 위치가 기록된다.

## 비목표

- OCR 기반 스캔 문서 복원
- 그림·차트의 시각적 의미 해석
- 표 수치를 의료 규칙으로 자동 승인
- 전체 자료 재인덱싱 또는 Qdrant 활성 컬렉션 교체
