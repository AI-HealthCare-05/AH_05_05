# 챌린지 기준 데이터 Aerich 시드 설계

## 목표

새 데이터베이스에서 `aerich upgrade`만 실행해도 공통코드 그룹, 공통코드, 기본 배지, 기본 공식 챌린지가 등록되도록 한다. 운영에 필요한 데이터만 포함하고 테스트·폐기 데이터는 제외한다.

## 대상 데이터

### 공통코드 그룹

- `CHAT/P_REASON`: 챗봇 평가 긍정 사유
- `CHAT/N_REASON`: 챗봇 평가 부정 사유
- `CHL/CHL_TYPE`: 챌린지 유형
- `CHL/CHL_PERIOD`: 챌린지 기간
- `CHL/CHK_TYPE`: 인증 방식
- `CHL/CHK_FREQ`: 인증 빈도

`CHAT/TEST` 그룹은 포함하지 않는다.

### 공통코드

- `CHAT/P_REASON`: `P01` 최신, `P02` 정확함, `P03` 도움이 됨, `P04` 지침을 따름, `P05` 우수한 출처
- `CHAT/N_REASON`: `N01` 오래된 정보, `N02` 부정확함, `N03` 잘못된 출처, `N04` 너무 김
- `CHL/CHL_TYPE`: `T01` 걷기, `T02` 스트레칭, `T03` 물마시기
- `CHL/CHL_PERIOD`: `D7` 7일, `D14` 14일, `D30` 30일
- `CHL/CHK_TYPE`: `SELF` 직접인증, `MANUAL` 관리자 검토
- `CHL/CHK_FREQ`: `DAILY` 매일, `WEEKLY_3` 주3회, `TOTAL_10` 10회

비활성화된 `N05`, `ONE_DAY`, `ONE_WEEK`, `ONE_MONTH`, `PHOTO`, `EVERY`, `THREE_TIMES`는 포함하지 않는다.

### 배지

- 물마시기 배지: `media/badges/water-badge.png`
- 스트레칭 배지: `media/badges/stretching-badge.png`

기존 이미지 파일을 안정적인 파일명으로 복사해 프로젝트 정적 자산에 포함한다. `테스트 배지`는 포함하지 않는다. 관리자 FK는 특정 관리자 계정 존재 여부에 의존하지 않도록 `NULL`로 등록한다.

### 공식 챌린지

- 챌린지명: 스트레칭 챌린지
- 유형: `CHL/CHL_TYPE/T02`
- 문구: 하루 총 5분 스트레칭
- 설명: 하루 총 5분 스트레칭을 해주세요.
- 모집 기간: 2026-09-07 22:11:00 ~ 2026-09-30 22:11:00 (Asia/Seoul 기준 저장값)
- 기간: `CHL/CHL_PERIOD/D7`
- 인증 방식: `CHL/CHK_TYPE/SELF`
- 인증 빈도: `CHL/CHK_FREQ/DAILY`
- 지급 배지: 스트레칭 배지
- 전시 여부: 사용
- 삭제 여부: 미삭제

관리자 FK는 `NULL`로 등록한다. 삭제된 `매일 30분 걷기` 챌린지는 포함하지 않는다.

## 마이그레이션 방식

1. 신규 Aerich 데이터 마이그레이션을 생성한다.
2. 그룹은 `group_code`, 상세코드는 `(group_id, detail_code)`, 배지는 `name`, 챌린지는 `name`을 자연키로 사용한다.
3. 자연키가 없으면 추가하고, 있으면 운영 기준 필드를 갱신한다.
4. FK 숫자 ID는 SQL에 고정하지 않고 서브쿼리 또는 조인으로 조회한다.
5. 마이그레이션 전용 추적 테이블에 이번 마이그레이션이 새로 생성한 행만 기록한다.
6. downgrade는 FK 역순으로 신규 생성 행만 삭제한다. 기존 행에 적용된 기준 필드 갱신은 유지한다.
7. 데이터 추가 순서는 그룹 → 상세코드 → 배지 → 챌린지로 한다.

## 안전성과 검증

- 같은 자연키를 가진 행이 있어도 중복 생성하지 않는다.
- 챌린지 FK가 가리키는 공통코드 및 배지가 모두 존재한 뒤 챌린지를 등록한다.
- 마이그레이션 적용 후 대상 행 수와 FK 연결값을 Docker MySQL에서 조회한다.
- Python 포맷 및 정적 검사를 실행한다.
- 사용자 요청에 따라 자동화 테스트와 Git 커밋은 실행하지 않는다.
