# Knowledge Corpus Partial Recovery Design

## 목적

문서 유형별 대표 PDF에서 사람이 검증한 전처리 규칙을 같은 유형의 전체 PDF에 적용하고, 문서 전체가 아닌 청크 단위로 품질을 판정하여 검색에 사용할 수 있는 내용을 최대한 복원한다.

현재 문서 매니페스트에는 PDF 1,286개가 있으며, 1,267개는 텍스트 추출 가능하고 19개는 OCR이 필요하다. 기존 `full-v2` 릴리스에서는 776개 문서만 포함되고 478개가 제외되었다. 제외 사유 중 455개는 자동 품질 차단이므로 영구적인 원문 손상이 아니라 기존의 문서 단위 차단 정책에 의한 손실이다.

## 성공 기준

- `TEXT_EXTRACTABLE` PDF 1,267개를 모두 전처리 대상으로 평가한다.
- 대표 문서에서 승인한 유형별 정규화·청킹 규칙을 동일 출처·문서 유형에 적용한다.
- 일부 청크에 문제가 있어도 같은 문서의 정상 청크는 릴리스 후보로 유지한다.
- `PENDING`, `REPAIR_REQUIRED`, `EXCLUDED_NON_CONTENT` 청크는 임베딩하지 않는다.
- `APPROVED` 청크만 불변 릴리스와 Qdrant 인덱싱 입력으로 사용한다.
- OCR 필요 문서 19개는 누락시키지 않고 별도 대기 목록과 보고서에 남긴다.
- 복원 전후 문서 수, 청크 수, 제외 사유를 출처별로 비교할 수 있는 보고서를 생성한다.
- 기존 승인 릴리스의 청크를 회귀시키거나 중복해서 포함하지 않는다.

## 선택한 접근 방식

### 청크 단위 부분 승인

기존 방식은 문서에서 차단 사유가 하나라도 발견되면 해당 문서의 모든 `text`와 `chunks` 출력을 삭제한다. 이를 다음과 같이 변경한다.

1. 문서 단위 보고서는 전체 품질 상태와 집계 정보를 계속 제공한다.
2. 각 청크는 별도의 검수 상태와 사유 코드를 가진다.
3. 안전한 청크는 `APPROVED`로 릴리스한다.
4. 복원 가능성이 있지만 자동 확정할 수 없는 청크는 `PENDING` 또는 `REPAIR_REQUIRED`로 격리한다.
5. 참고문헌, 머리글, 저자 정보처럼 검색 가치가 없는 청크는 `EXCLUDED_NON_CONTENT`로 기록하고 제외한다.

품질 임계값을 낮추거나 실패 청크를 강제로 포함하지 않는다. 데이터 회수율은 높이되 검색 근거의 정확성은 유지한다.

## 문서 유형별 규칙 상속

대표 문서의 수동 검수 결과를 동일한 `source_id`와 `document_type`에 적용한다.

- 반복 머리글·꼬리글과 페이지 번호 제거
- 다단 본문의 열 순서 복원
- 회전 텍스트 격리 또는 검증된 방향 복원
- 표 셀 좌표를 이용한 행·열 복원
- 줄바꿈 하이픈과 검증된 공백 복원
- 제목·소제목 계층과 의미 경계 유지
- 참고문헌 및 검색 가치 없는 문서 메타블록 제외
- 문서 유형별 목표 토큰, 최대 토큰, overlap 적용

문서별로 검증된 텍스트 치환이나 특별 섹션 경계는 해당 문서에만 적용한다. 한 문서에서 확인한 고유 문장을 다른 문서에 전역 치환하지 않는다.

## 품질 판정

### 문서 단위 차단을 유지할 경우

다음 문제는 청크만으로 안전하게 분리할 수 없으면 문서를 릴리스하지 않는다.

- 원본 파일을 열거나 텍스트를 추출할 수 없음
- 출처 식별자나 원본 경로가 없음
- 전체 페이지의 읽기 순서를 신뢰할 수 없음
- 암호화·손상 등으로 본문 자체가 없음
- 문서 대부분이 OCR 없이는 해석 불가능함

### 청크 단위 격리 사유

- 최대 토큰 초과
- 표 구조 불일치 또는 행·열 복원 실패
- 해당 페이지의 읽기 순서 불확실
- 해결되지 않은 줄바꿈·문자 깨짐
- 제목만 있거나 문맥이 없는 짧은 조각
- 필수 성분명·함량·단위 손상
- 다른 섹션 내용의 혼입
- 검색 엔터티 또는 근거 수준을 자동 판정할 수 없음

## 출력 구조

각 실행은 다음 출력을 생성한다.

- `candidate/`: 자동 전처리된 전체 후보
- `release/`: `APPROVED` 청크만 포함한 임베딩 가능 출력
- `quarantine/`: `PENDING` 및 `REPAIR_REQUIRED` 청크
- `excluded/`: `EXCLUDED_NON_CONTENT` 청크의 위치와 제외 사유
- `reports/preprocessing-quality.json`: 문서·청크 품질 상세
- `reports/recovery-summary.json`: 복원 전후 집계
- `reports/recovery-summary.md`: 사람이 읽을 수 있는 출처별 복원 보고서
- `reports/ocr-required.jsonl`: OCR 대기 문서 19개

## 복원 보고서 지표

- 전체 카탈로그 문서 수
- 상태별 입력 문서 수
- 출처·문서 유형별 처리 문서 수
- 완전 승인 문서 수
- 부분 승인 문서 수
- 승인 청크 수
- 격리 청크 수와 사유별 건수
- 비콘텐츠 제외 청크 수
- 문서 단위 차단 수와 사유
- OCR 대기 문서 수
- 기존 릴리스 대비 복원 문서·청크 수
- 중복 document ID 및 chunk ID 수

## 릴리스 구성

새 릴리스는 기존 의약품·영양제 승인 데이터와 새로 복원한 데이터를 모두 포함한다.

1. 기존 승인 릴리스에서 정상 문서·청크를 읽는다.
2. 새 전체 전처리 결과와 `document_id`를 대조한다.
3. 같은 문서의 새 결과가 승인되면 새 결과를 우선하고, 아니면 기존 승인 결과를 유지한다.
4. 신규 문서의 승인 청크를 추가한다.
5. 중복 document ID와 chunk ID를 검사한다.
6. 불변 dataset version으로 출력한다.
7. 임베딩 전 품질 보고서와 최종 청크 수를 사람이 확인한다.

## 오류 및 안전 처리

- OCR 문서를 텍스트 추출 실패로 조용히 버리지 않는다.
- 격리된 청크는 Qdrant 인덱싱 로더가 읽지 못하도록 디렉터리를 분리한다.
- 문서 단위 보고서가 `BLOCKED`여도 승인 청크가 존재할 수 있지만, 보고서에는 `partial_release=true`를 명시한다.
- 승인 청크가 0개인 문서는 문서 단위 제외로 집계한다.
- 원본 파일은 수정하지 않는다.
- `DEMO_RESTRICTED` 접근 범위와 출처 메타데이터를 그대로 보존한다.

## 테스트 전략

### 단위 테스트

- 차단 사유가 있는 한 청크만 격리되고 정상 청크가 릴리스되는지 검증한다.
- 참고문헌 청크가 `EXCLUDED_NON_CONTENT`로 제외되는지 검증한다.
- 승인 청크가 0개인 문서가 제외 목록에 남는지 검증한다.
- OCR 문서가 OCR 대기 보고서에 남는지 검증한다.
- 승인되지 않은 청크가 릴리스 디렉터리에 기록되지 않는지 검증한다.

### 통합 테스트

- 대표 규칙을 상속한 동일 유형의 여러 문서를 처리한다.
- 기존 릴리스와 복원 릴리스를 중복 없이 조합한다.
- 품질 보고서의 문서·청크 수와 실제 파일이 일치하는지 검사한다.
- 인덱싱 로더가 승인 릴리스만 읽는지 검사한다.

### 전체 Dry-run

PDF 1,286개 전체를 대상으로 임베딩 없이 전처리한다. 결과 보고서에서 OCR 19개, 문서 단위 차단, 부분 승인, 청크 격리 수를 확인한 뒤 임베딩 여부를 결정한다.

## 범위 밖

- OCR 엔진 자체 구현
- 품질이 확인되지 않은 청크의 강제 승인
- OpenAI 임베딩 API 호출
- Qdrant 활성 컬렉션 전환
- 원본 PDF 삭제 또는 수정

이 항목들은 전체 Dry-run 결과와 수동 표본 검수 후 별도 승인으로 진행한다.
