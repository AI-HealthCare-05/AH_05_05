# 전체 약·영양제 Knowledge 검색 개선 설계

## 목표

현재 대표 문서 8개 기준선에 한정된 Qdrant 검색을 전체 적격 PDF로 확장하고, 의약품과 영양제 이름이 겹치는 질문도 한쪽으로 성급히 확정하지 않고 근거를 비교해 답변한다.

## 데이터 범위

- `PUBLIC`과 `DEMO_RESTRICTED` 중 `sources.yaml`에서 `target: QDRANT`인 출처를 포함한다.
- `QDRANT_DISABLED_UNTIL_VERIFIED`, `STRUCTURED_SOURCE`, `OCR_REQUIRED`는 포함하지 않는다.
- `DEMO_RESTRICTED`는 내부 데모 전용 표시를 유지하고 원문 다운로드 API를 제공하지 않는다.
- 기존 `medication_knowledge_baseline_v1`은 변경하지 않고 새 dataset version과 불변 collection을 생성한다.
- 전체 OpenAI 임베딩 전송은 전처리 품질 보고서에서 문서·청크·차단 건수를 확인한 뒤 수행한다.

## 전처리와 메타데이터

대표 문서에서 승인된 문서 유형별 Loader, Normalizer, Splitter를 전체 코퍼스에도 재사용한다. 파일 해시 기반 `document_id`로 중복을 제거하고, 텍스트 품질 실패 문서는 인덱싱하지 않는다.

각 청크에는 문서 전체의 모든 성분이 아니라 청크가 실제로 다루는 정규화된 성분과 약 이름만 저장한다. 공전형 문서는 원료 계층에서 성분명을 상속하고, 약물백과·부작용 사례는 파일명과 제목에서 약 이름을 추출한다. 청크의 원문과 메타데이터가 일치하지 않으면 자동 품질 검사에서 차단한다.

## 질문 판별과 라우팅

키워드 하나로 의약품 또는 영양제를 확정하지 않는다. 질문에서 제품 제형, 성분명, 질문 의도와 현재 복용 컨텍스트를 분석하고 의약품 RDBMS 조회와 Qdrant 검색을 모두 수행할 수 있다.

- 정확한 제품명 또는 제형이 확인되면 의약품 근거를 우선한다.
- 성분 기능·섭취 목적 질문이면 영양성분 근거를 우선한다.
- 부분 제품명 후보가 여러 개여도 Qdrant에 직접 성분 근거가 있으면 영양제 답변을 사용한다.
- 양쪽 근거가 부족하거나 제품 지정이 필요한 질문만 명확화 응답을 반환한다.

## 검색

질문 원문에서 성분·약 이름과 `FUNCTION`, `DAILY_INTAKE`, `CAUTION`, `INTERACTION` 의도를 결정론적으로 추출해 검색 문장을 확장한다. Qdrant에서 후보 20개를 가져온 뒤 다음 순서로 재정렬한다.

1. 최소 의미 유사도 기준을 통과한 후보만 유지한다.
2. 질문 엔티티와 `ingredient_names` 또는 `drug_names`가 정확히 일치하면 가산한다.
3. 질문 의도와 `section_type`이 일치하면 가산한다.
4. 동일 문서·동일 내용 중복을 제거한다.
5. 최종 상위 5개만 답변 생성기에 전달한다.

전역 유사도 기준 `0.65`는 낮추지 않는다. 메타데이터 가산점은 순위에만 사용하고, 낮은 의미 유사도를 안전 근거로 승격하지 않는다.

## 실패와 안전성

- Qdrant 장애 시 RDBMS의 사용자 확정 복약정보와 승인된 규칙만 제공한다.
- 검색 결과가 없으면 LLM이 의학 지식을 임의 생성하지 않는다.
- 임부금기 등 구조화 DUR 자료는 MySQL 조회 결과를 우선하고 Qdrant는 설명 보충에만 사용한다.
- 출처 불명 자료는 검색 대상에서 제외한다.

## 검증

- `마그네슘은 왜 먹어?`가 의약품 중복 후보에서 즉시 종료되지 않는지 검증한다.
- `마그밀정 500mg`은 의약품 제품 안내로 유지되는지 검증한다.
- 성분명과 섹션 일치 후보가 의미 유사도 동점 후보보다 앞서는지 검증한다.
- 전체 전처리는 기존 대표 문서의 결정론적 해시와 품질 기준을 훼손하지 않아야 한다.
- 새 컬렉션은 기존 10개 기준 질문과 약·영양제·특수대상 질문을 함께 평가한 뒤 전환한다.
