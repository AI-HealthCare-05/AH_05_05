# RxVita 관리자 화면 브랜드 색상 테마 설계

## 배경

RxVita 관리자 화면은 로그인, 대시보드, 회원 관리, 관리자 관리, 작업 모니터링, 영양제 랭킹과 여러 오버레이로 구성된다. 현재 레이아웃과 중립색 체계는 일관적이지만 상호작용 강조색으로 기존 파란색(`#1c64f2`, `#1554d1`)이 여러 CSS와 템플릿 인라인 스타일에 흩어져 있다.

이번 변경은 화면 구조를 재설계하지 않고, RxVita 로고의 청록·딥 네이비 분위기에 맞춰 기존 파란색 계열만 브랜드 청록색으로 교체한다. 성공, 경고, 오류, 위험 상태의 의미 색상은 유지한다.

## 목표

- 모든 관리자 웹페이지에서 동일한 RxVita 청록 강조색을 사용한다.
- 브랜드 색상을 CSS 사용자 정의 속성으로 중앙 관리한다.
- 버튼, 링크, 선택 상태, 입력 포커스, 페이지네이션, 테이블 hover와 주요 지표의 파란색을 청록색으로 변경한다.
- 기존 레이아웃, 타이포그래피, 간격, 기능과 상태 의미를 보존한다.
- CSS 캐시 버전을 통일해 변경된 테마가 즉시 반영되게 한다.

## 비목표

- 페이지 레이아웃이나 컴포넌트 크기 변경
- 다크 모드 도입
- 성공·경고·오류·위험 상태 색상 재설계
- 이메일 템플릿 색상 변경
- 사용자용 프론트엔드 화면 변경

## 색상 토큰

공통 `:root`에 다음 토큰을 정의한다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--brand-primary` | `#18bfb3` | 강조선, 아이콘 배경, 선택 표시 |
| `--brand-primary-hover` | `#0e9384` | 테두리와 비채움 강조 요소의 hover |
| `--brand-primary-strong` | `#0b7f75` | 흰 배경의 링크와 흰 글자를 쓰는 기본 버튼 |
| `--brand-primary-strong-hover` | `#096c64` | 기본 버튼과 링크의 hover |
| `--brand-primary-soft` | `#e8f9f7` | 활성 메뉴와 선택 배경 |
| `--brand-primary-faint` | `rgba(24, 191, 179, 0.06)` | 기간 선택과 미세 강조 배경 |
| `--brand-focus` | `rgba(24, 191, 179, 0.18)` | 입력 및 버튼 포커스 링 |
| `--brand-hover-row` | `rgba(24, 191, 179, 0.04)` | 테이블 행 hover |
| `--brand-navy` | `#06356f` | 브랜드 제목과 로고 연계 요소에 한정 |

중립색(`#111827`, 회색 배경, 흰 카드)과 의미 색상(초록, 주황, 빨강)은 기존 값을 유지한다.

## 적용 구조

### 공통 스타일

`app/static/css/styles.css`가 색상 토큰의 단일 정의 지점이 된다. 모든 관리자 페이지가 이 파일을 먼저 불러오므로 `management.css`와 `overlays.css`에서도 동일 토큰을 사용할 수 있다.

`styles.css`에서는 로그인 입력 포커스, 비밀번호 도움말, 로그인 버튼, 대시보드 기간 선택, 차트와 지표 강조색을 토큰으로 교체한다.

`management.css`에서는 공통 입력 포커스, 기본 버튼, 링크 버튼, 활성 페이지 번호, 활성 사이드바, 테이블 hover, 영양제 검색 결과 hover를 토큰으로 교체한다.

`overlays.css`는 공통 입력과 버튼 클래스를 사용하므로 별도의 색상 재정의 없이 변경된 토큰을 상속한다. 오류 문구와 위험 구역은 기존 빨간색을 유지한다.

### 템플릿 예외

CSS 밖에 남아 있는 파란색 인라인 스타일은 다음과 같이 교체한다.

- `partials/sidebar.html`: 브랜드 아이콘 배경을 `var(--brand-primary)`로 변경한다.
- `dashboard.html`: OCR 정확도 원형 테두리와 수치 색상을 `var(--brand-primary)` 또는 대비가 필요한 경우 `var(--brand-primary-strong)`으로 변경한다.

로그인 페이지에 이미 적용된 RxVita 로고, `AI HEALTH ASSISTANT` 문구와 청록 로그인 버튼은 새 토큰을 사용하도록 정리한다.

### 캐시 갱신

관리 페이지별로 달라진 `styles.css`, `management.css`, `overlays.css` 쿼리 버전을 같은 새 버전으로 통일한다. 로그인 페이지도 동일 버전을 사용해 캐시 동작을 일관되게 만든다.

## 접근성 및 상호작용

- 흰 글자를 사용하는 버튼에는 `--brand-primary-strong`을 적용한다. `#0b7f75`와 흰색의 명암비는 4.88:1로 일반 텍스트 WCAG AA 기준을 충족한다.
- 밝은 `--brand-primary` 위에는 흰 글자를 올리지 않는다. 밝은 청록 배경이 필요한 경우 딥 네이비 글자를 사용한다.
- 키보드 포커스는 색상만으로 구분하지 않도록 기존 outline 두께와 offset을 유지한다.
- 활성 사이드바는 연한 청록 배경, 청록 테두리, 진한 청록 텍스트와 굵은 글꼴을 함께 사용한다.
- 위험·오류 동작은 계속 빨간색을 사용해 일반 기본 동작과 구분한다.
- 비활성 버튼은 회색과 낮은 불투명도를 유지한다.

## 테스트

정적 UI 테스트에 다음 계약을 추가한다.

- 공통 브랜드 토큰이 선언되어 있다.
- 기존 기본 파란색(`#1c64f2`, `#1554d1`, `#1d4ed8`, 파란색 rgba 포커스)이 관리자 CSS에서 제거된다.
- 사이드바와 대시보드의 인라인 강조색이 브랜드 토큰을 사용한다.
- 모든 관리자 페이지가 같은 CSS 캐시 버전을 불러온다.
- 의미 상태 클래스의 성공·경고·오류·위험 색상은 유지된다.

테스트는 먼저 기존 파란색이 남아 있어 실패하는 상태를 확인하고, 최소 변경으로 통과시킨다. 이후 전체 `app/tests/static_ui/*.test.mjs`를 실행한다. 전체 테스트에 이번 변경과 무관한 기존 실패가 있으면 로그인·사이드바·대시보드·관리 화면 관련 대상 테스트 결과와 구분해 보고한다.

## 위험과 대응

- **Tailwind 유틸리티 우선순위 충돌:** 브랜드 색상은 프로젝트 CSS 클래스와 토큰으로 적용하고, 색상 인라인 스타일은 제거하거나 토큰 참조로 교체한다.
- **캐시로 인한 구버전 노출:** 모든 관리자 페이지의 CSS 버전을 통일해 갱신한다.
- **의미 색상 손실:** 치환 대상은 파란색 계열로 제한하고 상태 색상 유지 테스트를 둔다.
- **대비 저하:** 청록 배경 위 흰 글자와 연한 청록 배경 위 진한 청록 글자를 각각 사용한다.
- **범위 외 변경:** HTML 구조와 JavaScript 동작은 수정하지 않는다.

## 완료 기준

- 로그인과 모든 관리자 페이지에서 기존 파란색 상호작용 요소가 청록색으로 표시된다.
- 페이지 레이아웃과 기능이 변경되지 않는다.
- 성공·경고·오류·위험 상태 색상이 유지된다.
- 새 테마 계약 테스트와 관련 정적 UI 테스트가 통과한다.
