# 질문 분류 3단계 기준선 기록

> 상태: 구현 완료 후 측정 대기
> 대상 브랜치: feature/383
> 활성화 전제: SEMANTIC_ROUTER_ENABLED=false 유지

## 목적

규칙 기반 기준선과 아래 두 선택 경로를 비교한다.

1. 로컬 Semantic Router
2. 후보 키 기반 구조화 LLM fallback

제품·성분·상호작용 쌍은 모든 조건에서 RDBMS·Qdrant 카탈로그와 기존 결정론적 Query Plan으로 확정한다.

## 측정 방법

각 질문을 같은 평가 계정과 같은 Qdrant 컬렉션에서 3회 실행한다. 각 실행에서 LangSmith의 다음 값을 기록한다.

- 최종 route와 safety status
- 정규화된 제품·성분 수
- 잘못된 대상 혼입 여부
- query.plan.semantic_router의 stage, top score, second score, elapsed ms
- query.plan.conditional의 호출 여부 및 candidate key 검증 결과
- 전체 응답 시간
- 근거 출처의 종류와 수

## 활성화 결정

측정 전에는 SEMANTIC_ROUTER_ENABLED=false를 유지한다. 기준을 통과한 뒤에도 먼저 개발 환경에서만 활성화하고, 배포 환경 활성화는 AWS 성능·안전성 재검증 후 결정한다.
