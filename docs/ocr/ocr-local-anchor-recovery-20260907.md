# OCR 선행 기호·로컬 앵커 복구 검증

작업 위치: `906/AH_05_05` 로컬 복사본. 기존 미커밋 변경을 보존했으며 커밋·push·별도 Git 폴더 반영은 하지 않았다.

## 요청과 적용 범위

- 약명 맨 앞의 특수기호·공백을 공통 정규화에서 무시한다. 원본 OCR 텍스트, 좌표, 블록 ID는 수정하지 않는다. 숫자·문자와 약명 내부 구두점은 유지한다.
- 잘린 `리토아틴정10밀`을 추정해 완성하지 않는다.
- 병원명은 전역 줄 묶음뿐 아니라 발행기관 등 명시적 라벨 주변의 원본 좌표로 찾는다. 병원명 자체의 근거 블록과 신뢰도를 반환한다.
- 기존 표 추출 경로가 모두 실패한 경우에만, 원본 좌표의 2단 복용정보 헤더와 인접한 약품 한 행을 복구한다. `1회/투약량`, `일투여/횟수`, `총투약/일수`의 명시적 헤더와 완전한 약명, 유일한 숫자 3개가 필요하다.
- 없는 헤더, 먼 헤더, 중복 약명·숫자, 두 번째 숫자 행, 금액 항목, 잘린 약명은 복구하지 않는다. 잘못된 숫자 `0`, `-1`, `1O`처럼 숫자를 포함한 근거도 중복 후보 검사에서 무시하지 않는다.

## 변경 파일

- `app/services/medication_ocr_v3/pipeline/ocr_layout.py`: 약명 매칭 및 제한적 2단 헤더 복구.
- `app/services/medication_ocr_v3/pipeline/hospital_name.py`: 라벨 기준 원본 좌표 추출, bbox 정렬의 타입 좁히기.
- `tests/ocr_v3/test_internal_pipeline.py`, `tests/ocr_v3/test_hospital_name.py`: 개인정보 없는 원본 좌표 기반 회귀·음성 테스트.
- 계획: `docs/superpowers/plans/2026-09-07-ocr-local-anchor-recovery.md`.

기본 worker와 같은 legacy 설정에서는 두 이미지 모두 결정적 검증으로 확정되어 LLM 호출을 생략했다. 별도로 `medication_semantic_review_v1` 및 구성된 `gpt-4o-mini`를 사용한 실제 LLM 경로에서도 같은 결과를 확인했으며 preprocess·ocr·candidate·llm·validate 단계가 모두 성공했다. worker 기본 모드나 모델 설정은 변경하지 않았다.

## 검증 기록

- 선행 기호, 병원명, 로컬 표 복구의 회귀 테스트 실패를 수정 전에 확인했다.
- 로컬 표 복구 19개 테스트 통과. 중복된 `0`, `-1`, `1O`를 무시하던 경우도 실패 재현 후 수정했다.
- 최종 `pytest tests/ocr_v3 -q --tb=short`: **344 passed in 14.00s**.
- 최종 안전 검사 보완 후 실제 영수증의 semantic API 경로도 다시 실행해 동일한 약품·복용정보 및 모든 단계 성공을 확인했다.
- `ruff check app tests` 통과. 수정한 생산 코드 4개는 `mypy --follow-imports=silent` 통과.
- 범위를 넓힌 기본 mypy 검사에는 변경하지 않은 전처리·semantic 등 파일의 기존 타입 오류가 남아 있다. 저장소 루트 전체 Ruff 검사에는 `.context`의 과거 기준본·진단 스크립트가 포함되어 오류가 나므로, 실제 코드·테스트 범위와 구분한다. 이 자료나 검사 기준은 변경하지 않았다.

## 검토 범위와 제한

- 변경 전 로컬 스냅샷 대비 재사용·코드 품질·효율 관점의 독립 검토를 수행했다. 재사용·품질 수정 사항은 없었다. 라벨별 전체 블록 검색을 공간 인덱스로 바꾸자는 효율 제안은 측정 근거가 없고 새 구조를 요구하므로 이번 범위에서 채택하지 않았다. 안전 검사 삭제나 전역 임계값 완화는 하지 않았다.
- Code review: skipped (ce-code-review unavailable) — 해당 워크플로의 Git 참조 기반 검토 범위로는 작업 전 미커밋 스냅샷과 기존 untracked 병원 파일을 정확히 표현할 수 없어 Stage 1에서 종료했다. 무관한 기존 변경을 포함하거나 임의 커밋을 만들지 않고, 실제 변경 전 스냅샷 대비 별도의 독립 읽기 전용 정확성 검증을 수행했다. CE 완료 영수증으로 표현하지 않는다.
- 독립 정확성 검토에서 숫자처럼 보이는 경쟁 근거를 누락하는 P2 1건을 재현·수정했다. 수정 후 재검토 판정은 **범위 내 차단 이슈 없음**이다. 검토자는 영향 테스트 85개를 독립 실행했고, 0.1배·1배·10배 확대 및 평행이동에서 값·원본 ID 보존, `0/-1/1O/90원` 경쟁 근거 거부를 확인했다. 실제 이미지/API 검증은 구현 담당자가 직접 실행했다.
- 이 복구는 완전한 약명이 원본에 별도로 있고 로컬 근거가 유일한 경우에 한정된다. 잘린 글자 복원, 전체 문서의 보편적 재분할, 모든 영수증 양식 지원을 의미하지 않는다.

배포·커밋·push는 범위 밖이다. 추후 반영 시 위 두 이미지의 병원명·행 소유권·복용정보와 모호한 표의 거부 여부를 동일 테스트로 재확인한다.
