# OCR 중복 계산 점검 및 최적화 (2026-09-18)

## 범위와 기준

기존 미커밋 수정이 포함된 현재 실행 코드를 기준으로 한다. 브랜치 변경·커밋·push 없이 계산 재사용만 적용한다. 품질 임계값, 약명 후보 채택 조건, LLM 근거 검증, 출력 스키마는 변경하지 않는다.

## 확인한 흐름

`업로드 형식 검증 → 전처리·이미지 품질 판정 → OCR → 표·약품 후보 → 결정적 근거 계획 → 필요한 경우 LLM → 최종 근거 검증 → 리뷰`

| 구간 | 판단 | 처리 |
| --- | --- | --- |
| 업로드/디코더 검증 | 서로 다른 경계의 형식·크기 안전 검사 | 유지 |
| 원근 보정 전후 품질 검사 | 원본 영역과 변환 이미지가 다름 | 유지 |
| 문서 사각형 후보 비교 | 동일 후보의 좌표 배열·면적을 비교할 때마다 재계산 | 요청 내부에서 재사용 |
| 결정적 날짜·함량 계획 | resolve와 canonicalization이 같은 입력으로 재계산 | 기존 계획 전달 |
| LLM 원본 선택/최종 선택 검증 | 검사 대상이 다르므로 중복 아님 | 유지 |
| 실패 후 대체 전처리 OCR | 다른 처리 이미지로 제한된 1회 복구 | 유지 |
| semantic evidence 준비 | 일부 공통 계산 반복 존재 | 비기본 경로이며 인터페이스 변경이 커 이번에는 보류 |

## 검증 방식

- 외부 OCR/LLM 호출 없이 동일 입력의 순수 전처리 시간을 측정한다.
- 사용자 생성 샘플 3장과 촬영본 2장, 장당 워밍업 1회 + 실측 3회, OpenCV RNG seed 0.
- 전체 `PreprocessResult` 해시를 비교한다. 여기에는 제공용 JPEG, 미리보기 JPEG, 변환 좌표, 품질 지표, 판정과 사유가 포함된다.
- 반복 횟수 절감과 그룹 순서·출력 동등성을 회귀 테스트로 확인한다.
- 근거 계획 재사용은 LLM 오류·모호성·행 소유 검증을 생략하지 않는다.

측정 도구: `scripts/benchmark_ocr_duplicate_work.py`.
로컬 증빙: `810final/output/ocr-duplicate-work-20260918/`의 spec, baseline 및 experiment log.

## 결과

| 입력 | 변경 전 중앙값 | 변경 후 중앙값 |
| --- | ---: | ---: |
| 생성 샘플 1 | 1,326.51ms | 1,022.31ms |
| 생성 샘플 2 | 1,264.07ms | 1,092.67ms |
| 생성 샘플 5 | 1,246.14ms | 1,137.83ms |
| 촬영본 A | 1,665.56ms | 1,655.00ms |
| 촬영본 B | 987.97ms | 1,029.77ms |
| 5장 중앙값 평균 | 1,298.05ms | 1,187.52ms |

표본 평균 전처리 시간은 110.54ms(8.5%) 줄었다. 모든 입력의 전체 결과 해시가 변경 전후 동일하며 반복 측정 안에서도 같았다. 표가 많은 생성 이미지에서 이득이 컸다. 촬영본은 차이가 작고 B는 오히려 느리므로 모든 이미지에 동일한 개선율을 보장하지 않는다. 네트워크·큐 대기·OCR·LLM 시간은 포함하지 않는다. 이번에는 외부 API를 다시 호출하지 않았다.

후처리는 legacy·semantic 모두 한 요청에서 결정적 계획 생성이 2회에서 1회로 감소했다. 서로 다른 catalog/rows 객체 또는 계산 날짜의 계획은 재사용하지 않고 다시 계산한다. 원본 LLM 선택과 최종 채택값의 검증은 둘 다 유지한다. 계획 생성 절감과 위 전처리 개선율을 합산하지 않는다.

검증:

- `tests/ocr_v3`: 529 passed, 1 skipped (14.43초). 기존 OCR-16 로컬 증빙 묶음이 없어 해당 테스트 1개는 건너뜀.
- 변경 Python 파일 Ruff check/format, `git diff --check` 통과.
- analyze/deterministic grounding Mypy `--follow-imports=silent` 통과.
- 기존 그룹화와 난수·퇴화 도형·실제 다중 그룹 병합 순서 동등성 검증.
- 모호한 날짜·함량 및 잘못된 LLM block ID의 fresh/reused 결과 동등성 검증.
- 독립 검토: 다른 요청의 계획 재사용 방지 조건 보완 후 차단 사항 없음.
- 로컬 OCR 대기열/진행 키가 비어 있음을 확인한 뒤 fastapi 통합 런타임 재시작, healthcheck 통과.

계산 결과는 함수/요청 내부에서만 재사용한다. 전역 이미지·OCR 캐시는 추가하지 않았다. 측정 결과에는 문서 원문이나 환자 정보를 기록하지 않고 해시와 시간만 남긴다. 기존 사용자 수정은 유지했으며 커밋·push는 하지 않았다.
