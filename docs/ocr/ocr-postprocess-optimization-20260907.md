## 구현

운영 코드 변경은 `app/services/medication_ocr_v3/pipeline/ocr_layout.py` 하나다.

1. 고정 헤더 별칭의 정규화를 반복하지 않고 모듈 초기화 시 한 번 계산한다. 환자 OCR 문자열을 전역 캐시에 저장하지 않는다.
2. 라인 그룹의 정확한 중앙값을 그룹 구성 변경 시에만 갱신한다. 기존 그룹화 판정과 원본 좌표는 유지한다.
3. 기존 표 후보가 모두 없을 때만 `약품명`과 반복되는 `1회투약량 / 1일투여횟수 / 총투약일수`를 근거로 보수적 복구를 시도한다. OCR 사각형 기울기를 행 대응에만 사용하며 원본 evidence/UI 좌표는 바꾸지 않는다.
4. 복구는 정확한 라벨 및 원문 숫자가 있는 최소 2행에 한정한다. 서로 먼 패널·헤더, 중복 약품명, 과도하거나 불일치하는 기울기, 복수 이름/숫자 후보, 중복 증거 블록은 거절한다. 잘못 읽힌 투약일수 라벨은 추측하지 않는다.

변경된 실제 문서는 `sample-04` 한 장이며 6행 중 5행을 새로 복구했다. 복구 근거가 부족한 1행과 다른 기존 미인식 사례는 남아 있다. 나머지 15장의 공개 review 해시는 동일하다. 출력 스키마·복용 단위 정책·전처리·공급자·LLM 경로는 바꾸지 않았다.

## 정답 오기 처리와 실험 이력

초기 고정 정답의 `sample-04` 세 번째 약품명이 `페나리민정`으로 기재되어 있었다. 원문 픽셀을 확인한 주 담당자와 **예측·정답을 보지 않은 별도 판독자** 모두 `페니라민정`을 읽었다.

원래 `../ocr-16-three-versions-20260907/ground-truth.json`은 수정하지 않았다. 초기 실험의 FP 증가 보호 조건 실패도 그대로 남겼다. 이 사실을 발견한 뒤 원래 4회 실험을 종료하고, 원본 정답 해시·이미지 해시·이전 값 검증이 있는 `postprocess-adjudications-20260907-v1.json`을 별도 등록했다. 이후 양쪽 구현용 OCR 응답을 새로 받은 단 한 번의 대응 비교로 최종 확인했다. 원래 채점과 보정 채점을 같은 결과 파일에 함께 기록했다.
