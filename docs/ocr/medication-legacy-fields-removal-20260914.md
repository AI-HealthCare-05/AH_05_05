# 등록 약품의 구형 필드 제거 — migration 46

## 범위

- `medications.efficacy`, `administration`, `precautions`, `note`만 제거한다.
- `medication_product_guides`의 효능·주의·복용법 자료는 유지한다.
- 사용자 복약 메모인 `medication_notes.body`와 영양제 메모는 유지한다.
- 모델과 DB 입력 제공자에서 삭제 필드 참조를 제거한다. 공용 AI 스키마의 선택 필드는 오프라인 입력 호환성을 위해 유지하며 DB에서는 값을 채우지 않는다.
- 복약 시간 API의 `timing`은 호환성을 위해 빈 문자열로 유지한다. 등록한 `slots`와 하루 횟수는 그대로 전달한다.

## 적용 전

이 문서와 마이그레이션 파일 생성은 DB 적용을 의미하지 않는다.

1. 대상 DB와 migration 45까지의 적용 이력을 확인한다. 기존 브랜치 병합 이력이 있으므로 다른 환경에서 곧바로 upgrade를 실행하지 않는다.
2. API·AI·OCR 작업자 등 DB 접근 프로세스를 정지하고 진행 중 쓰기가 끝났는지 확인한다.
3. 네 컬럼이 모두 존재하는지 확인한다. 사용자 요청에 따라 백업을 생성하지 않으며 기존 값은 영구 삭제된다.
4. 같은 MySQL 버전의 격리된 테스트 DB에서 먼저 검증한다. SQLite 회귀 테스트는 MySQL DDL 검증을 대체하지 않는다.

## 적용

프로젝트의 기존 Aerich 배포 절차로 migration 46을 적용한다. 백업 테이블이나 데이터 복사 없이 원본 테이블에서 네 컬럼을 제거한다.

적용 후 네 컬럼의 부재와 약 행 수·ID·복용량·일수의 보존을 확인한다. 수정된 코드로 프로세스를 시작하고 OCR 등록, 복약 시간 조회, AI 보고서·채팅을 점검한다. 구버전 프로세스를 그대로 실행하면 삭제 컬럼 조회 오류가 발생한다.

## 실패·복구

- MySQL DDL은 여러 문장 전체가 롤백되지 않는다. 부분 실패 시 자동 재실행하지 않는다.
- 자동 downgrade는 차단한다. 컬럼을 다시 생성해도 삭제된 값은 복원되지 않는다.
- 이 마이그레이션은 백업을 생성하거나 기존 백업을 삭제하지 않는다.

## ERD 수정

`Table medications` 안의 네 컬럼 행을 삭제하고, 해당 필드를 저장하거나 유지한다고 설명하는 Note 문장을 정리하면 된다. 네 컬럼에는 별도 FK·인덱스·CHECK가 없으므로 관계선 변경은 없다. 약품 안내 자료 테이블의 같은 이름 필드와 `medication_notes`는 삭제하지 않는다.

과거 마이그레이션 파일과 과거 버전 ERD는 이력으로 유지한다.
