# 현재 LLM 시간·정확도 기준선 — 2026-09-07

## 결론

현재 운영 설정은 `gpt-4o-mini`, `temperature=0`, 출력 상한 4096토큰, 전처리 `v3.4.1`이다. 실행 중인 로컬 worker와 호스트 설정이 일치함을 읽기 전용으로 확인했다.

**이번 개발 표본에서는 현재 조건부 LLM 호출이 약품 5필드 정확도를 높이지 않았다.** 동일 OCR 응답의 LLM 사용·미사용 양쪽 모두 공통 보정 정답 기준 **273/309 = 88.35%**다. 원래 정답표 기준으로도 양쪽 모두 **272/309 = 88.03%**다. LLM 호출당 평균은 두 실행 합산 **1.825초**, 서비스 전체 평균은 **2.792초**다.

LLM이 호출된 2개 이미지는 같은 문서를 서로 다른 각도로 촬영한 sample-08·11이다. 사실상 한 문서의 함량 모호성만 시험했으므로, 이 결과는 LLM의 일반적 유용성이나 검증 확대의 효과를 판정할 근거가 아니다. 모델 변경·LLM 비활성화·검증 범위 확대는 하지 않았다.

## 측정 설계

- 기존 고정 16개 이미지 및 원본 SHA-256, 기존 309개 판독 가능 필드를 유지했다.
- 이름·함량·1회 투약량·1일 횟수·일수의 5필드를 기존 행 대응 채점기로 평가했다. 분모는 각각 60/30/73/73/73이다.
- 각 이미지의 실제 서비스 분석을 1회 실행해 전처리·General OCR·후처리·조건부 LLM을 측정했다.
- 해당 OCR 응답을 메모리에 유지하고, 같은 응답으로 LLM 미사용 대조군 3회 및 LLM 사용 총 3회(최초 서비스 실행 포함)를 실행했다. LLM이 필요 없는 문서를 강제로 호출하지 않았다.
- 같은 구성으로 독립 실호출 실행을 두 번 수행했다. 총 서비스 입력 32회, General OCR 28회, 실제 LLM 12회다. 두 실행 모두 2개 이미지는 품질 게이트에서 재촬영으로 분류됐다.
- 두 실행의 활성 이미지 14개 OCR 응답 해시와 16개 이미지별 점수가 모두 같았다. 전처리·네트워크 응답 시간은 달랐다.
- 서비스 전체 시간은 `MedicationOcrV3Service.analyze()` 시작→반환이다. 업로드 전송, 큐 대기, DB 저장, 프런트 렌더링은 제외한다.
- 원본 이미지, 전체 OCR, 모델 응답 텍스트 및 환자 필드는 새 결과 파일에 저장하지 않았다. 입력 식별자·해시·점수·단계 시간만 저장한다.

로컬 후처리는 활성 이미지별 3회 중앙값들의 평균이며 전처리·OCR 네트워크·LLM을 제외한다. 두 번의 최초 서비스 실행에서 LLM이 호출된 4건의 전체 처리 평균은 6.357초다. LLM을 사용하지 않은 대조군의 서비스 전체 시간을 별도로 실측한 것은 아니므로, 로컬 후처리 20.42ms를 전체 처리 시간으로 오인하면 안 된다.

합산 서비스 32입력 기준 단계 평균은 전처리 815.59ms, General OCR 1708.53ms, 후보 처리 18.13ms, LLM 248.75ms, 검증 0.13ms다. General OCR을 실제 호출한 28건만의 OCR 단계 평균은 1952.61ms다. 단계 밖 처리 및 정수 ms 반올림 때문에 단계 합과 서비스 wall time은 완전히 같지 않다. 호출 수가 작아 p95를 안정적인 운영 지표로 제시하지 않는다.

## 이전 작업과 비교

정확도는 **같은 보정 정답표·행 대응 채점기**로 비교했다. 전처리 3버전 및 adaptive의 저장 결과를 재채점하여 값이 유지됨을 확인했다. 후처리 실험은 이미 저장된 보정 기준 대응 점수를 사용했다. 원래 정답표는 수정하지 않았다.

| 작업 상태 | 서비스 전체 평균 | 로컬 후처리 | 5필드 정확도 | FP / FN | LLM 조건 |
| --- | ---: | ---: | ---: | ---: | --- |
| 기본 v3.1.3 | 2.522초 | 별도 미측정 | 239/309, 77.35% | 9 / 70 | 호출 없음 |
| 색상·선명도 v3.2.7 | 2.440초 | 별도 미측정 | 238/309, 77.02% | 8 / 71 | 호출 없음 |
| 문자 기울기 v3.3.1 | 2.521초 | 별도 미측정 | 238/309, 77.02% | 10 / 71 | 호출 없음 |
| 적응형 전처리 v3.4.1 | 2.496초 | 별도 미측정 | 250/309, 80.91% | 11 / 59 | 호출 없음 |
| 후처리 최적화 직전 | 미측정 | 55.54ms | 250/309, 80.91% | 11 / 59 | 실제 호출 미측정 |
| 후처리 최적화 완료 | 미측정 | 18.73ms | 270/309, 87.38% | 11 / 39 | 실제 호출 미측정 |
| 현재, 같은 OCR의 LLM 미사용 | 전체 미측정 | 20.42ms | **273/309, 88.35%** | **8 / 36** | 대조군 |
| 현재, 조건부 LLM 사용 | **2.792초** | LLM 제외 대조군은 위 행 | **273/309, 88.35%** | **8 / 36** | 2/16이미지, 반복 포함 12회 |

과거 실험과 이번 실험은 외부 OCR 요청 시점 및 소스 버전이 다르다. 따라서 2.496→2.792초를 그대로 특정 변경의 시간 증가로 단정하지 않는다. 확실한 LLM 효과 비교는 이번 실험 내부의 같은 OCR 사용·미사용 대응 비교다. 후처리 55.54→18.73ms 역시 전체 서비스가 아니라 동일 응답 로컬 재생의 속도 개선이다.

기본 대비 현재 정답 필드는 +34, 직전 후처리 완료 대비 +3이다. 이 누적 증가분을 LLM 기여로 해석하면 안 된다. 이번 대응 비교에서 LLM의 5필드 정답 증가와 FP 감소는 모두 0이다.

## 정확도 해석의 경계

- 88.35%는 **파이프라인의 필드 일치율**이다. LLM 단독 정답률, 문서 전체 성공률, 임상적 정확성 보장이 아니다.
- 표본은 최적화에 사용한 개발 자료다. 16개 파일이 16개 독립 문서를 의미하지 않는다.
- 이번 실제 LLM 입력에는 날짜 후보가 없고 각 입력에 함량 후보 행이 하나씩 있었다. 조제일 선택 능력은 평가하지 않았다. 조제일 해시는 LLM 사용·미사용에서 변하지 않았다.
- 1차와 최종 확인 모두 LLM 3회 반복 점수가 동일하고 API 오류는 0건이다. 반복 호출이 독립 문서 수를 늘리는 것은 아니다.
- sample-08의 공개 review는 대조군과 해시가 같고, sample-11은 달랐다. 후자는 평가 대상 5필드의 점수와 날짜가 같으므로 전체 응답이 동일했다고 주장하지 않는다.
- 함량 표시 중복 제거는 프런트 표시 변경이다. 이 평가는 표시 문자열이 아닌 기존 백엔드 5필드 값으로 채점하므로, 화면 정리를 백엔드 추출 정확도 개선으로 집계하지 않는다.

## 검증·재현·변경 범위

독립 측정 검토가 재개 시 실제 원본 파일 해시 검증 누락을 발견했다. 시작·종료 시 전체 원본 검증을 추가하고 변조 회귀 테스트를 확인한 뒤, 1차 결과를 보존한 별도 출력 경로에서 최종 실호출을 수행했다. 재검토에서 Major가 해결됐고 새 blocker는 없었다.

- 현재 측정 도구: `scripts/benchmark_ocr_llm_baseline.py`.
- 회귀 테스트: `tests/ocr_v3/test_llm_baseline_benchmark.py`.
- 1차 결과: `.context/ocr-llm-baseline-20260907/`.
- 최종 확인 결과: `.context/ocr-llm-baseline-20260907-validated/`의 `manifest.json`, `sample-01.json`~`sample-16.json`, `summary.json`.
- 각 결과의 checksum, 실행 identity, 원본·소스·채점기·정답 해시를 기록하고 검증한다.
- OCR/LLM 공급자 호출 시 즉시 실패하도록 바꾼 진단 실행에서 `--resume-only`가 성공했다. 완료 체크포인트만으로 재개하며 외부 재호출하지 않았다.
- 관련 측정·채점·공급자 테스트, Ruff 검사·포맷 검사, diff 공백 검증을 실행했다.

완료 결과 재검증은 `python -m scripts.benchmark_ocr_llm_baseline --resume-only`다. 새 실측은 `--output`에 새 실험 디렉터리를 지정한다. 코드·원본·설정이 달라지면 기존 결과 재사용을 거부한다.

기존 미커밋 변경을 보존했다. 이번 기준선 측정은 운영 앱·LLM 프롬프트·모델 설정·DB·worker를 변경하지 않았고 커밋·push하지 않았다. 다음 변경은 이 기준선과 같은 입력·채점 조건의 대응 비교, 그리고 별도 신규 문서 검증으로 시간 증가·정답 증가·오수정 증가를 함께 평가해야 한다.
