# OCR v3.2 색상·선명도 전처리 실험

## 결론

3장·2개 후보·3회, LLM 연결 후속 검증을 합친 최종 결론은 **v3.2.1 대조군 유지**다. `v3.2.7`(채도 15% 증가 + 약한 선명화)은 기울어진 실사진의 low confidence를 4개에서 3개로 줄였지만, 접힌 저해상도 사진에서 `아목클정375mg`을 `아목물정375mg`으로 오인했다. 전체 필드 정확도도 90.36%에서 89.16%로 1.20%p 하락했으므로, 신뢰도 등급 1개 개선만으로는 채택 근거가 부족하다.

초기 `test.jpg` 1장 검증에서는 v3.2.7이 약품 7개와 모든 추출값을 유지했다. 다만 p95가 대조군보다 약 3.0%, provider JPEG가 약 8.4% 증가했고, 추가 사진에서 오인식이 확인되어 운영 기본값으로 채택하지 않는다.

중간 이상 선명화, CLAHE 대비 보정, 저채도, 흑백 처리는 육안상 글자를 보존했지만 이 사진의 CLOVA block 구성이 달라져 결정론적 약 행이 0개가 되었다. 따라서 단순히 더 쨍한 이미지가 OCR 구조화 품질을 높인다고 볼 수 없다.

## 재현 방법

PowerShell에서 버전을 바꾸어 생성 또는 측정한다. 병렬 실행은 생성 전용에만 사용하고 시간 측정과 실제 OCR 평가는 직렬로 실행한다.

```powershell
$env:OCR_V32_REFERENCE_IMAGE = "<test.jpg 절대 경로>"
$env:OCR_V32_ARTIFACT_DIR = "<산출물 폴더>"
$env:OCR_PREPROCESS_VERSION = "v3.2.7"

# 이미지 1회 생성
$env:OCR_V32_GENERATE_ONLY = "1"
uv run python -m scripts.benchmark_ocr_preprocess_v32

# warmup 2회 + 측정 8회
Remove-Item Env:OCR_V32_GENERATE_ONLY
uv run python -m scripts.benchmark_ocr_preprocess_v32
```

서버에서 비교할 때는 `.env`의 `OCR_PREPROCESS_VERSION`만 바꾸고 OCR worker를 다시 시작한다. 현재 운영 기본값은 v3.1.3이며, 이 문서의 v3.2 색상·선명도 실험은 별도 후보로 관리한다.

## 3이미지 LLM 연결 후속 실험

### 설계

2026-09-04에 주요 후보 `v3.2.1`과 `v3.2.7`만 다른 난이도의 3이미지에 각 3회씩 적용했다. 총 18회의 CLOVA OCR 호출은 직렬로 실행했고, 시간대 편향을 줄이기 위해 반복별 후보 순서를 교대했다. OpenAI `gpt-4o-mini`를 temperature 0, strict JSON schema, 비저장 모드로 연결했다.

| 식별자 | 사진 특성 | 정답 범위 |
| --- | --- | --- |
| `real-angle` | 기울어진 고해상도 실사진, 복약안내+영수증 | 조제일·병원명·약 7행의 5개 필드, 37개 |
| `real-folded` | 저해상도, 반사·접힘, 복약안내+영수증 | 육안으로 확정 가능한 약 6행·아목클 함량, 25개 |
| `synthetic-exact` | 조제약 영수증 표준 레이아웃 합성 문서 | 생성 원본과 일치하는 21개 |

`real-folded`의 판독이 불확실한 조제일·병원명·나머지 함량은 점수에서 제외했다. 1회 투약량은 현재 단일 필드 계약에 맞춰 문서에서 확정 가능한 경우 `1정`, `1캡슐`처럼 단위를 합쳐 채점했다.

### 품질 비교

아래 비율은 3회 반복 전체의 정답 필드를 가중 합산한 결과다. 필드 정확도의 분모는 추출된 필드가 아니라 전체 기대 필드로, `정답 필드 / 기대 필드`를 뜻한다. 각 후보의 결과는 모든 반복에서 완전히 동일했다.

| 후보 | 필드 추출률 | 필드 정확도 | 완전 행 비율 | low 평균 | LLM 실제 호출 |
| --- | ---: | ---: | ---: | ---: | ---: |
| v3.2.1 | 92.77% | **90.36%** | 64.71% | 3.67 | 3/9 |
| v3.2.7 | 92.77% | 89.16% | 64.71% | **3.33** | 3/9 |

| 사진 | 후보 | 필드 정확도 | 완전 행 | 약 수 | 주요 차이 |
| --- | --- | ---: | ---: | ---: | --- |
| real-angle | v3.2.1 | 89.19% | 4/7 | 7 | 병원명·함량 3개 미추출 |
| real-angle | v3.2.7 | 89.19% | 4/7 | 7 | 동일, low 4→3 |
| real-folded | v3.2.1 | **96.00%** | 5/6 | 6 | 첫 행 1회 투약량만 미추출 |

### 속도 및 LLM 호출

단위는 ms이고 값은 3회 p50이다. 전체 시간은 preprocess·OCR·candidate·LLM·validate를 합산했다.

| 사진 | 후보 | 전처리 | OCR | candidate | LLM | 전체 | LLM 호출 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| real-angle | v3.2.1 | 1,764 | 2,637 | 173 | 2,294 | 6,934 | 3/3 |
| real-angle | v3.2.7 | 1,794 | 2,640 | 167 | 4,560 | 9,168 | 3/3 |
| real-folded | v3.2.1 | 661 | 1,542 | 66 | 0 | 2,267 | 0/3 |
| real-folded | v3.2.7 | 663 | 1,733 | 64 | 0 | 2,461 | 0/3 |
| synthetic-exact | v3.2.1 | 978 | 2,151 | 98 | 0 | 3,224 | 0/3 |
| synthetic-exact | v3.2.7 | 991 | 2,053 | 101 | 0 | 3,153 | 0/3 |

전처리 자체의 p50 차이는 사진별 +2~30ms로 작았다. 전체 시간 차이는 대부분 외부 OCR·LLM 응답 변동이다. 특히 real-angle의 LLM p50 차이는 두 후보가 같은 모델과 같은 호출 횟수를 사용했으므로 전처리 비용 차이라고 해석하면 안 된다. 3회 표본의 p95는 변동성이 커 참고용이며, 원시 p95·최댓값은 `summary.json`에 보존했다.

LLM은 후보가 충돌한 `real-angle`에서만 각 후보 3회 모두 성공했고, 나머지 12회에서는 ambiguity gate에 따라 정상적으로 생략됐다. LLM은 조제일·함량 후보의 근거 ID만 선택하므로 OCR에 없는 병원명이나 함량을 생성할 수 없다. 이번 6회 OpenAI 호출은 결과 필드 정확도를 늘리지 않았고 real-angle 처리시간만 증가시켰다. 따라서 현재처럼 **충돌 후보가 있을 때만 조건부 호출**하는 구조를 유지한다.
