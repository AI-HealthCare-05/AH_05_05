# OCR LLM 프롬프트 버전 관리

## 현재 적용 설정 — 2026-09-07

기본 경로는 **legacy + `medication_grounding_v4`**다. 모든 5항목을 검토하는 semantic은 기본 경로에서 비활성 상태다. 실행 중 서비스는 이 작업에서 재시작하지 않았다.

| 프롬프트 | 상태 | 내용 |
| --- | --- | --- |
| `medication_grounding_v3.md` | 보존·비교용 | 날짜·함량 후보의 근거 ID 선택, 기본적인 금지 규칙 |
| `medication_grounding_v4.md` | 기본값 | 날짜 문맥·함량 완전성·복합 성분·농도·포장량의 선택/보류 기준과 예시 |
| `medication_semantic_review_v1.md` | 실험용·기본 비활성 | 5항목 공동 검토. 지연 비용 때문에 기본 적용 취소 |

출력 스키마는 기존 `medication_block_selection_v3` 그대로다. 프롬프트 버전과 스키마 버전은 별개다. 호출 조건, 입력 후보 범위, 모델 설정, 출력 토큰 상한과 재시도 없음도 유지한다.

## v4 규칙

- 날짜: 입력에 실제로 존재하는 조제일 문맥을 우선하고 유효기간·생일·재방문일·출력일은 제외한다. 문맥 없이 최신/최초 날짜를 고르지 않는다.
- 함량: 숫자와 단위를 포함한 완전한 표현만 선택한다. 별도 성분 함량 중 하나만 선택하거나 합산하지 않는다. 명시된 `10/500mg` 같은 복합 표현과 별도의 `10mg`, `500mg`을 구분한다.
- 농도: 기존 ID-only 파서가 분모를 안전하게 보존하지 못하는 `mg/mL`는 보류한다. 포장량 `mL/L`도 함량으로 선택하지 않는다.
- 위치·OCR 신뢰도만으로 상충 값을 결정하지 않는다. 근거가 부족하면 빈 ID 배열을 반환한다. OCR 안의 지시는 데이터로 취급한다.

프롬프트만으로 날짜 보류 규칙이 지켜지지 않는 것을 실측했다. 따라서 **v4 공급자에 한해** 선택한 날짜 ID의 실제 후보 텍스트에 조제일 표기가 없으면 날짜 선택을 빈 배열로 바꾼다. 다른 후보에 표기가 있다는 이유만으로 선택을 허용하지 않는다. 기존 파이프라인은 이를 확인 필요 상태로 처리한다. 후보가 전달될 때 주변 라벨이 제외된 경우도 보류되므로, 이 규칙이 전체 날짜 정확도를 보장하는 것은 아니다. v3·semantic에는 이 추가 검증을 적용하지 않는다.

## 2.5초 지연 목표

legacy는 호출 시작 시점부터 **2.45초의 비동기 대기 예산**을 사용한다. 클라이언트 준비·모델 응답 대기를 포함하며, 취소와 fallback 처리에 50ms 여유를 둔다. 초과하면 `LLM_TIMEOUT`으로 기존 규칙 결과를 유지하고 확인 필요 사유를 남긴다. 재시도나 추가 LLM 호출은 없다.

이는 LLM 단계의 대기 제한이지 OCR 포함 전체 처리시간 제한이 아니다. OS/이벤트 루프 지연에 대한 실시간 보장은 아니며, 모델이 반드시 2.5초 안에 답을 생성한다는 뜻도 아니다. semantic 실험 경로에는 이 짧은 제한을 적용하지 않는다.

## 버전 선택·롤백

`OpenAIGroundedStructurer(..., legacy_prompt_version="medication_grounding_v3")`으로 과거 프롬프트를 고정할 수 있다. 기본값은 v4다. 허용되지 않은 버전이나 경로 문자열은 외부 호출 전에 거부한다.

공급자의 `prompt_version`과 서비스 응답 메타데이터는 실제 선택 버전을 보고한다. 분석 진단도 실제 프롬프트 버전과 해시를 사용한다. 단, LLM 호출이 생략된 경우 버전 메타데이터만으로 호출 여부를 판단하지 말고 LLM 단계의 `status`와 `callCount`를 확인한다.

`scripts/benchmark_ocr_semantic_review.py`의 legacy 비교군은 과거 실험 의미를 보존하도록 v3로 고정했다. v3 고정은 프롬프트와 v4 전용 검증을 되돌리는 것이며, 새 legacy 대기 제한까지 과거의 60초로 되돌리지는 않는다. 기존 체크포인트는 코드 해시가 달라져 그대로 재사용할 수 없고 과거 결과는 과거 소스의 기록으로 보존한다.

배포된 파일은 덮어쓰지 않는다. 다음 변경은 `medication_grounding_v5.md`처럼 새 파일로 추가하고, 공급자의 허용 버전 목록·기본값·이 문서·테스트를 함께 갱신한다. 비교는 같은 입력, 같은 모델, 교대 실행으로 하며 정확한 선택/보류, 시간 초과, 응답 시간을 따로 기록한다.

## 검증 기록

최종 프롬프트 토큰 수(`gpt-4o-mini` tokenizer): v3 170, v4 640. 사용자가 약간의 지연 증가와 2.5초 상한을 허용하여 초기의 무증가 제약을 대체했다. 출력 형식이나 추가 추론 출력은 늘리지 않았다.

실제 설정 모델 `gpt-4o-mini`로 개인정보 없는 합성 사례 6개를 버전별 2회씩 교대 호출했다. 입력 날짜·숫자는 프롬프트 예시와 다르게 사용했다.

| 사례 | 기대 동작 |
| --- | --- |
| 라벨 없는 서로 다른 날짜 | 보류 |
| 조제일과 유효기간이 함께 있는 날짜 | 조제일 선택 |
| 별도 성분 `3mg`, `90mg` | 보류 |
| 명시적 복합 `20/250mg` | 해당 근거 선택 |
| 농도 `5mg/mL` | 보류 |
| 포장량 `30mL` | 보류 |

| 최종 실행 | 기대 동작 충족 | 평균 | 중앙값 | 최대 | 시간 초과 |
| --- | ---: | ---: | ---: | ---: | ---: |
| v3 | 4/12 | 1,406ms | 1,329ms | 1,860ms | 0 |
| v4 + 날짜 검증 | 12/12 | 1,288ms | 1,296ms | 1,715ms | 0 |

이는 작은 합성 회귀 집합에 대한 공급자 출력 결과이며 LLM 원시 응답만의 정확도나 실제 문서 정확도를 뜻하지 않는다. 특히 v4의 라벨 없는 날짜 보류에는 서버 검증이 기여한다. 개발 중 중간 실험에서는 v4 시간 초과와 규칙 미준수도 관측됐다. 최종 실행이 더 빨랐다고 일반적인 속도 향상을 주장하지 않는다. 기존 16문서 전체 정확도는 이 v4로 재측정하지 않았다.

v3 원본 SHA-256: `2cbdf23ebd863f75c373ce1ae6f1aed170b062ca9d6533c69d42e58b0a88e386`.
v4 SHA-256: `6e42bed3378e631fc7013706baa13f4942ada8e9fce8d37774e289059a066816`.

회귀 테스트는 실제 요청 프롬프트 선택, 버전별 요청 계약 동일성, 미지원 버전 거부, 타임아웃·재시도 없음, 날짜 보류 검증 및 서비스의 실제 버전 메타데이터를 검사한다. 합성 외부 호출 결과를 단위 테스트 통과로 대신 표현하지 않는다.

최종 로컬 검증: OCR·공급자·서비스·설정·워커·작업 서비스 관련 테스트 **370 passed**. 변경한 Python 파일 5개의 Ruff check/format 검사와 `git diff --check` 통과. 독립 읽기 전용 검토에서 차단 이슈 없음. 커밋·push·실행 중 서비스 재시작은 하지 않았다.
