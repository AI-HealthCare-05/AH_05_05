# 실제 복용 정보 AI 보고서

보고서 요청은 기존 API·인증 경로를 사용한다.

1. 인증 사용자의 현재 복용약·영양제를 조회한다.
2. DB 제품 안내·승인된 규칙과 검색 근거를 수집한다.
3. 제품 라벨과 실제 사용자 성별·연령 기준으로 영양소 합계·비율을 계산한다.
4. 원문 근거와 계산된 값을 AI에 전달해 약 조합, 생활습관, 약별 효능·주의·금기,
   영양제 및 출처를 포함한 보고서를 생성한다.
5. v11 프롬프트로 생성하고 출력 검증을 거쳐 화면에 표시한다. 검증 실패 시
   형식·안전 표현·수치·출처·제품 누락의 오류를 원래 근거와 함께 전달하여
   최대 2회 수정 재생성한다. 매번 같은 검증을 적용한다.
6. 끝까지 실패하면 기본 보고서나 검증 전 원문을 반환하지 않는다.
   API는 `INTAKE_REPORT_GENERATION_FAILED` 오류를 반환하고 기존 화면의
   오류 안내·다시 시도 버튼을 사용한다. 호출 오류와 시간 초과도 오류로 반환한다.

모델 생성/수정 전체 시간 예산은 90초, 근거 수집을 포함한 API 요청 예산은 120초다.
취소되면 남은 재생성을 중단한다. 검증 로그에는 버전·시도 번호·오류 코드만 남기고
환자 정보·약 이름·보고서 원문은 기록하지 않는다. 프롬프트 파일은
`ai_worker/llm/prompts/assets/intake_report_prompt_v11.md`다.

숫자는 Decimal 값과 단위로 비교하여 `210.00 mg`과 `210 mg`을 동일하게 취급한다.
μg/µg/mcg/㎍ 표기는 동일하게 취급하지만 mg↔μg 용량 변환이나 약 이름의 유사도
매칭은 하지 않는다. 확인되지 않은 OCR 이름을 정식 약으로 임의 연결하지 않는다.

특정 제품 ID·약 이름·조합별 보고서 문구를 고정하지 않는다.
이전 임시 생성기와 전환 설정은 제거했으며, 이전 환경변수가 남아 있어도
AI 생성을 우회하지 않는다. 기존 OpenAI·검색·DB 설정을 사용한다.

영양소는 제품 라벨의 하루 안내량 기준이며 실제 복용량이나 식사는 포함하지 않는다.
미확인 함량은 0으로 취급하지 않는다. 권장섭취량(RNI)·충분섭취량(AI) 비율은
부족·과다 판정이나 상한섭취량 비교가 아니다.

정규식·구조 검증은 근거 없는 수치·출처·제품 누락 등을 방어하지만
의학적 의미가 항상 보존된다고 보증하지는 않는다. 실제 모델 출력과 서버 동작은
사용자가 실행하여 확인한다. 이번 변경 작업에서는 서버 재시작·배포·실제 AI 호출을 하지 않는다.
