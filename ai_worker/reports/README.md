# 실제 복용 정보 AI 보고서

보고서 요청은 기존 API·인증 경로를 사용한다.

1. 인증 사용자의 현재 복용약·영양제를 조회한다.
2. DB 제품 안내·승인된 규칙과 검색 근거를 수집한다.
3. 제품 라벨과 실제 사용자 성별·연령 기준으로 영양소 합계·비율을 계산한다.
4. 서버가 근거 카탈로그에서 약 조합, 생활습관, 약별 효능·주의·금기,
   영양제 및 출처의 전체 구성과 원문을 확정한다. AI는 ID·분류·출처·본문을 생성하지 않는다.
5. 처음 생성할 때 교정 가능한 한글 설명 필드를 모두 AI 공백 검토에 포함한다.
   짧은 경고문이나 숫자가 섞인 복용 방법도 긴 한글 연속 구간 유무와 관계없이 검토한다.
   필드별 필수 JSON 속성과 원문 기반 정규식으로 **원문 글자 + 허용된 공백**만 응답할 수 있게 제한한다.
   모델에 숫자 위치를 세게 하지 않는다. 응답의 비공백 문자가 원문과 정확히 일치하는지 다시 검사한 뒤
   공백 위치 정수만 추출한다. 서버는 원문에 허용된 공백만 추가하고 전체 검증을 적용한다.
   모델 문장을 그대로 출력하거나 근접 문자열 정렬로 바뀐 글자를 보정하지 않는다. 실패 시 최대 2회 재요청한다.
   기존의 긴 한글 구간 검사는 결과 검증용으로 유지하며, 교정 대상 선정 기준으로 쓰지 않는다.
6. 끝까지 실패하면 검증되지 않은 원문이나 대체 보고서를 반환하지 않는다.
   API는 `INTAKE_REPORT_GENERATION_FAILED` 오류를 반환하고 기존 화면의
   오류 안내·다시 시도 버튼을 사용한다. 호출 오류와 시간 초과도 오류로 반환한다.

모델 생성/수정 전체 시간 예산은 90초, 근거 수집을 포함한 API 요청 예산은 120초다.
취소되면 남은 재생성을 중단한다. 검증 로그에는 버전·시도 번호·오류 코드만 남기고
환자 정보·약 이름·보고서 원문은 기록하지 않는다. 운영 공백 위치 선택 프롬프트는
`ai_worker/llm/generators/intake_report_cards_generator.py`의 `_spacing_messages`다.
`ai_worker/llm/prompts/assets/intake_report_prompt_v11.md`는 기존 Markdown 생성 경로용이다.

## 근거 우선·일관성 정책

- 제공된 제품 안내·등록 정보·승인된 규칙 및 서버 계산값 밖의 사실을 AI가 보충하지 않는다.
- 정보가 없으면 서버가 제공한 미확인 문구를 유지한다. 미확인을 안전함·효능 없음·금기 없음으로 바꾸지 않는다.
- `temperature=0`과 엄격한 JSON 스키마를 유지한다. 같은 표현을 반복해도 되며 다양성을 위한 재작성은 요구하지 않는다.
- 운영 서비스는 `enable_plain_language=False`를 명시한다. 생성기의 기본값도 `False`이므로
  별도 활성화 없이는 쉬운 말 재작성·AI 의미 검토 단계를 실행하지 않는다. 문장이 원문체로 보일 수 있다.
- AI 응답은 원문 기반 `pattern`으로 제한하며, 서버 내부에서는 검증된 공백 위치 정수 배열만 사용한다.
  기존 공백은 유지하고 한글 음절 사이 또는 한글 뒤 숫자 토큰 직전에만 공백을 추가한다.
  숫자·단위·HTML 엔티티 내부와 `금지`, `금기`, `하지`, `마십시오`, `마세요`, `아니` 내부는 후보에서 제외한다.
  원문 글자·숫자·단위·출처·소유 약·분류·문장 및 상세 항목 순서는 서버가 보존한다.
  중복·범위 밖 위치, 항목 누락, 아직 붙어 있는 긴 한글 문장은 거부한다.
  원문의 18자 이상 한글 연속 구간에서 허용 경계의 85% 이상을 선택한 음절 단위 과잉 공백도 거부한다.
  문장 일부에만 새로 생긴 한 글자 어절 6개 이상의 연속도 거부한다. 원문에 이미 있던 열거는 유지한다.
  이 검사는 조각을 합친 전역 위치 기준으로 수행한다. 모든 문법 오류를 판정하는 검사는 아니다.
  웹 카드와 이메일 Markdown은 같은 검증 완료 결과를 사용한다. 이미 발송된 메일은 바뀌지 않으므로 새 보고서가 필요하다.
  기존 오탈자나 모든 띄어쓰기 오류를 교정하는 기능은 아니며, 끝까지 검증에 실패한 결과는 표시하지 않는다.
- 약은 등록 ID 순, 주의 카드는 서버 중요도 `WARNING → CHECK → INFORMATION` 뒤 카드 ID 순,
  생활 안내는 분류·카드 ID 순, 출처는 ID 순으로 서버가 정렬한다. AI가 같은 중요도의 순서를 바꿔도 표시 기준은 같다.
- 같은 근거에 대한 판단과 구성의 일관성을 목표로 한다. 모델의 띄어쓰기, 원천 데이터·규칙·모델 버전 변경으로
  글자 단위의 완전한 동일성은 보장하지 않는다. 원천 데이터 자체의 오류나 의료적 정확성까지 보증하는 설정은 아니다.

숫자는 Decimal 값과 단위로 비교하여 `210.00 mg`과 `210 mg`을 동일하게 취급한다.
μg/µg/mcg/㎍ 표기는 동일하게 취급하지만 mg↔μg 용량 변환은 하지 않는다.
보고서용 약 이름 보정은 아래의 별도 검증을 통과한 경우에만 제품 안내에 사용한다.

### 보고서 약 이름 추정 연결

- 정확히 일치하는 제품을 우선한다. 오타 후보는 DB 제품 카탈로그에서만 찾으며 특정 약 이름을 고정하지 않는다.
  자동 연결의 순위 계산은 매 조회 시 새 제품 목록을 사용한다. 과거 제안용 인덱스로 새 경쟁 제품을 누락하지 않는다.
- 함량·단위·제형 접미부가 동일하고 숫자가 보존되어야 한다. 함량이나 제형이 빠진 이름은 자동 연결하지 않는다.
  `밀리그램`·`밀리그람`·`mg`처럼 같은 단위의 표기 차이만 정규화하며, 함량 환산은 하지 않는다.
  중첩·연속 성분 괄호를 분리하고, 입력에 괄호 정보가 있으면 후보의 대응 정보도 같아야 한다.
  입력에 없는 성분을 일치 확인했다고 간주하지 않는다. 제품명 뒤 구분 문자가 통째로 붙거나 빠진 경우도 연결하지 않는다.
- 공통 함량·제형 문자열을 제외한 제품명 본체를 한글 자모로 비교한다. 본체 4~64자,
  자모 편집 거리 2 이하, 1위 유사도 0.88 이상, 2위와의 차이 0.12 이상이면 규칙으로 연결한다.
  비교는 상위 후보를 자르기 전에 수행한다. 후보가 하나뿐이어도 절대 유사도 조건은 유지한다.
- 1위 유사도가 0.75 이상 0.88 미만이고 나머지 조건을 충족할 때만 기존 `OPENAI_CHAT_MODEL`에
  보조 판단을 요청한다. DB에서 재확인한 후보 최대 5개의 ID·제품명과 입력 이름만 전달한다.
  모델은 제공된 ID 또는 null만 반환하며, 사전 검증한 1위와 다른 선택은 거부한다.
  환자 프로필·복용 목록·제품의 의료 설명은 이 호출에 보내지 않는다.
- 예외적으로 숫자·단위 직전의 미인식 한글 한 음절이 알려진 한 음절 제형과 자모 편집 거리 1이면,
  본체 유사도 0.88 이상과 나머지 안전 조건을 모두 통과한 후보를 LLM으로 추가 확인한다.
  알려진 제형끼리의 변경은 금지하며, 이 예외는 LLM 확인 없이는 연결하지 않는다.
- LLM 응답은 동적 JSON enum과 원시 정수 타입으로 재검증한다. 오류·판단 불가·시간 초과는
  보고서 전체 실패 대신 미확정 후보로 남긴다. LLM 보조 단계는 대기 포함 5초, 동시 호출 최대 3개,
  재시도 0회이며 외부 취소는 전파한다. 유사도는 정답 확률이나 LLM 자신감이 아니다.
- `is_inferred`를 등록 ID별로 전달하고 약 카드 제목 바로 아래 및 이메일에 원래 이름과 추정 제품을 표시한다.
  저장된 등록명·복용량·승인 규칙 조회 입력은 바꾸지 않는다. 추정 가이드에서 전역 상호작용·운전·음식 카드를
  새로 만들거나, 정식 제품명을 확정된 등록약의 별칭으로 사용하지 않는다. 기존 승인 상호작용 등급은 유지한다.
- 점수 기준은 오타·동점·함량/제형 충돌 회귀 사례를 위한 보수적 구현 기준이다. 운영 카탈로그 전체의
  오연결률이나 실제 LLM 판별 정확도가 검증된 임상 기준은 아니며, 운영 적용 전 별도 평가가 필요하다.

특정 제품 ID·약 이름·조합별 보고서 문구를 고정하지 않는다.
이전 임시 생성기와 전환 설정은 제거했으며, 이전 환경변수가 남아 있어도
AI 생성을 우회하지 않는다. 기존 OpenAI·검색·DB 설정을 사용한다.

영양소는 제품 라벨 함량을 1개당 함량으로 환산한 뒤 등록한 1회 복용량과 하루 복용 시간대 수를 곱해 합산한다.
제품별 안내 횟수로 등록량을 덮어쓰지 않는다. 같은 제품의 별도 등록은 각각 계산하며 라벨 키는 등록 ID를 쓴다.
등록 계획 기준이며 실제 복용 이행이나 식사를 측정한 값은 아니다. 복용량·단위를 환산할 수 없는 제품은 제외한다.
미확인 함량은 0으로 취급하지 않는다. 권장섭취량(RNI)·충분섭취량(AI)과의 비교는
부족 진단이 아니며, 상한섭취량(UL)은 별도 값으로 제공한다.

### 성분 합계와 긴 원문 처리

- 성분 합계와 제품별 성분 표시는 같은 14개 지원 필드 정의를 사용한다. 라벨에서 0보다 큰 함량이
  확인된 성분만 개수 제한 없이 표시하며, 비타민 A는 `vitamin_a_ug_rae`만 합산한다.
  0인 성분과 값이 없는 성분은 항목을 만들지 않는다. 양의 라벨 함량은 있으나 등록 복용량을
  환산하지 못한 성분은 미확인으로 남기며, 다른 제품의 0 함량으로 이를 0mg으로 만들지 않는다.
  레티놀·베타카로틴은 별도 표시하며 비타민 A에 중복 합산하지 않는다.
  나이아신 mg을 근거 없이 mg NE로 환산하지 않는다. 비교 기준이 없어도 확인된 합계는 표시한다.
- 웹 v11 성분 그래프는 영양제 탭과 같은 `NutrientTotals` 컴포넌트를 사용한다.
  성분명·합계·상태 문구·막대·권장/충분 및 상한 눈금·성분 포함 제품 펼치기를 동일하게 표시하고,
  모바일과 PC 모두 1열로 배치한다. 보고서 전용 80% 축과 2열 설정은 사용하지 않는다.
  그래프에는 보고서 생성 시점의 합계·비교 기준을 연결하며 최신 영양제 목록으로 재계산하지 않는다.
  미확인 합계는 0으로 바꾸지 않고 막대를 숨긴다. 상한이 없으면 값을 추정하지 않는다.
  이메일은 본문에 안내만 표시하고, 서버에서 같은 스냅샷을 HTML로 렌더링하여 암호화 첨부한다.
  첨부 그래프는 상한 눈금 88%, 상한 초과 막대 100%, 소수점 최대 2자리와 제품 펼치기를 유지한다.
  약 정보는 효능부터 접힌 상태로 제공한다. 메일용 HTML에는 React 실행 환경이 필요 없다.
- 첨부파일 비밀번호는 발송 요청 시 회원정보의 생년월일 `YYMMDD`이다.
  PBKDF2-SHA256(600,000회)와 파일별 무작위 salt/IV, AES-256-GCM을 사용하며,
  보고서와 생년월일은 기존 암호화 큐 payload 안에서만 전달한다. 보고서 임시 파일은 만들지 않는다.
  생년월일이 없으면 발송 요청을 거절하며, 생년월일 없는 기존 대기 작업도 평문으로 보내지 않는다.
  변경 배포 후 보고서를 새로 생성해 발송한다. 메일 미리보기 대신 파일을 내려받아 브라우저에서 연다.
  생년월일 6자리는 추측 가능한 비밀번호이므로 강한 비밀번호와 같은 보호 수준을 보장하지 않는다.
- `upperLimitValue`/`upperLimitNote`는 같은 사용자 프로필로 선택한 기준에서 제공한다.
  칼슘·철·인·비타민 A·C·D에 기준표의 상한을 연결하며,
  0·비정상 숫자·권장/충분값보다 낮은 상한은 표시하지 않는다. 비타민 A는 영양제 탭과
  동일하게 총 RAE 함량을 기준표 상한과 비교한다. 이는 형태 미확인 총량의 보수적 비교이며,
  preformed vitamin A의 실제 상한 초과를 확정하는 판정은 아니다.
  적용 범위 참고: [NIH ODS FAQ](https://ods.od.nih.gov/HealthInformation/ODS_Frequently_Asked_Questions/),
  [비타민 A 형태별 상한](https://ods.od.nih.gov/factsheets/VitaminA-Consumer/).
  상한 아래라는 사실만으로 식사를 포함한 총 섭취량이 안전하다고 판정하지 않는다.
- 검토된 식품·복용 시점 안내는 `data/v11_lifestyle_guidance.json`에서 관리한다.
  근거가 등록되지 않은 성분의 안내를 임의 생성하지 않는다. 원문 분류의 문구 규칙은
  `data/text_guidance_rules.json`에서 관리하고, 분류되지 않은 주의 원문도 보존한다.
- 음식·술 카드는 음식 표지가 있어도 약물군이나 복용·투여 환자 조건이 섞인 문장은
  보수적으로 제외한다. 약 이름을 열거하거나 문장을 임의로 잘라 재작성하지 않으며,
  제외한 문장은 일반 상호작용 카드에 원문과 기존 등급 그대로 남긴다.
  이는 표현 범위 필터이지 모든 약 이름을 식별하는 분류기는 아니다.
- 띄어쓰기 교정은 전체 필드 4,000자 제한 대신 안전 경계의 최대 100자 조각과
  요청당 원문 최대 800자 묶음을 사용한다. 전체 원문을 다시 합쳐 검증하고 뒷부분을 자르지 않는다.
  보고서 전체 동시 AI 호출은 최대 3개이며, 실패·취소 시 남은 호출도 취소한다.
  기존 90초 시간 예산과 안전하게 분할할 수 없는 원문에 대한 오류 처리는 유지한다.
- 제품별 성분 표시와 상호작용 등급 정책은 유지한다. 실제 서버 적용 및 외부 모델 응답 검증은
  로컬 테스트와 별개이며, 이미 생성·발송된 보고서는 자동 변경되지 않는다.
- 웹·이메일·Markdown에서 등록 복용 정보 줄은 표시하지 않는다. 제품명·성분 요약은 유지하며,
  저장된 복용 정보와 이를 사용한 성분 합산은 변경하지 않는다.

정규식·구조 검증은 근거 없는 수치·출처·제품 누락 등을 방어하지만
의학적 의미가 항상 보존된다고 보증하지는 않는다. 실제 모델 출력과 서버 동작은
단위 테스트뿐 아니라 실제 보고서 생성과 이메일 렌더링으로 확인해야 한다.
