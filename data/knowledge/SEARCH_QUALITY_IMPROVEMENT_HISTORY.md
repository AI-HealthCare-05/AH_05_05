# 약·영양제 검색 품질 개선 이력

## 목적과 품질 우선순위

이 문서는 약·영양제 Chat Core의 검색 품질을 개선한 과정과 근거를 기록합니다.
우선순위는 다음과 같습니다.

1. 질문과 직접 관련된 근거를 찾는다.
2. 다른 약·성분의 근거를 섞지 않는다.
3. 근거가 없을 때 안전하다고 단정하지 않는다.
4. 위 조건을 지키면서 검색 지연을 줄인다.

OpenAI 질문 임베딩과 답변 생성은 외부 API이므로 Qdrant 검색 지연과 별도로
측정합니다. 전역 유사도 기준을 낮춰 속도나 검색 건수만 높이는 방식은 사용하지
않습니다.

## 1. 대표 문서 기준선

초기에는 문서 유형별 대표 8개 문서, 452개 청크로
`medication_knowledge_baseline_v1`을 만들었습니다. 이 단계의 목적은 전체 자료를
포괄하는 것이 아니라 전처리·청킹·검색 계약이 재현되는지 확인하는 것이었습니다.

| 항목 | 결과 |
|---|---:|
| 평가 질문 | 10건 |
| Hit@5 | 100% |
| MRR | 1.000 |
| 출처 정확도 | 100% |
| 약·성분 혼합 | 0건 |
| 중복 검색률 | 0% |
| Qdrant 검색 P95 | 43.755ms |

이 수치는 대표 8문서 안에서 만든 정답 세트의 결과이며 전체 약·영양제 질문의
성능을 의미하지 않습니다. 평가 범위를 명시하지 않으면 100%라는 숫자가 실제
서비스 품질로 오해될 수 있으므로 기준선과 전체 릴리스를 분리해 기록했습니다.

## 2. 전처리와 청킹 품질 보완

검색 모델을 바꾸기 전에 검색 입력 자체의 오류를 줄였습니다.

- PDF 다운로드 감사 문자열, 반복 푸터·배너와 참고문헌 뒤쪽을 제거했습니다.
- 건강기능식품공전은 원료, 기능성, 일일섭취량, 주의사항을 분리하고 제조기준,
  규격, 시험법은 검색 청크에서 제외했습니다.
- `SUPPLEMENT_CODE`의 번호 참조는 대상 절이 결정론적으로 확인될 때만 실제
  문구로 복원했습니다. 추측 복원은 자동 품질 검사에서 차단했습니다.
- 최대 토큰 분할 뒤 생긴 짧은 꼬리 문장은 최대 토큰을 넘지 않는 경우 앞 의미
  청크로 다시 결합했습니다.
- 동일 입력을 두 번 전처리해 JSONL SHA-256이 같은지 검사하고, 자동 `PASS`와
  수동 원문 대조를 모두 통과한 출처만 전체 처리 대상으로 올렸습니다.

이 단계의 핵심은 벡터 검색이 깨진 문장이나 서로 섞인 의미 단위를 정확히 찾는
상황을 방지하는 것입니다. 세부 규칙은 `CHUNKING_STRATEGY.md`와
`SUPPLEMENT_CODE_PREPROCESSING_RESULTS.md`에 기록되어 있습니다.

## 3. 전체 자료 불변 릴리스

대표 문서만 있던 기준선에서는 실제 자료에 문서가 있어도 검색할 수 없었습니다.
승인된 776개 문서를 전처리해 9,826개 청크를
`medication_knowledge_full_v1`에 적재했습니다.

| 구분 | 청크 수 |
|---|---:|
| PUBLIC | 559 |
| DEMO_RESTRICTED | 9,267 |
| 합계 | 9,826 |

기존 컬렉션을 삭제하거나 덮어쓰지 않고 dataset version과 collection을 함께
고정했습니다. 새 릴리스가 실패해도 이전 컬렉션으로 되돌릴 수 있고, 어떤 데이터와
임베딩으로 답했는지 추적할 수 있습니다.

## 4. 질문 확장과 점수 보정

전체 자료를 넣은 직후에는 전역 유사도 0.65를 원점수에 먼저 적용해 정확한 청크도
제거됐습니다. 예를 들어 `마그네슘의 효능`과 정확히 일치하는 기능성 청크의
원점수는 0.5947이었습니다.

다음 순서로 검색을 변경했습니다.

1. 질문에서 성분·약명 후보와 기능, 섭취량, 주의, 상호작용 의도를 추출합니다.
2. 최종 5건을 바로 요청하지 않고 최소 20건의 후보를 검색합니다.
3. 내용 해시가 같은 청크를 제거합니다.
4. 정확한 성분·약명 메타데이터 일치에 0.12, 포함 일치에 0.08, 의도 섹션
   일치에 0.05를 더해 재정렬합니다.
5. 전역 0.65는 유지합니다. 원점수 0.55 미만은 보정하지 않고, 0.55 이상도
   대상명 일치가 없으면 통과시키지 않습니다.

| 질문 | 개선 후 결과 | 최상위 원점수 | 근거 |
|---|---:|---:|---|
| 마그네슘의 효능 | 1건 | 0.5947 | 마그네슘 `FUNCTION` |
| 마그네슘은 왜 먹어? | 4건 | 0.6376 | 마그네슘 `FUNCTION` |
| 임산부는 무슨 약을 조심해야 해? | 3건 | 0.5740 | 임부 대상 `CAUTION` |

이 방식은 정확한 메타데이터가 있는 결과만 제한적으로 살리므로 0.65를 전역적으로
낮추는 것보다 무관한 청크 유입 위험이 작습니다.

## 5. Chat 라우팅과 제품명 검색 보완

벡터 검색 결과가 있어도 RDBMS 제품명 부분 일치가 먼저 실행되면 `마그네슘`을
의약품 제품군으로 오해해 제품 목록을 반환했습니다. 이를 다음과 같이 보완했습니다.

- 영양제 기능 근거가 있으면 의약품 부분 제품명 모호성보다 먼저 사용합니다.
- 정확한 제품명·함량이 있는 의약품 질문만 제품별 용법과 주의사항으로
  연결합니다.
- `타이레놀`처럼 통칭만 입력하면 같은 성분군의 대표 효능은 안내하되, 제품마다
  달라질 수 있는 복용량은 추측하지 않고 정확한 제품명을 요청합니다.
- 제품 질문 답변은 효능, 사용법, 핵심 주의사항을 우선하고 빈 항목과 질문하지
  않은 부가정보는 생략합니다.

이 변경으로 Qdrant에 적절한 영양제 근거가 있는데도 e약은요 의약품 목록으로
빠지는 경로를 막았습니다.

## 6. 영양제 상호작용 검색 보완

### 발견한 문제

상호작용 연구 PDF 제목과 본문은 영어인데 사용자 질문은 한국어였습니다. 또한
기존 `RESEARCH_ARTICLE` 청크의 `ingredient_names`와
`interaction_pair_keys`가 비어 있었습니다. 그 결과 한국어 임베딩 검색 점수가
0.65보다 낮았고, 검색 실패 뒤 `칼슘`, `철분`, `아연`을 의약품 제품명으로 조회해
관련 없는 제품 목록을 보여줬습니다.

| 질문 유형 | 개선 전 원점수 상위 | 최종 근거 |
|---|---:|---:|
| 칼슘·철분 동시 섭취 | 0.5280 | 0건 |
| 칼슘제·철분제 복용 간격 | 0.4975 | 0건 |
| 칼슘 영향의 지속성 | 0.4728 | 0건 |
| 철분 부족 상태의 아연 섭취 | 0.4486 | 0건 |

### 적용한 방법

1. 현재 보유 연구문서로 검증 가능한 조합과 한글·영문 동의어를
   `SupplementInteractionPair` Registry에 등록했습니다.
2. 한국어 확장 검색어와 영문 학술 검색어를 한 문장으로 섞지 않고 각각 별도로
   임베딩·검색합니다. 혼합 문장은 실험에서 목표 논문 점수가 0.5527에 그쳤지만,
   영문 `calcium iron absorption interaction`은 0.6979였습니다.
3. 두 검색은 `asyncio.gather`로 병렬 실행하고 결과를 합친 뒤 중복 제거와
   재정렬을 수행합니다.
4. 질문의 두 성분이 제목, 본문 또는 메타데이터에 모두 존재하는 청크만 상호작용
   근거로 허용합니다. 따라서 일반 아연 기능 청크 하나만으로 아연–철분 상호작용을
   설명할 수 없습니다.
5. 한 문서가 최종 결과를 독점하지 않도록 문서당 최대 2청크만 선택합니다.
6. 알려진 영양제 조합 질문은 의약품 제품명 Repository를 호출하지 않고
   `INTERACTION` 경로로 보냅니다.
7. Qdrant 근거가 있으면 “조합을 찾지 못했다”는 문장을 함께 출력하지 않습니다.
8. LLM은 두 질문 성분을 모두 다루는 초안 근거만 설명하고, 연구에 없는 복용
   간격·용량·안전 결론을 생성하지 않도록 제한했습니다. 동물·세포 연구는 사람에게
   확인된 결론으로 바꾸지 않습니다.

현재 Registry는 의료 결론을 하드코딩하지 않습니다. 코퍼스에 실제로 존재하는
조합의 검색 어휘와 안정적인 `pair_key`만 관리하며, 최종 설명 내용은 검색된 원문
근거에서 가져옵니다.

### 실검색 결과

2026-08-26에 OpenAI `text-embedding-3-small`과 현재
`medication_knowledge_full_v1`을 사용해 다시 측정했습니다.

| 질문 | 개선 후 건수 | 최상위 점수 | 검색 문서 |
|---|---:|---:|---|
| 칼슘과 철분을 같이 먹으면 철분 흡수가 떨어지나요? | 3 | 0.6979 | Calcium and Iron Absorption |
| 칼슘이 철분 흡수에 미치는 영향은 일시적인가요? | 3 | 0.6979 | Calcium and Iron Absorption |
| 철분이 부족한 사람이 아연 영양제를 먹어도 되나요? | 2 | 0.7330 | Supplemental Zinc Lowers Measures of Iron Status |
| 아연을 복용하면 철분 수치가 낮아질 수 있나요? | 2 | 0.7330 | Supplemental Zinc Lowers Measures of Iron Status |

칼슘–철분 결과에는 한 논문의 상위 2청크뿐 아니라 별도 체계적 문헌고찰·메타분석
문서도 0.6614로 포함됐습니다. 아연–철분은 현재 보유 코퍼스에 해당 조합 연구가
한 문서뿐이므로 그 문서의 상위 2청크만 반환합니다.

## 7. 다음 전처리 릴리스의 메타데이터

현재 `full_v1`은 재임베딩하지 않고 이중 검색과 본문 쌍 검증으로 즉시
보완했습니다. 다음 불변 릴리스부터 연구문서 제목에서 검증된 조합을 찾으면 다음
메타데이터가 자동으로 기록됩니다.

- `ingredient_names`: 예) `칼슘`, `철분`
- `interaction_type`: `SUPPLEMENT_SUPPLEMENT`
- `interaction_pair_keys`: 입력 순서와 무관한 SHA-256 조합 키

메타데이터가 포함된 새 컬렉션에서는 정확한 조합 필터와 점수 보정을 먼저 적용할 수
있습니다. 기존 `full_v1`을 제자리 수정하지 않고 새 dataset version과 collection을
만들어 전후 평가 후 전환해야 합니다.

## 8. 평가 지표 해석

- **Hit@5**: 정답으로 지정한 문서 또는 청크가 상위 5건 안에 한 건 이상 있는
  질문의 비율입니다.
- **MRR**: 첫 정답 순위의 역수 평균입니다. 정답이 항상 1위면 1.0입니다.
- **출처 정확도**: 검색 결과의 source·document 식별자가 기대 출처와 일치하는
  비율입니다.
- **약·성분 혼합**: 질문하지 않은 약이나 성분의 청크가 결과에 섞인 건수입니다.
- **중복 검색률**: 같은 내용 해시가 최종 결과에 반복되는 비율입니다.
- **P95**: 측정값의 95%가 이 시간 이하라는 뜻입니다. Qdrant P95와 OpenAI
  임베딩·LLM을 포함한 Chat API P95는 별도로 측정합니다.

## 9. 남은 고도화와 검증

1. 전체 릴리스 전용 상호작용 평가 질문과 정답 document ID를 확정해 Hit@5,
   MRR, 출처 정확도를 다시 측정합니다.
2. 상호작용 메타데이터가 포함된 새 불변 컬렉션을 만들고 `full_v1`과 A/B
   비교합니다.
3. Dense 검색 기준선을 유지한 채 BM25 계열 sparse 검색과 reranker를 각각
   추가해 정확도 개선이 측정될 때만 채택합니다.
4. 연구 설계별 근거 수준과 사람·동물·세포 연구 구분을 구조화해 답변 표현을 더
   엄격하게 제한합니다.
5. 검색 성공뿐 아니라 최종 한국어 답변의 근거 충실도, 금지 결론 발생률과 전체
   Chat API P50/P95를 반복 측정합니다.

검색 결과가 없다는 것은 안전하다는 뜻이 아닙니다. 검색 결과가 있더라도 챗봇은
복용 시작·중단·용량·간격을 스스로 결정하지 않으며, 보유 근거의 범위와 한계를
명시해야 합니다.
