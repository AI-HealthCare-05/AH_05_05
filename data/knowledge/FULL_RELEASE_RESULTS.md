# Medication Knowledge 전체 release 결과

## 릴리스

- 실행일: 2026-08-26
- dataset version: `knowledge-full-v1`
- Qdrant collection: `medication_knowledge_full_v1`
- embedding: `text-embedding-3-small`, 1536차원, Cosine
- 상태: `green`
- 전처리 승인 문서: 776개
- 적재 청크: 9,826개
  - `PUBLIC`: 559개
  - `DEMO_RESTRICTED`: 9,267개
- Qdrant `points_count`: 9,826
- Qdrant `indexed_vectors_count`: 9,826

`DEMO_RESTRICTED` 자료는 내부 부트캠프 데모에서만 사용하며 원문·추출문·Qdrant
볼륨은 Git에 포함하지 않는다. 외부 공개 시에는 해당 자료를 제외한 별도 dataset과
불변 collection을 생성한다.

## 기존 문제

기존 `medication_knowledge_baseline_v1`은 문서 유형별 대표 8개 문서와 452개
청크만 포함했다. 따라서 마그네슘 등 전체 자료에 존재하는 질문도 검색 근거가 없거나,
부분 일치한 의약품 제품명이 RDBMS에서 먼저 발견되어 질문이 모호하다는 응답이
나올 수 있었다.

전체 자료를 넣은 직후에도 0.65 원점수 기준을 먼저 적용하여 정확한 성분·섹션
청크가 제거되는 문제가 있었다. 예를 들어 `마그네슘의 효능`의 정확한 기능성 청크
원점수는 0.5947이었다.

## 개선

1. 승인된 Qdrant 출처와 텍스트 추출 가능 PDF 전체를 전처리하고 문서별 자동
   `PASS` 결과만 release에 포함했다.
2. 질문에서 성분·약명 후보와 기능·섭취량·주의·상호작용 의도를 추출해 검색 표현을
   확장했다.
3. 20건 이상의 후보를 조회하고 내용 해시 중복을 제거했다.
4. 정확한 성분·약명 일치에는 0.12, 메타데이터 이름에 질문 대상이 포함되면 0.08,
   의도 섹션 일치에는 0.05를 보정해 재정렬한다.
5. 전역 0.65 기준은 유지한다. 원점수 0.55 미만은 보정하지 않으며, 0.55 이상이라도
   성분·대상명 일치가 없으면 기준 미달 결과를 통과시키지 않는다.
6. 영양제 근거가 검색되면 RDBMS의 부분 제품명 일치만으로 먼저 모호성 응답을
   반환하지 않는다.

## 대표 실검색 검증

| 질문 | 결과 | 최상위 원점수 | 최상위 근거 |
|---|---:|---:|---|
| 마그네슘의 효능 | 1건 | 0.5947 | 마그네슘 `FUNCTION` |
| 마그네슘은 왜 먹어? | 4건 | 0.6376 | 마그네슘 `FUNCTION` |

마그네슘 기능 청크에는 `에너지 이용에 필요`, `신경과 근육 기능 유지에 필요`가
포함되어 있고, 일일섭취량 청크에는 `94.5 ~ 250 mg`이 별도 근거로 보존된다.
임부 관련 결과는 특정 질환·제품 문서의 일반 주의 근거이므로 모든 약을 포괄하는
목록으로 단정하지 않고, 구체적인 제품명·성분명을 다시 확인하도록 답변해야 한다.

## 남은 평가

- 기존 10개 기준 질문은 대표 8문서 기준선용이므로 전체 release 전용 평가 세트와
  정답 문서 ID를 별도로 확정해야 한다.
- 전체 Chat API의 OpenAI 임베딩·답변 생성 시간을 포함한 P50/P95를 측정해야 한다.
- RDBMS의 임부·노인·연령·용량·투여기간 DUR 구조화 자료 연결은 별도 단계다.

## 병합 전 전체 컬렉션 재검증

2026-08-26에 기존 10개 기준 질문의 dataset version만 `knowledge-full-v1`로
변경해 전체 컬렉션을 재검증했다. 이 평가는 생산용 점수 보정·재정렬 Retriever가
아닌 원본 Qdrant 검색 기준선이다.

| 지표 | 결과 | 기준 | 판정 |
|---|---:|---:|---|
| Hit@5 | 1.0000 | 1.0000 이상 | 통과 |
| MRR | 0.8333 | 참고 지표 | 기준선 기록 |
| 출처 정확도 | 0.6829 | 1.0000 이상 | 실패 |
| 중복 검색률 | 0.0976 | 참고 지표 | 개선 필요 |
| 잘못된 대상 혼입 | 0건 | 0건 이하 | 통과 |
| Qdrant 검색 P95 | 152.452ms | 300ms 이하 | 통과 |

검색 속도와 Hit@5는 통과했지만 종합 평가는 실패했다. 기존 정답 세트가 대표
8문서의 document ID만 정답으로 인정하기 때문에, 전체 릴리스에서 추가된 같은
주제·동일 내용 문서를 오답 또는 중복으로 집계했다. 따라서 수치를 임의로 통과
처리하지 않고 실패 결과를 보존한다. 다음 단계에서는 전체 776문서를 대상으로
동등 정답 문서 ID와 content hash 중복 정책을 검수한 전용 평가 세트를 만든 뒤,
생산용 Retriever의 질문 확장·중복 제거·재정렬까지 포함해 다시 평가한다.

같은 날 실제 MySQL 저장 트랜잭션을 사용하는 `POST /api/v1/chat`을 30회
호출하고 외부 OpenAI Core만 즉시 반환 구현으로 대체해 서버·RDBMS 구간을
측정했다. P50은 5.201ms, P95는 6.972ms로 CRUD 3초 기준을 통과했다. 이 값에는
OpenAI 질문 임베딩과 답변 생성 시간이 포함되지 않으므로 전체 사용자 체감
응답시간과는 별도로 관리한다.

## 병합 전 성능·안전성 보완

- 불변 Qdrant 컬렉션의 존재 여부·벡터 차원·거리 방식 검증은 프로세스에서
  최초 성공 시 한 번만 수행하고 이후 검색에서 재사용한다. 검색 쿼리마다 발생하던
  `collection_exists`와 `get_collection` 관리 RPC를 제거했다.
- 최대 2,000자 질문에서 토큰마다 의약품 제품 DB를 조회하지 않도록 제품명 후보를
  최대 12개로 제한했다.
- 약명·영양제 성분명·상호작용 조합 필터를 모두 만족해야 했던 AND 조건을
  하나 이상 일치하면 되는 OR 조건으로 변경해 관련 근거가 누락되지 않게 했다.
- LLM이 결정론적 초안에 없던 용량 또는 근거 없는 안전 단정을 추가하면 생성문을
  폐기하고 근거 기반 초안으로 되돌리며 `UNSUPPORTED_GENERATED_CLAIM`을 기록한다.
- 정지·탈퇴·승인 대기 계정의 기존 토큰 사용을 차단하고, 실패 요청의 동일
  `requestId` 재처리 및 일반 예외 시 실패 상태 저장을 회귀 테스트로 고정했다.
