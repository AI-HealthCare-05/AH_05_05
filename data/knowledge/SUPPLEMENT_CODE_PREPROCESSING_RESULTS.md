# 건강기능식품공전 전처리 보완 결과

## 작업 원칙

- 수동 검수 상태를 결과에 맞추어 임의로 `APPROVED`로 바꾸지 않습니다.
- 먼저 전용 계층 파서와 자동 품질 검사를 보완하고 같은 대표 문서를 다시 전처리합니다.
- 자동 검사와 원본 대조 수동 검수는 별도 게이트로 유지합니다.
- 챗봇은 한국어로 설명하지만, 전처리 단계에서는 LLM으로 원문을 요약하거나 의학적 의미를 새로 만들지 않습니다. 검색된 한국어 근거를 답변 생성 단계에서 자연스럽게 표현합니다.

## 보완 전 문제

기존 공통 제목 기반 분할은 자동 품질 상태가 `PASS`였지만 건강기능식품공전의 번호 계층과 PDF 추출 오류를 충분히 검사하지 못했습니다.

| 문제 | 실제 영향 | 보완 필요 이유 |
|---|---|---|
| `제조기준1)`, `원료(1)`, `제품의 요건3)`처럼 번호와 제목이 붙어서 추출됨 | 부모·자식 필드 경계가 사라지거나 `OTHER` 청크가 생성됨 | 성분 기능, 섭취량, 주의사항이 서로 섞이면 잘못된 답변 근거가 됨 |
| 비타민 A 원문의 `μg RAE`가 추출문에서 `g RAE`와 뒤쪽 `μ`로 분리됨 | 자동 검사가 잘못된 단위를 통과시킴 | `μg`와 `g`는 크기가 크게 달라 섭취량 안내에 사용할 수 없음 |
| 주의사항 뒤의 `시험법`이 같은 청크에 남을 수 있음 | 사용자 질문과 관계없는 시험 절차가 검색됨 | 검색 순위와 답변 집중도를 떨어뜨림 |
| `(가)의 경우`, `1). (1). (가) 및 (나)의 경우`가 참조 문구로만 남음 | 검색 청크만으로 실제 대상 원료·조건을 이해할 수 없음 | LLM이 번호 체계를 추측하게 하면 환각과 연결 오류 위험이 커짐 |
| 자동 검사가 토큰 크기와 의미 섹션 비율 위주였음 | 위 오류가 있어도 `PASS` 가능 | 의료·복약 관련 근거는 구조와 단위 자체를 차단 기준으로 검사해야 함 |
| 파서가 추가한 `성분`, `분류` 문장의 길이를 원문 위치처럼 다시 계산함 | 1페이지 필드가 2페이지까지 걸친 출처로 기록될 수 있음 | 사용자가 확인하는 출처 페이지와 실제 원문 위치가 달라질 수 있음 |
| `이미(1) : ・ 이취`, `비타민 표시량의 (2) A : 80 ~ 150%`처럼 번호와 필드 값의 순서가 뒤섞임 | 규격 항목의 번호·이름·값 연결이 어색해짐 | 번호, 고정 필드명, 현재 성분이 모두 확인되는 경우에만 결정론적으로 복원해야 함 |
| 빈 괄호, 뒤집힌 영문 괄호, 쉼표 앞 공백과 줄바꿈이 남음 | 검색어가 분리되고 사람이 읽기 어려움 | 의미를 새로 만들지 않는 안전한 문자 수준 정규화가 필요함 |
| 필수 절 누락과 `비타민 를 ... A` 같은 깨진 문장이 자동 `PASS` 가능 | 불완전한 문서가 전체 처리와 Qdrant 적재 후보가 됨 | 복원할 수 없는 의미 손상은 사람이 보기 전에 자동 차단해야 함 |
| 원료 절의 이름 항목 뒤에 제조 설명·일반 식품원료 문장·깨진 참고문이 함께 남음 | 원료명 검색 결과에 사용자 안내에 불필요한 제조 문장이 섞이고 문서 전체가 오탐 차단됨 | 검색 원료는 한글명과 영문명이 함께 확인되는 항목으로 범위를 좁혀야 함 |

## 적용한 보완

1. `SUPPLEMENT_CODE` 전용 계층 파서를 공통 분할보다 먼저 실행합니다.
2. 성분 1개를 문서 문맥으로 고정하고 모든 검색 청크에 `성분`과 `분류`를 기록합니다.
3. `(1) 원료`, `기능성 내용`, `일일섭취량`, `섭취 시 주의사항`을 독립 검색 청크로 만듭니다. 원료는 `(가) 한글명 (English Name)` 형식으로 이름 쌍이 확인되는 항목만 남기고, 설명문·일반 식품원료 문장·제조기준 `(2)·(3)`과 `규격`은 원본 추출문과 파서 구조에는 보존하지만 Qdrant 후보에서는 제외합니다.
4. `시험법`은 사용자 안내 검색 대상에서 제외합니다.
5. 전체 번호 경로를 가진 참조는 원료·기능성 항목에서 실제 문장을 찾아 `참조 내용`으로 붙입니다. 참조를 찾지 못하면 자동 차단합니다.
6. 같은 추출문 안에서 이동한 `μ`가 확인되는 알려진 패턴만 `μg RAE`로 복원합니다. 근거 없이 단위를 추정하지 않으며 의심 단위는 자동 차단합니다.
7. 다음 자동 품질 사유를 추가했습니다.
   - `MISSING_SUPPLEMENT_CONTEXT`
   - `SUSPICIOUS_SUPPLEMENT_UNIT`
   - `UNRESOLVED_HIERARCHY_REFERENCE`
   - `SUPPLEMENT_SECTION_CONTAMINATION`
8. 일반 문장 안의 `규격` 같은 단어는 필드 경계로 오인하지 않도록 줄 시작 제목만 혼입 검사에 사용합니다.
9. 전용 파서가 원문에서 계산한 필드 페이지 범위를 유지하고, 합성된 검색 문맥의 길이로 페이지를 다시 계산하지 않습니다. 다중 페이지 회귀 테스트로 이 동작을 고정했습니다.
10. `규격`의 `(1) 성상`, `(2) 성분 표시량`, `(3) 대장균군`을 번호와 고정 필드명으로 재조립합니다. 표시량은 원문에서 찾은 백분율 범위만 사용하고 현재 문서의 성분명을 붙입니다.
11. 빈 괄호, 뒤집힌 영문 괄호, 중점 주변 공백, 쉼표 앞 공백처럼 의미를 바꾸지 않는 추출 흔적만 정규화합니다.
12. `원료`, `기능성 내용`, `일일섭취량` 중 하나라도 빠지면 `MISSING_REQUIRED_SUPPLEMENT_SECTION`으로 차단합니다. 규격은 검색 대상이 아니며, 주의사항은 원문에 없는 성분도 있어 필수 절로 강제하지 않습니다.
13. 남은 빈 괄호·뒤집힌 괄호·비정상 구두점과 성분 기호 위치가 깨진 알려진 패턴은 `MALFORMED_SUPPLEMENT_TEXT`로 차단합니다. 이 경우 LLM이나 추측으로 복원하지 않습니다.
14. 건강기능식품공전 표본은 기본 길이 표본 외에도 존재하는 각 절의 첫 청크를 모두 포함하여, 필수 절별 원문 대조가 가능하도록 했습니다.
15. 원본과 직접 대조한 `비타민 를 ... 제조( ) A ･ 가공한 것` 패턴은 현재 문서 성분이 `비타민 A`이고 이동한 기호가 `A`일 때만 `비타민 A를 ... 제조·가공한 것`으로 복원합니다.
16. 한글 목록 기호는 `가나다라마바사아자차카타파하`만 허용합니다. 기존 `[가-하]` 범위가 일반 음절 `의`까지 목록 기호로 오인하던 문제를 제거했습니다.
17. 반복된 성분 기호(`A A`), 조사가 빠진 성분명(`비타민 와`), 단어에 붙은 성분 기호(`다만A`)는 남은 텍스트 손상으로 자동 차단합니다.
18. 원료 절에서 목록 기호·한글명·괄호 속 영문명이 모두 확인되는 항목만 결정론적으로 추출합니다. 영문명이 없는 일반 원료 문장과 연결 참고문은 Qdrant 후보에서 제외합니다.
19. 제외된 설명문과 제조기준의 손상은 검색 품질을 차단하지 않습니다. 다만 기능성·일일섭취량·주의사항처럼 실제 검색 청크에 남는 깨진 문장은 `MALFORMED_SUPPLEMENT_TEXT`로 계속 차단합니다.

## 대표 문서 재처리 결과

재처리 dataset version은 `knowledge-pilot-v1`입니다.

| 대표 문서 | 보완 전 | 보완 후 | 자동 상태 | 수동 상태 |
|---|---:|---:|---|---|
| 비타민 A 건강기능식품공전 | 5 청크 | 3 청크 (`원료`, `기능성`, `일일섭취량`) | `PASS` | `PENDING` |
| 비타민 B6 원료별 성분 자료 | 4 청크 | 4 청크 (`원료`, `기능성`, `일일섭취량`, `주의사항`) | `PASS` | `PENDING` |

확인된 개선 결과:

- 비타민 A 일일섭취량이 `210 ~ 1,000 μg RAE (699.93 ~ 3,333 IU)`로 복원됐습니다.
- 비타민 B6 일일섭취량 `0.45 ~ 67 mg`이 독립 청크로 유지됐습니다.
- 비타민 B6 주의사항에 시험법 문장이 섞이지 않았습니다.
- 비타민 A 원료는 `(가) 레티닐 팔미트산염 (Retinyl Palmitate)`, `(나) 레티닐 아세트산염 (Retinyl Acetate)`만 남았습니다.
- 비타민 B6 원료는 `(가) 피리독신염산염 (Pyridoxine Hydrochloride)`만 남았고, 주의사항의 `섭취를 중단` 표기가 복원됐습니다.
- 규격이 `(1) 성상`, `(2) 현재 성분의 표시량`, `(3) 대장균군`으로 재구성됐습니다.
- 모든 공전 검색 청크에 성분명과 계층 분류가 포함됐습니다.
- 비타민 A의 `원료`, `규격`, `기능성 내용`, `일일섭취량` 출처 범위가 실제 원문 위치인 1페이지로 기록됐습니다.
- `식품원료를 사용하여 비타민 A를 보충할 수 있도록 제조·가공한 것` 같은 일반 원료 문장은 원본 추출문에는 보존하고 검색 청크에서는 제외했습니다.
- `의 형태로 사용`이 `(의) 형태로 사용`으로 잘못 변환되던 목록 기호 범위 오류를 수정했습니다.
- 비타민 A 원료 절의 제조기준 `(2)·(3)`에 있던 `A A`, `비타민 와`, `다만A`는 검색 범위에서 제외됐습니다.
- `(...Vitamin A) A 의 형태`처럼 이름 항목이 아닌 깨진 참고문은 검색 청크에서 제외되어 원료명 검색을 오염시키지 않습니다.
- 비타민 A와 비타민 B6 모두 자동 `PASS`이며 두 문서의 수동 상태는 `PENDING`으로 유지했습니다.
- 전체 파일럿 처리 결과는 8개 문서·477개 청크입니다. 수동 승인된 출처가 없어 `ready_for_bulk_source_ids`는 비어 있습니다.

## 남은 검수와 확대 조건

자동 `PASS` 이후에도 다음은 사람이 원본과 대조해야 합니다.

- 원본의 읽기 순서와 추출 순서가 같은지
- 성분명·함량·단위가 원문과 같은지
- 필드 경계와 페이지 범위가 맞는지
- PDF 추출로 조사·괄호·영문명이 어색해졌지만 의미가 달라지지 않았는지
- 참조 해소 결과가 실제 번호 경로와 같은지

비타민 A의 제외 대상 제조기준은 다음 세 추출문을 원본과 대조해 제외 경계가 맞는지 확인했습니다.

- `비타민 원료와 베타카로틴 원료를 (2) A A`
- `최소함량기준은 비타민 와 베타. A`
- `비타민 전환계수는 을 적용함 다만A 1/2`

비타민 A의 다음 참고문은 원본 추출문에 보존하지만 이름 쌍이 아니므로 검색 청크에서는 제외합니다.

- `유성비타민 지방산 에스테르(Dry Formed Vitamin A) A 의 형태로 사용(Vitamin A in Oil)`

대표 문서를 수동 검수해 승인하기 전에는 같은 유형의 전체 PDF 처리나 Qdrant release 전환을 진행하지 않습니다.

## 식품안전나라 기능성원료 심사보고서 복원 정책

### 문제와 범위

식품안전나라의 기능성원료 심사보고서는 건강기능식품공전과 달리 `원료 또는 원재료`,
`기능성 내용`, `일일 섭취량`, `섭취 시 주의사항`이 한 페이지의 인라인 텍스트로 이어져
추출됩니다. 공전용 번호 계층 파서로 처리하면 심사자 정보·규격·안전성 평가·연구 결과가
사용자 안내 청크에 섞이거나, 필요한 네 항목을 찾지 못해 `AUTOMATIC_QUALITY_BLOCKED`가
발생할 수 있습니다.

이 형식에는 심사보고서 전용 분기를 적용합니다. 대상은
`food_safety_korea_supplement_ingredients` 출처 중 실제로 네 필드를 가진 문서이며,
다른 형식의 성분 자료를 같은 규칙으로 강제로 통과시키지 않습니다.

### 추출·청킹 규칙

1. `원료 또는 원재료 → 기능성 내용 → 일일 섭취량 → 섭취 시 주의사항` 순서의 첫
   필드 집합만 탐지합니다.
2. `지표성분`, `규격`, 안전성·기능성 평가, 심사 결과, 독성 시험, 연구 결과,
   참고문헌, 시험법과 `심사자 정보 사항` 이후는 소비자 안내 근거에서 제외합니다.
3. 한 필드는 하나의 독립 섹션으로 만들고, 그 섹션이 최대 토큰을 넘을 때만 기존
   재귀 분할 규칙을 적용합니다. 따라서 일반적인 심사보고서는 네 개의 섹션 청크가
   생성되지만, 긴 필드는 안전하게 둘 이상의 청크가 될 수 있습니다.
4. `E(u(commia → Eucommia`처럼 괄호가 영문 속에 끼어든, 원문 대조가 가능한
   문자 수준 손상과 식물 부위 표기 앞 공백만 복원합니다. 성분명·함량·의학적 의미를
