# 약·영양제 지식 문서 청킹 전략

## 1. 목표

이 파이프라인의 목표는 PDF를 일정한 글자 수로 자르는 것이 아니라, 질문과 직접 관련된 약·성분·상호작용 근거가 하나의 검색 결과 안에서 식별되도록 만드는 것입니다. 검색된 청크는 답변 생성 근거와 출처 표시에도 사용하므로 다음 조건을 동시에 만족해야 합니다.

- 제목, 약명, 성분명, 상호작용 대상이 설명과 분리되지 않는다.
- 서로 다른 약, 성분, 사례를 한 청크에 섞지 않는다.
- 인용할 원문과 검색용 보강 문장을 구분한다.
- 같은 입력은 항상 같은 청크 ID와 경계를 만든다.
- OCR 품질이 낮거나 출처 사용이 보류된 문서는 인덱싱하지 않는다.

여기서 말하는 “의미 단위 분리”는 LLM이 문맥을 보고 임의로 경계를 고르는 방식이 아닙니다. 문서 유형별로 확인한 제목·필드 패턴을 규칙으로 탐지해 먼저 섹션을 나누고, 한 섹션이 허용 크기를 넘을 때만 토큰 수를 계산하는 재귀 분할기를 적용하는 결정론적 방식입니다.

## 2. 전체 처리 순서

1. `pilot_manifest.json`에서 `TEXT_EXTRACTABLE`이고 `index_eligible=true`인 대표 PDF만 선택합니다.
2. `pypdf`로 페이지별 텍스트를 추출하고 페이지 번호를 유지합니다. 기본은 원래 읽기 순서를 유지하는 `plain` 모드이고, 실제 파일럿에서 NUL 문자 때문에 문장 공백이 사라진 팜리뷰만 `layout` 모드를 사용합니다.
3. Unicode NFKC 정규화, 제어문자 제거, 공백 정리, 반복 머리말·꼬리말과 독립 페이지 번호 제거를 수행합니다.
4. 아래 문서 유형별 제목 사전으로 섹션 시작점을 탐지합니다. 제목이 본문과 붙어서 추출된 경우도 탐지합니다.
5. 섹션 경계를 넘지 않은 상태에서, 허용 최대 토큰을 넘는 섹션만 `문단 → 줄 → 문장 → 구 → 공백 → 문자` 순서로 재귀 분할합니다.
6. 서술형 문서는 앞뒤 맥락을 잇기 위해 토큰 overlap을 사용하고, 사례·성분 규격·상호작용 쌍처럼 독립적인 단위에는 overlap을 쓰지 않습니다.
7. `content`에는 출처로 제시할 정규화 원문을 두고, `embedding_text`에는 문서 제목·약/성분·섹션명을 접두어로 붙입니다. LLM이 만든 요약은 임베딩 본문에 넣지 않습니다.
8. 재귀 분할된 하위 청크의 원문 시작·끝 문자 위치를 페이지별 문자 범위표에 대입해 실제 `page_start`, `page_end`를 계산합니다. 문서 ID, 섹션, 실제 페이지 범위, 내용 해시로 결정론적 `chunk_id`를 생성하고 JSONL로 저장합니다.
9. 청크 품질과 검색 평가를 통과한 release만 Qdrant의 새 컬렉션에 적재합니다.

## 3. 공통 전처리 규칙

### 3.1 제거하는 항목

- 여러 페이지에서 반복되는 짧은 머리말·꼬리말
- `1/3`, `- 7 -`처럼 한 줄 전체가 페이지 번호인 문자열
- NUL, 제어문자, 연속된 탭·공백
- 연구 문서의 `References`, `Bibliography` 이후 본문

### 3.2 제거하지 않는 항목

- 약명, 성분명, 함량, 단위
- 위험도나 근거 강도를 나타내는 표현
- 표에서 추출된 행과 열의 텍스트
- 페이지 번호 메타데이터
- 원문의 불확실성 표현(예: “가능성이 있다”, “보고된 바 있다”)

제거 규칙을 제한하는 이유는 문장을 매끄럽게 만드는 것보다 원문 근거를 보존하는 것이 더 중요하기 때문입니다. 줄바꿈이나 조사까지 LLM으로 교정하면 출처 문장의 의미가 달라질 수 있어 사용하지 않습니다.

## 4. 문서 유형별 경계와 크기

| 문서 유형 | 먼저 나누는 실제 경계 | 목표 / 최대 토큰 | overlap | 선택 이유 |
|---|---|---:|---:|---|
| 약물백과 | `개요`, `요약`, `약리작용`, `효능·효과`, `용법·용량`, `부작용`, `주의사항`, `상호작용` | 250~450 / 600 | 40~60 | 약의 효능과 위험 설명이 섞이지 않게 하고, 긴 서술의 문맥만 연결합니다. |
| 부작용 사례 | 문서 1개를 사례 1개로 고정하고 `환자 정보`, `이상사례`, `복용 의약품 정보`, `상세 사항`, `평가 의견`으로 분리 | 300~500 / 700 | 0 | 다른 환자 사례가 섞이는 것을 막고, 중복 검색 결과를 만들지 않습니다. |
| 팜리뷰 | 제목, `개요`, `키워드`, 번호가 붙은 장 제목, 문단, `결론`; 참고문헌 제외 | 400~600 / 750 | 80 | 긴 설명의 앞뒤 논리를 유지하되 치료·주의·상호작용을 한 덩어리로 만들지 않습니다. |
| 건강기능식품 공전·성분 | 성분 1개를 문서 단위로 고정하고 `원료`, `규격`, `기능성 내용`, `일일섭취량`, `섭취 시 주의사항`, `시험법` | 200~400 / 500 | 0 | 성분별 법정 기준 필드는 독립 사실이므로 겹치면 같은 사실이 여러 번 검색됩니다. |
| 약-음식 상호작용 안내 | 질환/약효군 제목을 먼저 나누고, 본문의 약 또는 성분과 음식 조합을 가능한 한 한 단위로 유지 | 150~300 / 450 | 0 | 상호작용의 두 대상을 함께 보존해야 잘못된 조합으로 답하지 않습니다. |
| 건강기능식품 기능 정보집 | 기능성 범주, 기능성 원료, 기능·주의·특수대상 제목 | 250~450 / 600 | 40 | 같은 기능 범주 설명은 이어지지만 다른 원료나 특수대상 주의는 분리해야 합니다. |
| 상호작용 모노그래프 | 원료 번호 또는 원료명, 상호작용 상대별 항목 | 150~300 / 450 | 0 | 원료 A의 상호작용을 원료 B의 설명과 혼합하지 않습니다. 출처 미확인 자료는 전처리 검토만 하고 인덱싱하지 않습니다. |
| 연구 논문 | `Abstract`, `Introduction`, `Methods`, `Results`, `Discussion`, `Conclusion`, `Limitations`; 참고문헌 제외 | 400~700 / 800 | 100 | 연구 결과와 기전, 한계를 구분하면서 긴 논증의 문맥을 유지합니다. |

토큰 수는 OpenAI 임베딩과 호환되는 `cl100k_base` tokenizer로 계산합니다. 한국어는 한 글자와 한 토큰이 일치하지 않으므로 기존의 `len(text)` 기반 1000자 제한을 그대로 사용하지 않습니다.

## 5. 제목 탐지 방식

제목 탐지는 문서 유형마다 별도 별칭 목록을 사용합니다. 예를 들어 건강기능식품 공전은 `기능성 내용`, `일일섭취량`, `섭취 시 주의사항`을, 연구 논문은 영어 대소문자를 무시하고 `Abstract`, `Methods`, `Results`, `Discussion`, `Conclusion`을 탐지합니다.

- 제목은 줄 시작뿐 아니라 PDF 추출 과정에서 앞 문장 또는 뒤 본문과 붙은 경우도 찾습니다.
- 더 긴 제목을 먼저 비교해 `섭취 시 주의사항`이 `주의사항`으로 잘못 잘리지 않게 합니다.
- 제목 문자열 앞은 문서 시작·줄바꿈·문장 종결 기호 중 하나이고, 뒤는 공백·콜론·구분 기호 중 하나인 경우만 경계 후보로 인정합니다. 따라서 문장 중간의 `Results`, `상호작용` 같은 단어는 제목으로 자르지 않습니다.
- 동일 제목이 120자 안에서 다시 추출되면 PDF 추출 중복으로 보고 하나만 남깁니다. 120자보다 멀리 떨어진 동일 제목은 여러 성분·사례의 반복 필드일 수 있으므로 독립 경계로 유지합니다.
- `제조기준`, `제품의 요건`처럼 하위 필드를 묶는 부모 제목은 독립 청크로 만들지 않고 이어지는 `원료`, `규격`, `기능성 내용`에 문맥으로 포함합니다.
- `상호작용`, `치료`처럼 본문에 자주 등장하는 일반 단어는 약-음식 안내서와 팜리뷰의 단독 제목 규칙으로 사용하지 않습니다. 해당 문서에서는 더 구체적인 제목이나 최대 토큰 재귀 분할을 사용합니다.
- 제목을 찾지 못한 문서는 `OTHER` 섹션으로 유지한 뒤 최대 토큰 기준만 적용하고, 품질 보고서에서 검토 대상으로 표시합니다.

## 6. 청크 데이터 계약

각 청크는 다음 정보를 가집니다.

- `chunk_id`: 문서 ID, 섹션 유형, 페이지 범위, 청크 순서, 내용 해시로 만든 SHA-256 기반 ID
- `content`: 답변 근거와 인용에 사용하는 정규화 원문
- `embedding_text`: `[문서]`, `[약/성분]`, `[섹션]` 접두어와 `content`를 결합한 검색용 텍스트
- `token_count`: `content`의 실제 토큰 수
- `source_id`, `access_scope`, `document_type`, `document_id`, `dataset_version`
- `page_start`, `page_end`, `chunk_index`, `section_type`, `section_title`, `content_hash`
- `entity_type`, `drug_names`, `ingredient_names`, `interaction_type`, `special_populations`
- `index_eligible`: 출처와 처리 품질을 확인해 Qdrant 적재 가능한지 여부

`content`와 `embedding_text`를 분리하는 이유는 검색률을 높이기 위한 접두어를 사용자에게 원문 인용처럼 보여주지 않기 위해서입니다.

매번 실행할 때 현재 파일럿 매니페스트에 없는 이전 JSONL과 이번 실행에서 건너뛸 문서의 JSONL을 먼저 제거합니다. 같은 `source_id` 또는 `document_id`가 중복되면 처리 순서에 따라 산출물이 덮이는 것을 막기 위해 매니페스트 검증 단계에서 실패시킵니다. 식별자는 영문·숫자로 시작하고 영문·숫자·밑줄·하이픈만 허용해 산출물 경로로 해석되지 않게 합니다.

## 7. OCR 및 출처 보류 처리

- `OCR_REQUIRED` 문서는 일반 PDF 파이프라인에서 제외합니다.
- OCR 후에는 최소 글자 수, 제어/대체문자 비율, 비정상적으로 긴 무공백 문자열을 검사합니다.
- 품질 검사 결과가 `PASS`가 아니면 자동 인덱싱하지 않고 검토 목록에 남깁니다.
- `QDRANT_DISABLED_UNTIL_VERIFIED` 또는 `index_eligible=false` 자료는 텍스트 추출 실험은 할 수 있지만 release 및 Qdrant 적재 대상에서는 제외합니다.

## 8. 비교 실험과 합격 기준

동일한 파일럿 질문 세트로 다음 세 방식을 비교합니다.

- A: 기존 방식 — 1000자, 200자 overlap
- B: 섹션 경계 우선 + 유형별 토큰 크기
- C: B + 약/성분/섹션 접두어 + 구조화 메타데이터 필터(채택 후보)

기록할 지표:

- Hit@5: 최소 80%, 목표 90% 이상
- MRR: 정답 근거가 상위 순위에 나타나는 정도
- 출처 정확도: 목표 90% 이상
- 경계 보존율: 정답에 필요한 제목과 설명이 같은 청크에 남은 비율
- 약·성분 혼합 오류: 목표 0건
- 중복 검색 결과 비율
- 동일 질문 반복 검색의 순위 일관성
- Qdrant 검색 P95: 목표 300ms 이내

한 번의 예시 검색 점수만 보고 전역 similarity threshold를 낮추지 않습니다. 특정 문서가 검색되지 않으면 먼저 섹션 경계, 제목/성분 접두어, 메타데이터, 평가 질문을 확인하고, 파일럿 지표가 개선될 때만 정책 또는 release 버전을 변경합니다.

## 9. 현재 파일럿 범위

- `TEXT_EXTRACTABLE`이며 출처 사용이 허용된 대표 PDF만 자동 전처리합니다.
- OCR 대표 문서는 OCR 품질 검증이 추가될 때까지 제외합니다.
- 출처 확인이 필요한 상호작용 모노그래프는 `index_eligible=false`로 유지합니다.
- 파일럿이 합격한 문서 유형만 같은 정책으로 나머지 원본에 확대 적용합니다.

기존 `public_guidelines_small_v1` 컬렉션은 새 데이터 release의 검색 검증이 끝난 뒤 제거합니다. 원본 볼륨이나 Qdrant 컨테이너를 먼저 삭제하지 않습니다.
