# #563 공통 달력 및 24시간 입력 구현 계획

승인 근거: 사용자는 달력 내부 오늘 버튼, OCR·복약 메모 등 모든 날짜 선택 화면 적용, 오전/오후 없는 24시간 입력을 승인했다. 버튼 그림자는 #562로 분리한다.

목표: 기본 OS 날짜 피커 대신 기존 달력 모양을 재사용한 공통 달력, 오늘 바로 선택, 연/월 이동, 범위 제한, 날짜시간의 24시간 편집 및 취소 보존.

## 범위와 소유

- `shared/ui/Calendar.tsx`: 재사용 날짜 그리드. 날짜 값 YYYY-MM-DD, 선택 범위 min/max. 오늘은 브라우저 로컬 날짜(기존 native local 입력과 동일). 연/월과 날짜 키보드 탐색. 선택은 draft에 반영.
- `shared/ui/DateInput.tsx`: 공통 Input의 date/datetime-local 분기. 기존 API(onChange event/value/ref/required/min/max/disabled) 유지. 텍스트 표시/직접 입력과 달력 버튼, 팝업의 날짜 draft와 시/분 24시간 선택. 적용만 onChange, 취소는 저장 안 함.
- `shared/ui/Input.tsx`: 공통 기본 입력 렌더와 날짜 분기를 나누되 다른 입력은 변경하지 않음. 날짜 컨트롤은 16px 유지.
- `MedicationPeriodCalendar.tsx`: 기존 기간 필터는 공통 Calendar 어댑터로 재사용, 기존 선택 즉시 적용/닫기 유지.
- OCR·복용 일정의 native showPicker 호출 제거. 팝업은 필드 클릭/달력 버튼으로 공통 동작.
- 표시만 보고하는 챌린지 실천 캘린더는 날짜 입력이 아니므로 교체하지 않음. 생년월일의 기존 min/max/나이 validation 유지(나이 정책 변경 없음).

## 검증 순서

1. 신규 E2E: OCR 달력 내부 오늘 → 적용 시 값 변경; 취소 시 원래 값 유지. 구현 전 오늘 버튼 부재 실패 확인.
2. 메모 datetime-local: 기존 18:37 유지하며 오늘로 변경, 00·23시 및 00·59분 24시간 선택. ISO 저장값 확인.
3. 내 정보 생년월일: 기존 max 이후 날짜 선택 불가, 연/월 이동 가능.
4. 진료 일정 중첩 팝업: 날짜 선택 → 원래 sheet에 복귀, 병원명 입력/저장 가능.
5. 기간 필터: min/max에 따라 오늘 활성/비활성, 범위 밖 날짜 적용 불가.
6. 375/393/430px Chromium·WebKit, 기존 OCR·복용 일정·메모·생년월일 입력 회귀, tsc.
7. 실제 날짜 팝업/24시간 선택 및 #562 버튼 전후 스크린샷 별도 제공. 실기기 네이티브 OS 동작 확인과 로컬 WebKit 확인 구분.

제약: 새 패키지 없음. 운영 API/DB 변경 없음. #555/#556 브랜치와 독립. 사용자가 보기 쉬운 기본 checkout으로 유지하며 PR/배포는 요청 전 실행하지 않음.
