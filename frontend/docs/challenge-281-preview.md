## 확인할 흐름

1. 둘러보기 → 공식 상세 → 참여하기 → 개인 수행 기간 확인.
2. 마이 카드에서 직접 했어요 → 진행 수치 갱신 → 같은 날 중복 인증 불가.
3. 복약·영양제 카드에는 기록 버튼 없이 자동 연동 안내만 표시.
4. 맞춤 챌린지 → 대상 여러 개 선택 → 선택한 대상 요약 확인.
5. 나만의 챌린지 → 매일/주 몇 회 전환 → 날짜·기간 입력 → 생성.
6. 기록 돌아보기 → 항목 열기 → 해당 기간 목업 확인 → 돌아오면 확인 표시.
7. 기록 없음/오류는 정상 열람 완료로 처리하지 않음.
8. 내 배지 → 전체 목록 → 획득/미획득 상세.
9. 홈 챌린지 요약에는 직접 인증 버튼 없음; 더보기로 마이 이동.

## 처방별 챌린지·배지 정책 검토 (최신)

- `/dev/challenges` 하단 **홈** → `/dev/home-challenges`: 2026-09-13 저녁으로 고정한 검토 전용 홈입니다. 일반 `/challenges`의 홈 이동 및 실제 홈의 API·저장 동작은 변경하지 않았습니다.
- 기존 홈 복약 UI를 재사용합니다. 감기약과 9월 7일 처방이 보이며, 행을 선택한 다음 `먹었어요`로 해당 처방만 기록합니다. 선택하지 않고 누르면 두 처방을 함께 기록합니다.
- 기본 챌린지 대상은 감기약만입니다. 6/9회(67%) → 감기약 저녁 기록 → 7/9회(78%). 참여하지 않은 다른 처방 기록은 이 진행률이나 배지 획득을 바꾸지 않습니다.
- `복약 챌린지 참여 처방 확인`에서 **9월 7일 처방**을 추가하고 참여합니다. 마이에 처방별 카드 2개가 나타나며 합산 진행률은 없습니다. 감기약은 6/9회(67%), 9월 7일 처방은 13/14회(93%)입니다.
- 홈에서 9월 7일 처방 행만 선택해 `먹었어요`를 누르면 해당 챌린지만 14/14회(100%)로 달성합니다. 감기약은 그대로 67%입니다. 홈에서 달성한 처방 상세 → `복약 루틴 배지 자세히 보기`로 이동합니다.
- 동일한 복약 배지를 묶어 **2회 획득**으로 표시합니다. 기존 8월 31일 처방 획득 1회 + 이번 처방 획득 1회이며, 상세 획득 이력에서 각각의 참여 상세로 이동합니다. 같은 참여를 다시 열거나 다시 참여해도 획득 이력은 중복되지 않습니다.
- 마이는 진행 중인 처방을 각각 표시하고, 달성한 처방은 지난 기록에 보관합니다. 홈 요약에는 현재 목업의 두 처방에 대한 진행/달성 수를 표시하고, 마이에는 과거를 포함한 전체 복약 챌린지 수를 표시합니다.
- 이미 참여한 처방은 선택 화면에서 체크된 비활성 상태로 유지합니다. 새 처방 추가가 기존 참여나 획득 이력을 지우지 않습니다. 여러 처방을 선택하면 각각의 참여가 만들어지며, 마이 목록으로 이동합니다.
- 같은 처방의 같은 날짜·시간대는 약이 여러 개여도 1회입니다. 반복 저장은 중복 집계하지 않습니다. **아직 챌린지를 달성하지 않은 처방**은 완료 행 선택 후 `복약 기록 되돌리기`로 취소할 수 있습니다.
- 상세는 해당 처방의 기간·시간대·진행률·달성 결과만 보여줍니다. 신규 처방은 자동 참여시키지 않습니다. 복약에는 하루 한 번 인증으로 오해할 수 있는 일별 인증표나 별도 `했어요`를 표시하지 않습니다.
- 지난 기록은 처음에는 접히고, 펼치기/접기 가능합니다. 화면 재진입 시 다시 접힙니다.
- 복약과 챌린지 연동은 이 검토용 홈의 메모리 상태에만 적용됩니다. 실제 복약/영양제 API 연동은 없으며, 영양제 탭은 표시용입니다. 새로고침하면 모두 초기화됩니다.

### 미확정 정책과 목업 경계

- 중간 참여 시 이전 기록 인정 범위, 처방 변경·중단 시 목표 조정, 달성 후 기록 취소·배지 회수는 아직 협의 대상입니다.
- 목업에서는 기존 예시 기록을 포함해 개별 달성 화면을 확인합니다. 새 참여의 날짜는 예시 처방 기간이며 실제 참여일 계산 정책을 확정한 것이 아닙니다.
- 달성 후 취소는 검토 전용 홈에서 안내 메시지를 표시하고 수행하지 않습니다. 이는 실제 복약 기록 취소를 금지하는 제품 정책이 아닙니다. 일반 홈/실제 복약 저장 동작은 바꾸지 않았습니다.
- 프론트 목업 `ChallengeParticipation.episodeId`가 개별 처방을 식별합니다. `ChallengeBadge.awards`는 `participationId`, `episodeId`, `title`, `earnedAt`을 가진 획득 이력 배열입니다. 서버 API나 DB 계약을 구현한 것이 아닙니다.
- 공식 챌린지와 영양제 챌린지는 기존 동작을 유지합니다. 복약의 에피소드별 정책을 영양제에 임의 적용하지 않았습니다.
